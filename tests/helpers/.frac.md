## 1. 本目录是什么

测试共享设施，不含任何 `*.test.ts`：临时 git 仓库 fixture、假 plugin、两个后端（`SimpleGit` / `IsomorphicGit`）的 manager 构造器，以及测试后的清理机制。被 `tests/gitManager/` 全部文件、`tests/ui/diff/` 以及 `tests/automaticsManager.test.ts`（只用 `createFakePlugin`）使用。
依赖关系：`gitRepo` 与 `createFakePlugin` 是底层；`simpleGit`、`isomorphicGit` 各自构造一个后端；`gitManagerHarness` 把两个后端包装成同一接口，供契约测试 `describe.each`。`obsidian` 模块本身由 vitest 别名指向 `tests/stubs/obsidian.ts`，不在本目录。

## 2. 直属文件

- `cleanup.ts`：`withCleanup(resource)` 把带 `cleanup()` 的对象压入模块级栈并原样返回；文件在 import 时注册 vitest 的 `afterEach`，按后进先出调用 `cleanup()`。因此只要 import 了它，同一测试文件里所有 `withCleanup` 的资源都会在每个用例后回收。
- `createFakePlugin.ts`：`createFakePlugin()` 返回强转成 `FakePlugin` 的最小对象，只有 `app.workspace.trigger`、`settings: {}`、`localStorage: {}`、`state`（`offlineMode: false`、`mergeInProgress: false`、`operation: GitOperation.idle`）、`setPluginState`、`log`、`displayError`（均为 `vi.fn()`）。
- `gitRepo.ts`：`TestRepo` 类型与 fixture 工厂，以及 `createTempDirectory(prefix)` / `cleanupTempDirectory(dir)`。
  - `createRepoWithOrigin()`：`dir/remote.git`（bare）+ `dir/worktree`（`repoPath`），分支 `main`、远端 `origin`，身份 `Test User <test@example.com>`，`core.quotepath=off`，初始提交 `note.md` = `"base\n"` 并 `push -u`。
  - `createEmptyRepo()`：只有 `worktree`，无提交无远端。`createRepoWithMergeConflict()`：在上面基础上让 `note.md` 在 `main`（`ours\n`）与 `other`（`other\n`）间冲突，返回合并中途的仓库；若没有冲突会清理并抛错。
  - `TestRepo` 方法：`raw / head / headMessage / statusPorcelain / cachedDiffNames / unpushedCount(tracking = "origin/main") / mergeCommitCount(range) / show(ref) / write / remove / writeAndCommit / appendAndCommit / cleanup`；`git` 字段是 simple-git 客户端。
- `simpleGit.ts`：`createSimpleGitTestContext({ fixture?, plugin?, configurePlugin?, gitClient?, getVaultOptions? })` 返回 `{ manager, repo, plugin, cleanup }`；`GitFixture` 类型 = `() => Promise<TestRepo>`。默认会执行真实的 `manager.setGitInstance()`；传 `gitClient` 则直接设置 `manager.git` 与 `absoluteRepoPath` 而跳过它。构造出的 `plugin.app.vault` 只有 `configDir: ".obsidian"` 与 `adapter.getBasePath() / exists()`。`cleanup()` = `manager.unload()` + `repo.cleanup()`；构造失败时先清理仓库再抛错。
- `isomorphicGit.ts`：`createIsomorphicGitManager(repoPath, { vaultPath?, basePath? })` 返回 `{ manager, plugin, setPluginState, updateCachedStatus }`（后两者是 `vi.fn()`）。`plugin.app.vault` 是 `createNodeVault(root)` 生成的基于 `fs/promises` 的 Node 版 vault：adapter 实现 `exists / read / readBinary / write / writeBinary / stat / list / mkdir / rmdir / remove`，vault 路径先去掉前导 `/` 再拼到 root；`getAbstractFileByPath` / `getFolderByPath` 恒返回 `null`。不返回 `cleanup`，调用方需自己处理仓库回收。
- `gitManagerHarness.ts`：`gitManagerBackends`（名称 `simple-git` 与 `isomorphic-git`）和 `GitManagerTestHarness = { manager: GitManager, repo, plugin, cleanup }`；`create(fixture?)` 默认用 `createRepoWithOrigin`。IsomorphicGit 的 `cleanup()` = `manager.unload()` + `repo.cleanup()`。

## 4. 本层约束 / 约定 / 禁忌

- `FakePlugin.settings` 是空对象而不是 `DEFAULT_SETTINGS`：任何设置在用例里默认都是 `undefined`（假值）。两个 manager 构造器只预置 `basePath`、`gitDir: ""`（IsomorphicGit 另有 `mergeStrategy: "none"`、`listChangedFilesInMessageBody: false`），所以用例要自己写 `syncMethod`、`limitToVault`、`autoCommitGlobMode`、`manualCommitUsesAutoCommitGlobs` 等。新增设置项时不会有 helper 帮你给默认值。
- `FakePlugin` 没有 `updateCachedStatus`（SimpleGit 上下文）、`isAllInitialized`、`tools`、`displayMessage`、`statusBar` 等成员；源码路径用到时由用例自行补，见 `tests/gitManager/.frac.md`。
- `TestRepo` 的输出都经过 `trim()`：`show("HEAD:x")` 没有结尾换行，`statusPorcelain()` 会丢掉第一条记录的前导空格（`" M a"` 变成 `"M a"`）。断言文本时按这个规则写期望值。
- harness 让 vault 根 = `repo.dir`、仓库在子目录 `worktree`，所以 `basePath` 是 `"worktree"`，`status` 里的 `vaultPath` 总是 `worktree/<path>`；直接用 `createIsomorphicGitManager(repo.repoPath)` 或 `createSimpleGitTestContext()` 时 vault 根就是仓库根、`basePath` 为 `""`。
- SimpleGit 上下文默认注入 `getEnvVars → ["SSH_ASKPASS=obsidian-git-test-askpass"]`，目的是让 `setGitInstance()` 不去启动长期运行的 askpass 服务；要测真实的 askpass 安装流程必须用 `configurePlugin` 覆盖（`getEnvVars = () => []`）。
- IsomorphicGit 的 Node vault 是手写的：源码一旦调用 adapter / vault 的新方法，需要先在 `createNodeVault` 里补实现，否则运行时才会报 `undefined is not a function`。`readBinary` 常被用例 `vi.spyOn` 来统计读盘次数。
- 所有 fixture 都在系统临时目录下创建，`cleanup()` 删除整个 `dir`；自己新增 fixture 必须返回 `TestRepo` 并保证 `cleanup()` 能删到 `dir`，调用方再用 `withCleanup(...)` 登记。

## 5. 什么时候需要下钻

- 写 manager 层的新用例：先看本文件选对入口（契约测试用 `gitManagerBackends`，单后端用 `createSimpleGitTestContext` / `createIsomorphicGitManager`），再看 `tests/gitManager/.frac.md` 的现有覆盖。
- 需要新的仓库状态（多分支、子模块、冲突变体）：在 `gitRepo.ts` 增加返回 `TestRepo` 的 fixture，而不是在用例里重复手写 git 命令。
- 源码访问到 Obsidian API 但 helper 里没有：查 `tests/stubs/.frac.md`（`obsidian` 别名模块）。
