# .frac.md — tests/helpers

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

测试共享设施，不含 `*.test.ts`：临时 git 仓库 fixture、假 plugin、两个后端的 manager 构造器、清理机制。使用方是 `tests/gitManager/`（`networkPolicy.test.ts` 除外）、`tests/ui/diff/`，以及只用 `createFakePlugin` 的 `tests/automaticsManager.test.ts`。

## 2. 直属文件

- `cleanup.ts`：`withCleanup(resource)` 登记带 `cleanup()` 的对象并原样返回；import 时注册 `afterEach`，在每个用例后按后进先出回收登记过的资源。
- `createFakePlugin.ts`：强转成 `FakePlugin` 的最小对象：`app.workspace.trigger`、`vi.fn()` 的 `setPluginState` / `log` / `displayError`，加空的 `settings` / `localStorage`。`manifest` 的 `git-maintained` id 与 `dir` 是维护版加的，`SimpleGit` 靠它找插件目录。
- `gitRepo.ts`：`TestRepo` 类型、fixture 工厂与临时目录函数，是其余 helper 的底层。
  - fixture：`createRepoWithOrigin()`（bare 远端加 `worktree`，分支 `main`、远端 `origin`、已 push 的初始提交）、`createEmptyRepo()`（无提交无远端）、`createRepoWithMergeConflict()`（`note.md` 在 `main` 与 `other` 间冲突，返回合并中途的仓库）。
  - `TestRepo` 带 git 辅助（`raw`、`head`、`statusPorcelain`、`show` 等）与文件辅助（`write`、`writeAndCommit` 等）。
- `simpleGit.ts`：`createSimpleGitTestContext(options)` 返回 `{ manager, repo, plugin, cleanup }`。默认执行真实的 `manager.setGitInstance()`，传 `gitClient` 则跳过它。
- `isomorphicGit.ts`：`createIsomorphicGitManager(repoPath, options)` 返回 `{ manager, plugin, setPluginState, updateCachedStatus }`，`plugin.app.vault` 是手写的 `fs/promises` 版 Node vault（`createNodeVault`）。不返回 `cleanup`，仓库回收由调用方登记。
- `gitManagerHarness.ts`：把两个后端包成同一接口：`gitManagerBackends` 与 `GitManagerTestHarness`；`create(fixture?)` 默认用 `createRepoWithOrigin`。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- `FakePlugin.settings` 是空对象而不是 `DEFAULT_SETTINGS`：没设的设置项在用例里都是 `undefined`。构造器只预置 `basePath`、`gitDir`（`IsomorphicGit` 另有 `mergeStrategy`），其余由用例自己写。
- `FakePlugin` 缺 `updateCachedStatus`（SimpleGit 上下文）、`isAllInitialized`、`tools`、`displayMessage`、`syncSupervisor` 等成员，源码用到时由用例补（见 `tests/gitManager/.frac.md`）。
- `TestRepo` 的输出都经 `trim()`：`show("HEAD:x")` 没有结尾换行，`statusPorcelain()` 丢掉第一条记录的前导空格。
- harness 的 vault 根是 `repo.dir`、仓库在子目录 `worktree`，所以 `basePath` 是 `"worktree"`、`status` 的 `vaultPath` 带该前缀；直接用另两个构造器时 vault 根就是仓库根。
- SimpleGit 上下文默认让 `getEnvVars` 返回 `SSH_ASKPASS=...`，避免 `setGitInstance()` 启动 askpass 监听；测真实 askpass 安装要用 `configurePlugin` 覆盖成返回空数组。
- Node vault 是手写的：源码用到 adapter / vault 的新方法（如救援文件夹用的 `createFolder`），要先在 `createNodeVault` 补实现，否则运行时才报 `undefined is not a function`。
- 新增 fixture 返回 `TestRepo`（建在系统临时目录，`cleanup()` 删整个 `dir`），调用方用 `withCleanup(...)` 登记。

## 5. 什么时候需要下钻

- 写 manager 层新用例：先选对入口（契约测试 `gitManagerBackends`，单后端 `createSimpleGitTestContext` / `createIsomorphicGitManager`），再看 `tests/gitManager/.frac.md`。
- 需要新的仓库状态（多分支、冲突变体）：在 `gitRepo.ts` 加返回 `TestRepo` 的 fixture，不在用例里手写 git 命令。
- 源码用到 Obsidian API 而这里没有：查 `tests/stubs/.frac.md`。
