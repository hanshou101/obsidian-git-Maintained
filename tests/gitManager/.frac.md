# .frac.md — tests/gitManager

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

`src/gitManager/`、`GitActions` 与 askpass 凭据桥的集成测试，位于 `tests/` 之下。用例大多跑在真实临时 git 仓库上、不 mock git：桌面后端 `SimpleGit`、移动后端 `IsomorphicGit`、两者共用的 `GitManager` 契约，以及维护版新增的拉取修复与手机同步。

## 2. 直属文件

**两个后端的行为**
- `gitManager.test.ts`：后端无关的契约测试，`describe.each(gitManagerBackends)` 让每个用例对两个后端各跑一遍（harness 在 `helpers/gitManagerHarness`）。覆盖 status / stage / commit（含 amend）、glob 选择、detached HEAD、合并冲突流、`GitActions` 的 `commit` / `commitAndSync`。
  - 维护版新增 `manualCommitUsesAutoCommitGlobs` 的用例（手动提交跟随自动提交的 glob）。
- `simpleGit.test.ts`：只测 `SimpleGit`：`limitToVault` 的 vault 范围（vault 在仓库子目录里）、commit、pull / push、branchInfo、fetch / checkout、进度事件映射、`squashAllUnpushedCommits`、`show`。
- `isomorphicGit.test.ts`：只测 `IsomorphicGit`：pull 的 merge 状态（快进撞上本地编辑、未跟踪文件不被覆盖）、冲突、push 结果、`status()`。远端用 `update-ref` 加 `reset --hard` 模拟，`manager.fetch` 被 mock，spy 挂在 `isomorphic-git` 的默认导出对象上，源码改变引用方式要同步查。

**维护版新增**
- `isomorphicGitPushAfterMerge.test.ts`：守护 `patches/` 下的 isomorphic-git pnpm 补丁（merge 后 push 不重发整段历史）：把请求交给真实 `git http-backend` 并数上传的对象；`index.cjs` 与 `index.js` 两个构建都跑。
- `pullRecovery.test.ts`：`IsomorphicGit` 拉取被打断后的行为：工作区已是远端内容而索引仍旧的卡死状态、被杀的 checkout 经日志补做、本地改动挡住拉取时按 `rescueFolder` 留副本。
- `phoneSync.test.ts`：真实 `GitActions` 加 `SyncSupervisor` 在 `IsomorphicGit` 上的联动：`syncOnLeave` 只扫收件箱、弱网下错误静默重试（不弹窗）、一次完整的离开同步，外加 `commitsAhead`。
- `networkPolicy.test.ts`：`networkPolicy.ts` 的纯函数测试（注入 `NetworkEnvironment`、fake timers）：离线快速失败、超时、读请求重试、push 不重试、`isNetworkFailureMessage` / `redactUrl`。

**凭据桥**
- `askpass.test.ts`：`AskpassServer` 的本机 HTTP 桥：协议状态码、`ASK_PASS_SCRIPT` 经 `sh` 的端到端、作为 `GIT_ASKPASS` 跑真实 `git credential fill`；`SimpleGit` 把脚本装进 `manifest.dir`（缺省回落 `plugins/<manifest.id>`）并写入 `.git/info/exclude`。弹窗用 `vi.mock` 替换。

## 4. 本层约束 / 约定 / 禁忌

- 环境依赖：PATH 要有 `git`（push 补丁测试还要 `git http-backend`，askpass 要 POSIX `sh`）。断言写死默认分支 `main` 与 `origin/main`，由 `helpers/gitRepo` 保证；自建 fixture 要沿用。
- 仓库 / 上下文必须经 `withCleanup(...)` 或 harness 的 `cleanup()` 回收，否则临时目录泄漏。
- manager 层不展示错误：失败只抛出，用例断言 `plugin.displayError` 没被调用。`setPluginState` 的调用序列（进入操作、回到 `GitOperation.idle`）是被精确断言的契约，改 `withGitOperation` 或新增 Git 操作要同步。
- 两个后端的 glob 语义必须一致：`*` 不跨目录、`**` 跨目录，末尾 `/` 表示目录，隐藏文件参与匹配，空 include 不暂存任何文件，手动已暂存的内容仍被提交。
- 跑 `GitActions` 的用例要手工补 plugin 的 `updateCachedStatus`、`isAllInitialized`、`tools.hasTooBigFiles`、`displayMessage`，新用例照抄。
- 升级 isomorphic-git 前先确认补丁仍适用：`isomorphicGitPushAfterMerge.test.ts` 是回归开关，补丁与退出方式见 `MAINTENANCE.md`。

## 5. 什么时候需要下钻

- 改 `simpleGit.ts` 或 `isomorphicGit.ts` 的 pull / merge / status：读对应的 `simpleGit.test.ts` / `isomorphicGit.test.ts`，并连带 `gitManager.test.ts`；改 `GitManager` 契约或 `GitActions.commit` 的结果：两个后端都要过。
- 改拉取修复、救援文件夹、`scopedStatus` / `commitsAhead`：读 `pullRecovery.test.ts`、`phoneSync.test.ts`；改弱网重试：`networkPolicy.test.ts`；改 `askpassServer.ts` 或 `ASK_PASS_SCRIPT`：`askpass.test.ts`。
- 监督器本身的测试在上一级 `tests/syncSupervisor.test.ts`；要新的 fixture 或假 plugin：先读 `tests/helpers/.frac.md`。
