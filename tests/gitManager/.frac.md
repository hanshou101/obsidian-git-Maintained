## 1. 本目录是什么

`src/gitManager/`、`src/gitActions` 与凭据桥的集成测试目录，是整个测试套件里最重的一块（8 个文件，约 4100 行）。几乎全部用例都跑在真实的临时 git 仓库上，不 mock git：桌面后端 `SimpleGit`（原生 git）、移动后端 `IsomorphicGit`（isomorphic-git）、两者共享的 `GitManager` 契约，以及 `AskpassServer`；维护版新增的拉取中断修复、`GitActions` 与 `SyncSupervisor` 的联动也在真实仓库上测，只有弱网请求策略 `networkPolicy` 是纯函数测试、不碰仓库。
没有子目录。仓库 fixture、假 plugin、manager 构造器全部来自 `tests/helpers/`（`cleanup`、`createFakePlugin`、`gitRepo`、`gitManagerHarness`、`simpleGit`、`isomorphicGit`；`networkPolicy.test.ts` 不用 helper），`obsidian` 由 vitest 别名指向 `tests/stubs/obsidian.ts`。

## 4. 本层约束 / 约定 / 禁忌

- 真实环境依赖：PATH 中必须有 `git`（`isomorphicGitPushAfterMerge` 还需要 `git http-backend`，`askpass` 还需要 POSIX `sh`）。断言写死默认分支 `main` 与 `origin/main`，由 `helpers/gitRepo` 的 fixture 保证；自建 fixture 时要沿用。
- 每个仓库/上下文必须用 `withCleanup(...)`（或 harness 的 `cleanup()`）回收，否则临时目录泄漏；`afterEach(vi.restoreAllMocks)` 只在 `isomorphicGit.test.ts`、`pullRecovery.test.ts`、`phoneSync.test.ts` 全局设置；`networkPolicy.test.ts` 在 `beforeEach` / `afterEach` 里切换 fake timers。
- manager 层不展示错误：失败只抛出（`GitConflictError` 等），`plugin.displayError` 必须不被调用，展示由 `GitActions` / UI 边界负责；多处用例专门断言这一点。
- `setPluginState` 的调用序列是被精确断言的契约（进入操作、成功或失败后回到 `GitOperation.idle`；无操作的 no-op 路径则完全不调用）。改 `withGitOperation` 或新增 Git 操作时，这里的序列用例会失败，需同步更新。
- 两个后端对同一份 glob 语义必须一致：`*` 不跨目录、`**` 跨目录；末尾 `/` 表示目录（`private/` 不匹配 `private-old/`，`public.md/` 不匹配文件 `public.md`）；括号按字面量；支持 `[[:digit:]]` 等 POSIX 字符类；隐藏文件参与匹配；空 include 列表不暂存任何文件；手动已暂存的内容在 include / exclude 下都仍被提交；被排除的已删除文件保持未暂存。
- `GitActions` 用例每个都要手工补 4 项 plugin 成员：`updateCachedStatus`、`isAllInitialized`、`tools.hasTooBigFiles`、`displayMessage`（目前是复制粘贴的样板）；新增同类用例时照抄。
- `IsomorphicGit` 的 spy 拦截的是默认导出对象上的方法（`pullRecovery.test.ts` 也用它 spy `git.checkout`，在 checkout 里先写几个文件再 reject 来模拟被杀的拉取；`isomorphicGit.ts` 现在是 `import git, { Errors, readBlob } from "isomorphic-git"` 并以 `git.merge` / `git.checkout` 等调用，`readBlob` 是具名导入，这种 spy 拦不到），改变源码对 isomorphic-git 的引用方式（例如换成具名导入）可能让这些 spy 失效 [推测，失效的后果未实测]。
- 维护版特有的几处不要回退：`isomorphicGitPushAfterMerge.test.ts` 的对象数 6 / 12，`manualCommitUsesAutoCommitGlobs` 用例，`pullRecovery.test.ts`（手机上出错的那组文件、日志与恢复、救援文件夹），以及 `phoneSync.test.ts`（scoped status、弱网下静默重试）。升级 `isomorphic-git` 版本时先确认补丁仍然适用，`isomorphicGitPushAfterMerge.test.ts` 就是回归开关。
