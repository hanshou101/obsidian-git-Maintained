## 1. 本目录是什么

`src/gitManager/`、`src/gitActions` 与凭据桥的集成测试目录，是整个测试套件里最重的一块（5 个文件，约 3300 行）。几乎全部用例都跑在真实的临时 git 仓库上，不 mock git：桌面后端 `SimpleGit`（原生 git）、移动后端 `IsomorphicGit`（isomorphic-git）、两者共享的 `GitManager` 契约，以及 `AskpassServer`。
没有子目录。仓库 fixture、假 plugin、manager 构造器全部来自 `tests/helpers/`（`cleanup`、`createFakePlugin`、`gitRepo`、`gitManagerHarness`、`simpleGit`、`isomorphicGit`），`obsidian` 由 vitest 别名指向 `tests/stubs/obsidian.ts`。

## 2. 直属文件

- `gitManager.test.ts`：后端无关的契约测试。`describe.each(gitManagerBackends)` 让每个用例对 SimpleGit 与 IsomorphicGit 各跑一遍；`backend.create(fixture?)`（`helpers/gitManagerHarness`）返回 `{ manager, plugin, repo, cleanup }`，`afterEach` 负责 `cleanup()`。
  - 覆盖：`status()` 的路径与状态字母、`show`、`stage/unstage`、`commit/commitAll`（含 `amend`、返回提交文件数）、`selection: { mode: "exclude" | "include", globs }` 的 glob 语义、detached HEAD / 无 upstream 下 `branchInfo / canPush / pull / push` 的归一化结果、合并冲突流（`createRepoWithMergeConflict`：`status.conflicted`、`isMergeInProgress()`、两亲提交、`GitConflictError`）。
  - `GitActions` 级用例（`new GitActions(plugin).commit / commitAndSync`）：结果形如 `{ status: "success", value: { status: "committed", files } }` 或 `{ status: "nothing-to-commit", reason: "no-changes" | "nothing-staged" }`；auto commit globs 默认只作用于 `fromAuto: true`；`commitAndSync` 在 pull 与 push 之间不刷新 status；`formatCommitMessage` 配合 `listChangedFilesInMessageBody`；glob 过滤后无变更时不能弹出 `CustomMessageModal`（用 spy 断言）。
  - 维护版新增：`applies the auto commit globs to manual commits when enabled`，对应设置 `manualCommitUsesAutoCommitGlobs`。开启且 `autoCommitGlobMode = "include"` 时，手动 `mode: "all"` 提交只提交 glob 选中的文件；用户显式 stage 的文件（`mode: "smart"`）仍会提交；关闭后（上游默认）手动提交恢复为提交全部。紧邻的 `applies excluded paths to auto commits only` 是它的对照：选项未开时手动提交不受 glob 影响。
- `simpleGit.test.ts`：只针对 `SimpleGit` 的行为，用 `createSimpleGitTestContext()` 或本文件局部的 `createManager(repoPath, gitClient, plugin, vaultPath)`（把 vault 放进仓库子目录 `docs/` 以测 `limitToVault`）。
  - `commit / commitAll`：提交数、`setPluginState` 序列 `[{operation: GitOperation.commit}] → [{operation: GitOperation.idle}]`、触发 `obsidian-git:head-change`；批量暂存必须只调用一次 `git.add(["-A", "--", ".", ":(exclude,glob)<glob>"])`，include 模式为 `["-A", "--", ":(glob)<glob>"]`。
  - vault 范围：`limitToVault` 开/关下的 `status`（`stagedOutsideVault`、`conflictedOutsideVault`）、include/exclude globs 以仓库根为基准并可越过 vault 范围、`unstageAll / discardAll` 只作用于 vault 内、`getTreeStructure(…, "vault")` 的 `vaultPath`。
  - `pull`：`updated`（`files: [{ path, workingDir: "P", vaultPath }]`、`outsideVault` 计数）/ `up-to-date` / `skipped (no-upstream)`；`syncMethod` 的 merge / rebase / reset；`rebaseAutoStash` 的 `enabled | disabled | git-config`；冲突抛 `GitConflictError`（`files`）且不调用 `displayError`；detached HEAD 报 `No current branch found. Cannot pull.`。
  - `push`：`pushed`（`files` 数或 `null`）/ `up-to-date` / `blocked (no-branch)` / `skipped (no-upstream)`，push 目标与 upstream 不同时的 `getUnpushedCommits / canPush`。
  - 其余：`branchInfo`（含首次提交前、detached）、`fetch`/`checkout` 的操作状态与进度清理、`toGitProgress` 事件映射（"Fetching" / "Pushing" / "Checking out"）、`squashAllUnpushedCommits`（及它不动手的 4 种情形）、`show` 应用 textconv。
  - 局部辅助：`addStatusBar`（mock `displayProgress / clearProgress`）、`addVaultDirectory`、`createRemoteCommit`、`createPullConflict`。
- `isomorphicGit.test.ts`：只针对 `IsomorphicGit`，用 `createIsomorphicGitManager(repoPath)`（返回 `manager / plugin / setPluginState / updateCachedStatus`）。远端用 `update-ref refs/remotes/origin/main` + `reset --hard` 模拟，`manager.fetch` 被 mock，不碰网络；`vi.spyOn(git, "merge" | "checkout" | "push" | "add")` 作用在 `isomorphic-git` 默认导出对象上。
  - `pull` 的 merge 状态：快进遇到与本地编辑重叠的文件时抛 `/uncommitted/` 且 HEAD 与工作区不变；保留无关的 staged / unstaged 改动；本地领先时返回 `up-to-date`；无树变化的 merge 提交不调用 `checkout`；准备快进期间被编辑的文件会被发现；被忽略的未跟踪文件不被远端覆盖（`/untracked file/`）；`checkout` 失败不推进 HEAD；强制 checkout 只限变更路径（`force: true, noUpdateHead: true`）；真实 merge 以 `abortOnConflict: true` 调用并拒绝覆盖未提交编辑。
  - 冲突与元数据：未解决冲突只出现在 `conflicted`；提交后清除 `.git/MERGE_MSG` / `MERGE_MODE` 并 `setPluginState({ mergeInProgress: false })`；冲突提交抛 `GitConflictError` 且不 `updateCachedStatus` / `displayError`；`mergeStrategy = "none"` 时写入冲突标记与 `ORIG_HEAD / MERGE_HEAD / MERGE_MSG`。
  - `push` 返回显式结果、失败原样抛出；`stage` 失败不 `displayError`；`getFileChangesCount` 把仅改 mode 的文件算作 `M`，且不进入两侧相同的子树；`status()` 第二次不再重读未变化的工作区文件（`readBinary` 计数为 0）。
- `isomorphicGitPushAfterMerge.test.ts`（维护版新增）：守护 `patches/isomorphic-git@1.44.3.patch`（pnpm patch，回移 isomorphic-git PR #2458）。测试内自带 `HttpClient`，把每个请求交给真实的 `git http-backend` CGI（`spawnSync`，环境变量 `GIT_PROJECT_ROOT / GIT_HTTP_EXPORT_ALL / PATH_INFO / QUERY_STRING / REQUEST_METHOD`），并解析 `git-receive-pack` 请求体里 `PACK` 头的对象数记入 `pushedObjectCounts`。
  - `describe.each(builds)` 同时覆盖 `index.cjs`（Node / 测试使用，`createRequire` 加载）与 `index.js`（Vite 打出的插件 bundle 使用，`pathToFileURL` 动态 import 的 `default`）两个构建。
  - 用例一：远端已有 40 条历史，手机提交一次后与桌面提交合并，再 `push`，断言只上传 6 个对象（手机提交的 commit + 两棵 tree + blob，加合并提交与其根 tree；未打补丁的 1.44.3 会重发全部 41 个提交）；用例二：远端仅落后（3 个手机提交），仍应上传全部缺失的 12 个对象。两者都断言远端与手机的 `rev-parse main` 相等，并跑 `git fsck --no-dangling`。
- `askpass.test.ts`：`AskpassServer` 的 127.0.0.1 HTTP 桥（`POST /askpass`，请求体为 `token\nprompt`）。`vi.mock("../../src/ui/modals/generalModal")` 以 `vi.hoisted` 的 `modal` 对象替代弹窗（记录 `obscure / placeholder`）。
  - 协议：回答返回 200 与 `answer\n`（空串返回 `\n`），用户取消返回 409，token 错误返回 403 且不开弹窗，同时只显示一个提示，`stop()` 时挂起请求返回 503 并关闭弹窗，启动期间 `stop()` 使 `start()` 以 `stopped during startup` 拒绝。

## 4. 本层约束 / 约定 / 禁忌

- 真实环境依赖：PATH 中必须有 `git`（`isomorphicGitPushAfterMerge` 还需要 `git http-backend`，`askpass` 还需要 POSIX `sh`）。断言写死默认分支 `main` 与 `origin/main`，由 `helpers/gitRepo` 的 fixture 保证；自建 fixture 时要沿用。
- 每个仓库/上下文必须用 `withCleanup(...)`（或 harness 的 `cleanup()`）回收，否则临时目录泄漏；`afterEach(vi.restoreAllMocks)` 只在 `isomorphicGit.test.ts` 全局设置。
- manager 层不展示错误：失败只抛出（`GitConflictError` 等），`plugin.displayError` 必须不被调用，展示由 `GitActions` / UI 边界负责；多处用例专门断言这一点。
- `setPluginState` 的调用序列是被精确断言的契约（进入操作、成功或失败后回到 `GitOperation.idle`；无操作的 no-op 路径则完全不调用）。改 `withGitOperation` 或新增 Git 操作时，这里的序列用例会失败，需同步更新。
- 两个后端对同一份 glob 语义必须一致：`*` 不跨目录、`**` 跨目录；末尾 `/` 表示目录（`private/` 不匹配 `private-old/`，`public.md/` 不匹配文件 `public.md`）；括号按字面量；支持 `[[:digit:]]` 等 POSIX 字符类；隐藏文件参与匹配；空 include 列表不暂存任何文件；手动已暂存的内容在 include / exclude 下都仍被提交；被排除的已删除文件保持未暂存。
- `GitActions` 用例每个都要手工补 4 项 plugin 成员：`updateCachedStatus`、`isAllInitialized`、`tools.hasTooBigFiles`、`displayMessage`（目前是复制粘贴的样板）；新增同类用例时照抄。
- `IsomorphicGit` 的 spy 拦截的是默认导出对象上的方法，改变源码对 isomorphic-git 的引用方式（例如换成具名导入）可能让这些 spy 失效 [推测，未读源码确认]。
- 维护版特有的两处不要回退：`isomorphicGitPushAfterMerge.test.ts` 的对象数 6 / 12，以及 `manualCommitUsesAutoCommitGlobs` 用例。升级 `isomorphic-git` 版本时先确认补丁仍然适用，这个测试就是回归开关。
