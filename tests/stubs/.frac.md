# .frac.md — tests/stubs

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

只有 `obsidian.ts`：`obsidian` 包在 Node/Vitest 下的手写最小替身，由 `vitest.config.ts` 的别名接管源码里所有 `import ... from "obsidian"`；不模拟界面或事件系统。

## 2. 直属文件

- `obsidian.ts`：
  - 值与类：`moment`（固定值桩）、`Platform`、`Notice`、`TFile` / `TFolder`、`Plugin` 等，以及一批空的界面基类（`Modal`、`ItemView`、`WorkspaceLeaf` 等）。
  - 函数：`normalizePath`、`debounce`、`requestUrl`、空操作的 `setIcon` / `setTooltip`，维护版加的 `getLanguage`（恒返回 `"en"`，`syncProblems.ts` 靠它选文案语言）。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- `Platform` 是可变对象，默认全是桌面值；走移动端分支的用例要自己改属性并还原。`requestUrl` 恒返回 404 且无 body，要别的响应在用例里覆盖。
- `debounce` 是手动触发版：不起定时器，回调只在 `.run()` 时执行；断言传给它的延迟要 `vi.mock("obsidian")` 包一层（见 `tests/automaticsManager.test.ts`）。
- `Notice` 只存 `message` 与 `timeout`，`messageEl`（`SyncSupervisor` 给通知挂点击监听用）是维护版加的；断言弹了什么通知要 `vi.mock("obsidian")` 派生子类（见 `tests/syncSupervisor.test.ts`）。
- `Modal`、`ItemView` 等是无成员的空类：继承它们的 UI 类能 import、不能实例化后使用，用例要整模块 `vi.mock` 或 `Object.create(X.prototype)`；`TFile` / `TFolder` 依赖 `tests/setup.ts` 补的 `Array.prototype.last()`。
- 导出的类型（`Editor`、`Vault`、`App` 等）比真实 `obsidian` 窄得多，只够让别名后的导入可编译；要更多成员，或源码新引用了这里没有的 API，就在此补最小实现（不引入真实 `obsidian` 包），否则运行时读到 `undefined`、用到才失败。

## 5. 什么时候需要下钻

- 源码新增 `obsidian` 导入，或用例因 stub 的行为失败：先读本文件，再决定改 stub 还是在用例里局部覆盖。
- 要伪造 plugin / vault：看 `tests/helpers/.frac.md`（它的假对象与这里的类型不共享定义）。
