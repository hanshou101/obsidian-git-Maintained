## 1. 本目录是什么

`src/editor/`（CodeMirror 集成）的测试目录，按源码子模块镜像成子目录，位于 `tests/` 之下。本目录没有直属文件，只容纳 `conflicts/` 与 `signs/`。`src/editor/` 里的 `lineAuthor/`、`control.ts`、`editorIntegration.ts`、`eventsPerFilepath.ts`，以及 CodeMirror 扩展实例、hunk 操作按钮，全仓测试都没有覆盖。

## 2. 直属文件

无直属文件。

## 3. 子目录导航

- `conflicts/`：见 `conflicts/.frac.md`；合并冲突标记解析模型 `model.ts`（`parseConflictBlocks` / `resolveBlockText`）的纯函数测试。
- `signs/`：见 `signs/.frac.md`；`diff.ts` 的 `computeHunks`（含增量更新）与 `hunks.ts` 的 `Hunks` 静态工具测试，另有用真实 `git` 交叉验证的补丁往返测试。

## 4. 本层约束 / 约定 / 禁忌

- 子目录名对应 `src/editor/<name>/`；新增编辑器子模块的测试沿用这个镜像结构，并在新目录补 `.frac.md`。
- 两个子目录都是纯逻辑测试，经相对路径 `../../../src/editor/...` 导入被测模块，不依赖 `obsidian` stub 或 `tests/helpers/`；唯一外部依赖是 `signs/patchRoundTrip.test.ts` 需要 PATH 里有 `git`。目录层级变动时这些相对路径要同步改。
- 位置 / 偏移类字段（冲突块的 `from/to` 与各区间 range、hunk 的 `start/count/vend`）是被逐字断言的契约；改实现按两个子目录 `.frac.md` 写明的语义来，不是只调整期望值。

## 5. 什么时候需要下钻

- 改冲突标记解析：读 `conflicts/.frac.md`。
- 改 gutter 标记、hunk 数据结构、补丁文本生成：读 `signs/.frac.md`，补丁相关改动还要跑往返测试。
- 给 `src/editor/` 里还没有测试的部分加测试：先确认对应源码子目录，再在本目录下建镜像子目录。
