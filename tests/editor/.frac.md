## 1. 本目录是什么

`src/editor/`（CodeMirror 集成）的测试目录，按源码子模块一一镜像成子目录，位于 `tests/` 之下。本目录自身没有直属文件，只是 `conflicts/` 与 `signs/` 两个子目录的容器。
当前只覆盖冲突块解析与 diff 标记/hunk 逻辑；本目录里没有针对 CodeMirror 扩展实例、hunk 操作按钮或 line authoring 的测试。

## 2. 直属文件

无直属文件。

## 3. 子目录导航

- `conflicts/`：见 `conflicts/.frac.md`；`src/editor/conflicts/model` 的 `parseConflictBlocks` / `resolveBlockText` 单元测试（两路与 diff3 冲突标记、各区间的字符偏移）。
- `signs/`：见 `signs/.frac.md`；`src/editor/signs/diff` 的 `computeHunks`（含增量更新）与 `hunks` 的 `Hunks` 静态工具测试，另有一个用真实 `git diff --no-index` / `git apply --unidiff-zero` 做交叉验证的往返测试。

## 4. 本层约束 / 约定 / 禁忌

- 子目录名与 `src/editor/<name>/` 对应；新增编辑器子模块的测试时沿用这个镜像结构，并在新目录里补 `.frac.md`。
- 两个子目录的测试都是纯逻辑测试，直接用相对路径 `../../../src/editor/...` 导入被测模块，不依赖 `obsidian` stub 或 `tests/helpers/`；唯一的外部依赖是 `signs/patchRoundTrip.test.ts` 需要 PATH 中有 `git`。目录层级变动时这些相对路径要同步修改。
- 位置/偏移类字段（冲突块的 `from/to` 与各区间 range、hunk 的 `start/count/vend`）是被逐字断言的契约，改实现时按 `conflicts/`、`signs/` 的 `.frac.md` 里写明的语义来改，而不是只调整期望值。

## 5. 什么时候需要下钻

- 改冲突标记解析（`src/editor/conflicts/model.ts`）：读 `conflicts/.frac.md`。
- 改 gutter 标记、hunk 数据结构、补丁文本生成（`src/editor/signs/diff.ts`、`hunks.ts`）：读 `signs/.frac.md`，补丁相关改动还要跑往返测试。
- 想给 `src/editor/` 里没有测试的部分（如 line authoring）加测试：先在 `src/editor/` 的对应子目录确认模块，再决定在本目录下新建镜像子目录。
