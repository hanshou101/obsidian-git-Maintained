# .frac.md — tests/editor/signs

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

`src/editor/signs/` 中行级 diff 与 hunk 逻辑（编辑器 gutter 的变更标记，以及 hunk 暂存 / 还原用的补丁生成）的测试，位于 `tests/editor/` 之下。纯逻辑：不用 `obsidian` stub 和 `tests/helpers/`，只经相对路径 `../../../src/editor/signs/` 导入 `diff` 与 `hunks`。

## 2. 直属文件

- `diff.test.ts`：`computeHunks` 的精确输出（单行 / 多行的增删改、文件头尾、缺结尾换行）；另验证带上一次 `chunks` 与 `ChangeSet` 描述的增量计算，结果须等于全量计算。
- `hunks.test.ts`：`Hunks` 静态工具类，覆盖 `createHunk`、`getHunkHeader` / `parseDiffLine`、`calcSigns`、`createPatch`、`findHunk` / `findNearestHunk`、`createPartialHunk`、`patchLines`、`getSummary`。局部辅助函数 `hunk(...)` 包装 `createHunk` 并填入行内容。
- `patchRoundTrip.test.ts`：用真实 `git` 二进制交叉验证。同一组 case 上，`computeHunks` 每个 hunk 的起止要等于 `git diff --no-index --unified=0` 的 `@@` 头；`Hunks.createPatch` 的输出在临时目录里经 `git apply --unidiff-zero` 后必须还原出 `newText`。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- Hunk 数字约定是被逐字断言的契约：沿用 `-U0` 的 unified diff 约定，纯 add 的 `removed.count` 为 0、纯 delete 的 `added.count` 为 0；`vend` 是该 hunk 在新文本的末行，纯 delete 时等于 `added.start`；文件开头删除 / 插入时对应一侧的 `start` 为 0。
- `getHunkHeader` 只在计数为 0 时省略 `,count`，`parseDiffLine` 把缺省计数当 1。两边不对称是现有行为，改动前同时看 `hunks.test.ts` 与 `patchRoundTrip.test.ts`。
- `createPatch` 头部数字能否被 `git apply --unidiff-zero` 接受，只由 `patchRoundTrip.test.ts` 保证；不要只改 `hunks.test.ts` 的期望字符串。
- `patchRoundTrip.test.ts` 依赖 PATH 里有 `git` 并写系统临时目录；`git diff --no-index` 有差异时退出码为 1，用例靠 `catch` 读 `error.stdout`，不要改成 `--exit-code` 之类写法。
- `calcSigns` 的 sign 序列是逐项锁定的现有输出；untracked 只允许 add hunk，其余会 `console.error` 并返回 `[]`（用例用 spy 屏蔽）。改动前先确认 gutter 渲染是否依赖它。

## 5. 什么时候需要下钻

- 改 `diff.ts` 的算法或增量更新：读 `diff.test.ts` 与 `patchRoundTrip.test.ts`，两者都要重跑。
- 改 `hunks.ts` 的标记、补丁生成、选区截取：读 `hunks.test.ts`；动补丁文本格式必须同时跑 `patchRoundTrip.test.ts`。
- 冲突块解析的测试在 `../conflicts/.frac.md`，与本目录互不依赖。
