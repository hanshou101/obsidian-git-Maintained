## 1. 本目录是什么

`src/editor/signs/` 中行级 diff 与 hunk 逻辑的测试目录，对应编辑器 gutter 的变更标记（signs）与 hunk 暂存/还原所用的补丁生成。三个文件都是纯逻辑测试：不使用 `obsidian` stub、不使用 `tests/helpers/`，只直接导入 `src/editor/signs/diff` 与 `src/editor/signs/hunks`（相对路径 `../../../src/...`）。

## 2. 直属文件

- `diff.test.ts`：`computeHunks(oldText, newText, prevChunks, changeDesc)` 的精确输出。
  - 用例：无变化返回 `[]`；单行 add / delete / change；一行换多行；文件头尾插入与删除（产生两个 hunk）；缺结尾换行时 `removed` 与 `added` 带 `no_nl_at_eof: true`。
  - 增量用例：用 `@codemirror/state` 的 `ChangeSet.of(...).desc` 加上上一次的 `chunks` 做增量计算，结果必须与不传 chunks 的全量计算的 `hunks` 相等。
  - 局部辅助函数 `computeHunksOnly` 只取 `.hunks`。
- `hunks.test.ts`：`Hunks` 静态工具类（及 `Hunk` 类型）。
  - 辅助函数 `hunk(oldStart, oldCount, newStart, newCount, removedLines, addedLines)` 包装 `Hunks.createHunk` 并填入行内容。
  - `createHunk`：按计数判定 add / delete / change，并给出 `vend`。
  - `getHunkHeader` / `parseDiffLine`：显式与省略计数两种写法，省略时计数按 1 解析。
  - `calcSigns`：返回 `{type, count, lnum}` 列表，类型含 `add`、`change`、`topdelete`、`changedelete`、`untracked`；可见行范围参数；untracked 只允许 add hunk，其他 hunk 会 `console.error` 并返回 `[]`（用例里用 `vi.spyOn(console, "error")` 屏蔽并断言调用一次）。
  - `createPatch`：4 行头（`diff --git` / `index 000000..000000 <mode>` / `---` / `+++`）加 hunk 行；支持 `invert` 参数；保留 `\ No newline at end of file`。
  - `findHunk` / `findNearestHunk`：按行定位 hunk，及 `first / last / next / prev` 加可选环绕。
  - `createPartialHunk`：按选区行范围截取 hunk。
  - `patchLines`（可选去掉 `\r`）与 `getSummary`（`{added, changed, removed}`）。
- `patchRoundTrip.test.ts`：用真实 `git` 二进制做交叉验证（`execFileSync`），共用同一组 8 个 `cases`（含缺结尾换行）。
  - 把 `computeHunks` 的每个 hunk 的 `start/count` 对比 `git diff --no-index --unified=0` 的 `@@` 头（经 `Hunks.parseDiffLine` 解析）。
  - 把 `Hunks.createPatch(...)` 的输出写文件，在临时目录里 `git apply --unidiff-zero` 后，文件内容必须等于 `newText`。
  - 临时目录由 `mkdtempSync(tmpdir()/obsidian-git-test-*)` 创建，在 `finally` 中 `rmSync` 清理。

## 4. 本层约束 / 约定 / 禁忌

- Hunk 数字约定是被逐字断言的契约：沿用 `-U0` 的 unified diff 约定，纯 add 的 `removed.count` 为 0、纯 delete 的 `added.count` 为 0；`vend` 是该 hunk 在新文本中的末行，纯 delete 时等于 `added.start`；文件开头删除/插入时对应一侧的 `start` 为 0。
- `getHunkHeader` 只在计数为 0 时省略 `,count`（计数为 1 仍写 `,1`，如 `@@ -4,1 +4,1 @@`）；`parseDiffLine` 则把缺省计数当作 1。两边不对称是现有行为，改动前要同时更新 `hunks.test.ts` 与 `patchRoundTrip.test.ts`。
- `createPatch` 头部数字是否能被 `git apply --unidiff-zero` 接受，只由 `patchRoundTrip.test.ts` 保证；不要只改 `hunks.test.ts` 的期望字符串。
- `patchRoundTrip.test.ts` 依赖机器上有可执行的 `git`（PATH 中），并写入系统临时目录；`git diff --no-index` 在有差异时退出码为 1，用例靠 `catch` 里读 `error.stdout` 处理，不要改成 `git diff --exit-code` 之类的写法。
- `calcSigns` 的 sign 序列是被逐项锁定的现有输出：例如 `hunk(4,1,4,3)` 产生 change@4、add@4、add@5、add@6，`count` 只出现在部分 sign 上（位置以用例断言为准）；改动前先确认 gutter 渲染是否依赖它。
- `calcSigns` 的第一与第三个位置参数在所有用例中都传 `undefined`；新增用例沿用同一调用形态。

## 5. 什么时候需要下钻

- 改 `src/editor/signs/diff.ts` 的 diff 算法或增量更新（`chunks` + `ChangeDesc`）：先读 `diff.test.ts` 与 `patchRoundTrip.test.ts`，三者都要重跑。
- 改 `src/editor/signs/hunks.ts` 的标记、补丁生成、选区截取：读 `hunks.test.ts`；动补丁文本格式时必须同时跑 `patchRoundTrip.test.ts`。
- 冲突块解析的测试在上一层的 `conflicts/` 子目录，见 `../conflicts/.frac.md`，与本目录互不依赖。
