## 1. 本目录是什么

`src/editor/conflicts/model.ts`（合并冲突标记的纯文本解析模型）的单元测试，位于 `tests/editor/` 之下。全是纯函数断言：不依赖 `obsidian` stub、`tests/helpers/`、CodeMirror 实例或文件系统。

## 2. 直属文件

- `model.test.ts`：覆盖 `parseConflictBlocks` 与 `resolveBlockText` 两个导出；场景是无标记、单个两路冲突、多个冲突、带 `|||||||` 基线段的 diff3 冲突。文件内辅助函数 `lines(...)` 用 `\n` 连接并补结尾换行，所有输入文本都经它构造。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 位置语义是被断言的契约，都是原文本的字符下标，用 `text.slice(from, to)` 验证：`block.from/to` 覆盖整个冲突块（含最后一个标记行的换行）；`markers[i].from/to` 只覆盖标记行本身、不含换行；`oursRange / baseRange / theirsRange` 覆盖各段正文并含结尾换行。
- 段内容（`ours` / `base` / `theirs`）保留结尾 `\n`；非 diff3 时 `base` / `baseRange` 必须是 `undefined` 而不是空串；`markers` 个数随是否 diff3 变化。
- `resolveBlockText` 只实际测了 `"base"` 选项；其他选项、CRLF、未闭合 / 嵌套标记都没有用例，扩展这些行为要自行补测试。
- 被测模块经相对路径 `../../../src/editor/conflicts/model` 导入，不走 `src` 别名；移动目录要同步这个路径。
