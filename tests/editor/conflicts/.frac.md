## 1. 本目录是什么

`src/editor/conflicts/model.ts`（合并冲突标记的纯文本解析模型）的单元测试目录，位于 `tests/editor/` 之下。
只有一个测试文件，全部是纯函数断言：不依赖 `obsidian` stub、不依赖 `tests/helpers/`、不碰 CodeMirror 实例或文件系统。

## 2. 直属文件

- `model.test.ts`：覆盖 `parseConflictBlocks(text)` 与 `resolveBlockText(block, choice)` 两个导出，用例如下。
  - 无标记文本返回 `[]`。
  - 单个两路冲突（`<<<<<<< HEAD` / `=======` / `>>>>>>> origin/master`）：`ours`、`theirs` 带结尾 `\n`，`base` 与 `baseRange` 为 `undefined`；`markers` 长度为 3。
  - 多个冲突按文档顺序各自成块。
  - diff3 冲突（含 `|||||||` 基线段）：`markers` 长度为 4，`base` 为 `"base\n"`，`baseRange` 有值，`resolveBlockText(block, "base")` 返回 `"base\n"`。
  - 文件内本地辅助函数 `lines(...values)`：用 `\n` 连接并补结尾换行，所有输入文本都经它构造。

## 4. 本层约束 / 约定 / 禁忌

- 位置语义是被断言的契约：`block.from/to` 覆盖整个冲突块（含最后一个标记行的换行）；`markers[i].from/to` 只覆盖标记行本身、不含换行；`oursRange / baseRange / theirsRange` 覆盖各段正文并包含结尾换行。三者都是原文本的字符下标，用 `text.slice(from, to)` 验证。
- 段内容字符串（`ours` / `base` / `theirs`）一律保留结尾 `\n`，改解析逻辑时不要悄悄去掉。
- `markers` 的个数随是否为 diff3 变化（3 或 4），`base`/`baseRange` 在非 diff3 时必须是 `undefined` 而不是空串。
- 本文件只实际执行了 `resolveBlockText` 的 `"base"` 选项；其他选项、CRLF、未闭合/嵌套标记都没有用例。扩展这些行为时要自行补测试。
- 用例通过相对路径 `../../../src/editor/conflicts/model` 导入被测模块，而不是 `src` 别名；移动目录时要同步这个路径。
