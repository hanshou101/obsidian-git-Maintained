## 1. 本目录是什么

`src/ui/diff/` 下 split diff 视图的测试目录，位于 `tests/ui/` 之下。目前只有 `splitDiffView.test.ts` 一个文件，混合了两类测试：对真实临时 git 仓库的 `SplitDiffView.gitShow` 测试，以及对"不执行构造函数的视图对象"做的纯 mock 刷新逻辑测试。

## 2. 直属文件

- `splitDiffView.test.ts`：被测对象是 `SplitDiffView` 默认导出与具名导出 `getSplitDiffTimeout`（从 `src/ui/diff/splitDiffView` 以 `src` 别名导入），另用到类型 `DiffViewState`（`src/types`）。
  - `getSplitDiffTimeout(timeout, flag)`：`flag === true` 返回原值（75 → 75），`false` 返回 10 倍（75 → 750）；`0`、负数、`NaN`、非整数（1.5）视为无效持久化值，回落到默认 50（`false` 时为 500）。测试标题写的是 "ten times ... for read-only diffs"，布尔参数的方向以断言为准，改动前到源码确认含义。
  - `SplitDiffView.gitShow(ref, path)`（真实 git）：未合并文件在 `ref === ""` 时读 index 中我方（stage 2）的版本，`ref === "HEAD"` 时读 HEAD 的版本，冲突仓库里两者都是 `ours\n`；我方删除文件的 modify/delete 冲突返回 `""`（空对比）；当 stage 2 是唯一冲突阶段时（目录/文件冲突产生的 `folder~HEAD` 路径）仍读 stage 2；已解决文件继续读 stage 0。
  - `SplitDiffView` 刷新逻辑（mock）：`isWorkingTreeBFile(vaultPath)` 仅在 `bRef` 为 `undefined` 且路径等于 `getRelativeVaultPath(bFile)` 时为真；`updateModifiableEditor()` 用 `app.vault.adapter.read` 读 vault 相对路径（如 `repo/note.md`）；`updateModifiableEditor()` 与 `updateRefEditors()` 在读取/`gitShow` 失败时必须 reject 且把 `refreshing` 复位为 `false`，下一次刷新仍然可用。
  - 文件内局部辅助函数：`editorWithText(text)`（带 `state.doc.toString/length`、`state.update`、`dispatch` 的最小编辑器替身）与 `createView(state)`（见下文）。
- 依赖的共享测试设施（均不在本目录）：`tests/helpers/cleanup`（`withCleanup`）、`tests/helpers/gitRepo`（`createRepoWithOrigin`、`createRepoWithMergeConflict`）、`tests/helpers/simpleGit`（`createSimpleGitTestContext`，返回 `{ manager, repo, plugin, cleanup }`，`cleanup` 由 `withCleanup` 在每个用例后调用）。

## 4. 本层约束 / 约定 / 禁忌

- 视图对象不走构造函数：测试用 `Object.create(SplitDiffView.prototype)` 加 `Object.assign` 注入字段（`gitShow` 测试只注入 `plugin.gitManager`；`createView` 注入 `refreshing`、`state`、`mergeView`、`app.vault.adapter.read`、`plugin.gitManager.getRelativeVaultPath`）。构造函数会注册 workspace 事件，所以不能直接 `new`。源码里的方法如果开始读取新的 `this.*` 字段，这里的注入对象必须同步补上，否则会在测试里 `undefined` 报错。
- `createView` 模拟"仓库位于 vault 子目录 `repo`"：`getRelativeVaultPath` 返回 `repo/<path>`，读文件必须使用这个 vault 路径，不是仓库相对路径。
- `gitShow` 的内联 fixture 假定默认分支为 `main`（`repo.git.checkout("main")`）；`merge(["other"]).catch(() => undefined)` 是有意吞掉冲突退出码来制造未合并状态。
- 这些用例会在临时目录里起真实 git 仓库，需要机器上有 `git`；每个上下文都要用 `withCleanup(...)` 包裹，保证临时仓库被删除。
- 导入风格：被测源码用 `src/...` 别名，测试辅助用相对路径 `../../helpers/...`（由 `vitest.config.ts` 的别名决定）。
