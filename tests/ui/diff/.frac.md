# .frac.md — tests/ui/diff

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

`src/ui/diff/splitDiffView.ts`（split diff 视图）的测试，位于 `tests/ui/` 之下。一个文件，两类测试：真实临时 git 仓库上的 `SplitDiffView.gitShow`，以及不执行构造函数的视图对象上的 mock 刷新逻辑。

## 2. 直属文件

- `splitDiffView.test.ts`：被测对象是默认导出 `SplitDiffView` 与具名导出 `getSplitDiffTimeout`（经 `src` 别名导入）。
  - `getSplitDiffTimeout`：超时换算与无效持久化值的回落；布尔参数方向以断言为准，改前到源码确认。
  - `gitShow`（真实 git）：未合并文件读 index 里我方（stage 2）的版本；我方删除的 modify/delete 冲突返回空串；已解决文件读 stage 0。
  - 刷新逻辑（mock）：`isWorkingTreeBFile` 判定；`updateModifiableEditor` 经 vault 路径读文件；读取或 `gitShow` 失败时它与 `updateRefEditors` 必须 reject 并把 `refreshing` 复位。
- 共享设施来自 `tests/helpers/`：`cleanup`、`gitRepo`、`simpleGit`。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 视图对象不走构造函数（它会注册 workspace 事件）：`Object.create(SplitDiffView.prototype)` 加 `Object.assign` 注入字段。`gitShow` 用例只注入 `plugin.gitManager`，`createView` 另注入刷新要读的字段。源码方法开始读新的 `this.*` 字段时，注入要同步补，否则用例里报 `undefined`。
- `createView` 模拟「仓库位于 vault 子目录 `repo`」：读文件用 vault 路径，不是仓库相对路径。
- `gitShow` 的内联 fixture 假定默认分支为 `main`；`merge(["other"]).catch(() => undefined)` 是有意吞掉冲突退出码来制造未合并状态。
- 临时 git 仓库需要机器上有 `git`；每个上下文都用 `withCleanup(...)` 包裹以删除临时仓库。

## 5. 什么时候需要下钻

- 改 `splitDiffView.ts` 的 `gitShow`（冲突阶段选择）、`refreshing` 刷新状态机或超时换算：先读本目录对应用例。
- 新增需要真实仓库或冲突状态的用例：看 `tests/helpers/.frac.md`，复用 fixture，不手写 git 命令。
