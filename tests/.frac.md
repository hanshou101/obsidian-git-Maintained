# .frac.md — tests

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

整个 Vitest 测试套件的根目录。测试在 Node 环境运行，不启动真实 Obsidian：`vitest.config.ts` 把 `obsidian` 别名到 `tests/stubs/obsidian.ts`、`src` 别名到源码目录，`setup.ts` 在每个测试文件前执行，匹配规则是 `tests/**/*.test.ts`。涉及 Git 行为的用例用真实的临时 git 仓库。
本层直属文件是与 UI、Git 后端都无关的编排类测试，加 `README.md` 与 `setup.ts`；其余测试按源码子目录镜像放在子目录里，`helpers/` 与 `stubs/` 是支撑代码而非测试。

## 2. 直属文件

**说明与全局设置**
- `README.md`：测试策略的人工文档（命令、runner 配置、stub 与 helper 用法、设计原则、可选的 E2E 方案），写新测试前的第一站。原则：纯逻辑写纯单元测试，Git 工作流用真实临时仓库而不 mock `simple-git`，不拉起 Obsidian，stub 保持最小。
- `setup.ts`：全局 setup。缺失时补 `Array.prototype.last` / `contains`、`String.prototype.contains`、`Math.clamp`（两个 `contains` 是维护版加的，`AutomaticsManager` 与 `SimpleGit` 要用）；`window` / `activeWindow` 是返回 `globalThis` 的 getter，`localStorage` 是普通对象，`activeDocument` 没有 `document` 时回落到近乎空实现的伪造文档。

**上游原有的编排类测试**
- `automaticsManager.test.ts`：`AutomaticsManager` 的自动 commit-and-sync：`createFakePlugin()` 加真实 `PromiseQueue` 和 mock 的 `gitActions.commitAndSync`，验证第一次运行期间的编辑恰好再提交一次；debouncer 由用例手动 `.run()`。维护版加了一组断言等待时间的用例，靠 `vi.mock("obsidian")` 包装 `debounce` 记录参数。
- `coalesce.test.ts`：`coalesce(fn)`：运行期间的多次调用合并成一次后续运行并共享同一个 promise；上一轮结束后可重新开始；活动运行失败时后续运行仍会执行。
- `promiseQueue.test.ts`：`PromiseQueue`：任务 rejection 逃逸时记 `console.error` 并继续执行下一个任务。
- `gitAction.test.ts`：`runGitAction(host, action)` 与 `GitActionHost`。结果是 `success` / `failed` / `cancelled` 三态：冲突交给 `handleConflict` 且只报一次，用户取消静默，push 被拒给出对应提示，其他错误只 `displayError` 一次。

**维护版新增的测试**
- `syncSupervisor.test.ts`：`SyncSupervisor` 本身：`vi.mock("obsidian")` 派生 `Notice` 子类记录通知，手写假插件（不用 `createFakePlugin`），`vi.useFakeTimers()` 加只有 `visibilityState` getter 的假 `document`（`afterEach` 还原）。覆盖历史、弱网重试与恢复通知、需要用户处理的问题、离开 / 回来 / 启动时的同步、哪些编辑算数、亮屏。
- `syncProblems.test.ts`：`classifySyncError` 与 `problemText`，纯函数：同一个网络错误在在线 / 后台 / 离线下的分类、HTTP 状态到 `kind` 的映射、从拉取错误里解析被挡的文件列表，以及每种 `kind` 的中英文文案（只有 `autoRetry` 为真才承诺自动重试）。
- `autoCommitGlobs.test.ts`：`includeGlobScope`：取 include glob 开头的字面文件夹；无法收窄到某个文件夹的 glob（如 `**/*.md`、空列表）返回 `undefined`。

## 4. 本层约束 / 约定 / 禁忌

- 只在 Node 下运行，没有 DOM：依赖真实 DOM 的代码要在用例里提供自己的假对象，不要扩充 `setup.ts`（它对整个套件生效）。`window` 就是 `globalThis`，所以源码里的 `window.setTimeout` 也受 `vi.useFakeTimers()` 控制。
- stub 与 helper 故意保持最小：只在测试确实需要时才增加符号或成员，不要做成保真的 Obsidian 运行时。
- 测试文件同样受 `pnpm run lint` 与 Prettier 检查（范围含 `tests`，见根 `AGENTS.md`）；不要夹带无关的格式化。
- 导入路径风格不统一：本层文件用 `../src/...`，子目录文件用 `../../src/...` 或 `src/...` 别名，helper 用相对路径；移动文件时同步这些路径。
- 真实环境依赖：Git 工作流测试需要本机 `git`（含 `git http-backend`），askpass 测试需要 POSIX `sh`；Node 与 pnpm 的版本要求见 `AGENTS.md`。
- 命名易混：`gitAction.test.ts` 测 `src/gitAction.ts` 的 `runGitAction`（单数），`GitActions` 类（`src/gitActions.ts`）的行为测试在 `gitManager/`。监督器同理：本层测监督器本身，它与真实 `GitActions` / `IsomorphicGit` 的联动在 `gitManager/phoneSync.test.ts`。
- 维护版回归开关：`gitManager/isomorphicGitPushAfterMerge.test.ts` 失败先查 isomorphic-git 补丁（见 `MAINTENANCE.md`）是否仍适用，不要放宽对象数断言；`pullRecovery.test.ts` 失败先看 `IsomorphicGit.pull` 的日志与 `clearPullBlockers`。
- `syncSupervisor.test.ts` 写死了重试节奏、通知次数与「只在 `managing` 时行动」的开关语义，改这些行为要同步改用例，不是放宽断言。

## 5. 什么时候需要下钻

- 改 Git 后端、`GitActions`、auto commit glob、askpass，或手机同步里与后端相关的部分（拉取修复、弱网请求策略、`scopedStatus`、`commitsAhead`）：读 `gitManager/.frac.md`，需要新 fixture 时再读 `helpers/.frac.md`。
- 改 `src/editor/` 的冲突解析、gutter signs、hunk 补丁：读 `editor/.frac.md`（补丁文本改动还要跑 `signs/` 的 git 往返测试）。
- 改 `src/ui/diff/`：读 `ui/.frac.md`；给 `src/ui/` 其他部分补测试，先读 `stubs/.frac.md` 了解空类 stub 的限制。
- 源码新引用 Obsidian API、测试报 `undefined is not a function` 或 `Platform` 分支不对：读 `stubs/.frac.md`。
- 改 `automaticsManager`、`coalesce`、`promiseQueue`、`gitAction`、`syncSupervisor`、`syncProblems`、`autoCommitGlobs` 的源码：直接看本层对应的 `*.test.ts`，它们不依赖子目录。
