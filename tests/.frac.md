# .frac.md — tests

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

整个 Vitest 测试套件的根目录。测试在 Node 环境运行，不启动真实 Obsidian：`vitest.config.ts` 把 `obsidian` 别名到 `tests/stubs/obsidian.ts`、`src` 别名到源码目录，`setup.ts` 在每个测试文件前执行。涉及 Git 行为的用例使用真实临时 git 仓库与 `git http-backend`。
本层直属文件覆盖编排、同步监督与纯逻辑测试及全局配置；其余测试按源码路径镜像放在子目录里。

## 2. 直属文件

**说明与全局设置**
- `README.md`：测试策略文档（命令、配置、stub/helper 用法、设计原则）。纯逻辑写单元测试，Git 工作流用真实临时仓库，stub 保持最小。
- `setup.ts`：全局 setup。按需补 `Array.prototype.last` / `contains`、`String.prototype.contains`、`Math.clamp`；定义 `window` / `activeWindow`、`localStorage` 及最小 `activeDocument` 替身。

**编排与监督器测试**
- `automaticsManager.test.ts`：`AutomaticsManager` 自动 commit-and-sync 防抖与 `autoSyncDelaySeconds` 延迟验证（`vi.mock("obsidian")` 记录 `debounce` 参数）。
- `coalesce.test.ts`：`coalesce(fn)` 并发合并、串行续跑与错误恢复行为。
- `promiseQueue.test.ts`：`PromiseQueue` 异常隔离、队列排空与 `clearPending` / `pendingCount` 语义。
- `gitAction.test.ts`：`runGitAction` 结果三态、`observeError` 抑制弹窗与冲突/取消/错误分派。
- `syncSupervisor.test.ts`：`SyncSupervisor` 综合测试（`vi.useFakeTimers()` + 伪造 `Notice` / `document`）：历史记录、弱网重试与进度快照、`boot-pull` 启动拉取监督、自动同步期间触发手动同步的非阻塞续跑排队、离开/回来、回声过滤与亮屏控制。
- `syncProblems.test.ts`：`classifySyncError` 与 `problemText` 纯函数测试：离线/后台/在线错因分类、HTTP 状态映射、拉取阻挡与冲突文件路径解析、中英文提示与自动重试开关一致性。
- `autoCommitGlobs.test.ts`：`includeGlobScope` 从 include glob 提取起始目录或返回 `undefined`。

## 4. 本层约束 / 约定 / 禁忌

- 仅在 Node 运行：`window` 即 `globalThis`，受 `vi.useFakeTimers()` 控制；依赖 DOM 的测试自行提供局部轻量替身，不污染 `setup.ts`。
- stub 与 helper 刻意保持最小：不模拟完整 Obsidian 客户端渲染，端到端界面验证在真机/模拟器运行。
- 测试同样受 `pnpm run lint` 与 Prettier 格式检查约束。
- 真实环境依赖：本机 `git`（含 `git http-backend`）及 POSIX `sh`；Node / pnpm 要求见根 `AGENTS.md`。
- 注意区分：`gitAction.test.ts` 测 `runGitAction`，`GitActions` 集成流在 `gitManager/`；`syncSupervisor.test.ts` 测监督器状态机，与真实 `IsomorphicGit` 联动在 `gitManager/phoneSync.test.ts`。
- `gitManager/isomorphicGitPushAfterMerge.test.ts` 与 `pullRecovery.test.ts` 为核心回归闸门，不可放宽断言。

## 5. 什么时候需要下钻

- 改 Git 后端、`GitActions`、拉取/冲突救援或弱网请求策略：读 `gitManager/.frac.md` 与 `helpers/.frac.md`。
- 改编辑器或 UI 逻辑测试：读 `editor/.frac.md`、`ui/.frac.md` 及 `stubs/.frac.md`。
- 改编排、队列、监督器或问题分类源码：直接对照本层对应 `*.test.ts`。
