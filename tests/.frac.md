## 1. 本目录是什么

整个 Vitest 测试套件的根目录。测试在 Node 环境运行，不启动真实的 Obsidian：`obsidian` 导入被别名到 `tests/stubs/obsidian.ts`，`src` 别名指向源码目录，`tests/setup.ts` 在每个测试文件前执行，匹配规则是 `tests/**/*.test.ts`，覆盖率用 V8（以上均见 `README.md` 与根目录 `AGENTS.md`）。涉及 Git 行为的用例都用真实的临时 git 仓库。
本层直属文件是几个与 UI、Git 后端都无关的编排类测试（维护版加了同步监督器、错误分类、glob 范围三个），另有套件说明 `README.md` 和全局 setup。其余测试按源码子目录镜像放在子目录里，`helpers/` 与 `stubs/` 是支撑代码而非测试。
维护版（obsidian-git-Maintained）新增的测试在 `gitManager/`、`setting/`，以及本层的 `syncSupervisor.test.ts`、`syncProblems.test.ts`、`autoCommitGlobs.test.ts`，见下文。

## 2. 直属文件

- `README.md`：测试策略的人工文档（命令、runner 配置、stub 与 helper 的用法（含假插件带的 `manifest`）、设计原则、一个尚未实现的可选 E2E 方案）。写新测试前的第一站；其中设计原则：纯逻辑写纯单元测试，Git 工作流用真实临时仓库，不对"价值在 Git 流程本身"的方法 mock `simple-git`，不拉起 Obsidian，stub 保持最小且只供测试，能用 Git 当 oracle 就不要贴合实现细节。
- `setup.ts`：全局 setup（`setupFiles`）。仅在缺失时补 `Array.prototype.last`、`Array.prototype.contains`（维护版加的，`AutomaticsManager.reload` 用 `type.contains(…)`）、`String.prototype.contains`（维护版加的，`SimpleGit` 写 `info/exclude` 时用到）与 `Math.clamp`（并用 `declare global` 补类型）；定义 `globalThis.localStorage = { debug: "-simple-git" }`（一个普通对象，不是 `Storage`）；`window` 与 `activeWindow` 都是返回 `globalThis` 的 getter；`activeDocument` 在 Node 没有 `document` 时回落到一个极简伪造文档（`body.style.setProperty / append / appendChild / classList.contains`、`addEventListener`、`createElement`、`getElementById`、`querySelector` 都是空实现）。
- `automaticsManager.test.ts`：`AutomaticsManager`（`src/automaticsManager`）的自动 commit-and-sync。用 `createFakePlugin()` 加真实 `PromiseQueue` 和 mock 的 `gitActions.commitAndSync`，验证第一次运行期间发生的编辑（模拟 vault 事件调用 `plugin.autoCommitDebouncer`）恰好再提交一次，且旧的 debouncer 不会再触发第三次；debouncer 由用例手动 `.run()` 触发，没有真实计时器（`tests/stubs/obsidian.ts` 的 `debounce` 就是这种手动触发版本）；结尾调用 `manager.unload()`。维护版加了 `describe("AutomaticsManager wait after file edits")`：文件顶部 `vi.mock("obsidian")` 把 `debounce` 包成 `vi.fn(actual.debounce)`（行为仍是手动触发的 stub，只是能记录参数），局部 `createPlugin(settings)` 造插件；两条用例断言传给 `debounce` 的第二个参数——默认是 `autoSaveInterval` 的分钟（`5 * 60_000`），`autoSyncDelaySeconds = 10` 时是 `10_000`，再把它改成 20 并 `manager.reload("commit")` 后最后一次调用变成 `20_000`。
- `coalesce.test.ts`：`coalesce(fn)`（`src/coalesce`）。运行期间的多次调用合并成一次后续运行并共享同一个 promise（`third` 与 `second` 是同一个对象）；上一轮结束后可以重新开始；活动运行失败时后续运行仍会执行。局部辅助 `deferred()`。
- `promiseQueue.test.ts`：`PromiseQueue`（`src/promiseQueue`）。逃逸的任务 rejection 会以 `console.error("Unhandled PromiseQueue task rejection", error)` 记录并继续执行下一个任务（`addTask(task, onFinished)`）。
- `gitAction.test.ts`：`runGitAction(host, action)` 与 `GitActionHost`（`src/gitAction`，注意是单数文件名，和类 `GitActions` 所在的 `src/gitActions` 不同）。结果为 `{ status: "success", value } | { status: "failed" } | { status: "cancelled" }`。
  - `GitConflictError` 先 `updateCachedStatus` 一次，再经 `handleConflict(files)` 只报告一次，不再额外 `displayError`；isomorphic-git 的 `UserCanceledError` 静默返回 `cancelled`。
  - `PushRejectedError("not-fast-forward")` 记日志 `Push rejected:` 并提示先 pull、解决冲突再 push（不建议 force push）；`"tag-exists"` 给出远端标签已存在的提示；其他错误只 `displayError(error)` 一次。
- `syncSupervisor.test.ts`（维护版新增）：`SyncSupervisor`（`src/syncSupervisor`）。`vi.mock("obsidian")` 派生 `Notice` 子类，把每条通知的 `message` / `timeout` 记进 `notices`；`createPlugin(settings)` 手写一个假插件（不是 `createFakePlugin`）：设置默认值、真 `PromiseQueue`、带 `commitsAhead` mock 的 `gitManager`、`gitActions.commitAndSync` mock、内存版 `getSyncLog` / `setSyncLog`、会记下 handler 的 `registerDomEvent`；`beforeEach` 起 `vi.useFakeTimers()` 并用 `Object.defineProperty` 装一个只有 `visibilityState` getter 的假 `document`，`afterEach` 还原（含 `Capacitor` 全局和 `Platform.isMobileApp`）。辅助 `settle()` 把队列里的任务跑完，`failingSync()` 模拟 `GitActions` 对监督器的调用顺序（`syncStarted` → `observeError` → `syncFinished`）。
  - 历史：重启（新建一个 `SyncSupervisor`）后日志条目、`lastSuccessAt`、`lastPushAt` 都还在，`details()` 含开关状态；两个开关都关着时只记录——`observeError` 返回假、没有 `nextRetryAt`、没有通知、不建 ribbon 图标。
  - 弱网模式：失败后按 `RETRY_DELAYS_MS`（15 s、30 s、1 min、2 min、5 min，之后一直 5 min）重试，调用带 `reason: "retry"`，网络错误不弹通知；离线时 `nextRetryAt` 等于 `OFFLINE_FALLBACK_MS`，`online` 事件触发 `reason: "online"` 的同步；问题持续超过 1 分钟后恢复，弹一次「同步恢复正常」。
  - 需要用户处理的问题：连续失败也只弹一条 `timeout` 为 0 的通知，快照是 `attention`、不排定时重试；`other` 错误前 4 次保留上游弹窗、第 5 次转为需要用户处理；冲突交回上游处理（`observeError` 返回假、无通知）。
  - 离开 / 回来：有编辑时离开，立即 `reason: "leave"` 同步（并取消 `autoCommitDebouncer`）；被系统断网记为 `background: "blocked"`、不排定时重试、不弹通知，回来时 `reason: "resume"` 同步并弹一次电池提示；Capacitor 的 `resume` 先于 `visibilitychange`，用例在 `document.visibilityState` 仍是 `hidden` 时调用 `onReturn()`，这之后的同步不算「在后台完成」，而始末都在后台的成功会把 `background` 标为 `allowed`；没东西可传时离开什么都不做；上次会话留下的未上传提交在 `start()` 后触发 `reason: "startup"`；自动化暂停时只有 `manual` 能排进去。
  - 编辑与亮屏：只有自动提交能挑中的编辑算数，`expectWrites` 登记的拉取回声不算（同一路径的下一次事件又算编辑），把文件移出收件箱算编辑；提交开始之后才发生的编辑在 `recordCommit` 后仍保留；亮屏用假的 Capacitor `KeepAwake` 验证：编辑后亮屏、上传成功后放开、没上传时最多亮 `KEEP_AWAKE_MAX_MS`。
- `syncProblems.test.ts`（维护版新增）：`classifySyncError` 与 `problemText`（`src/syncProblems`），纯函数。分类：同一个网络错误在在线 / 后台 / 离线下分别是 `network` / `background-blocked` / `offline`，`raw` 里没有令牌；`NetworkUnavailableError` 的三种 `reason`；HTTP 401 / 403 → `auth`、404 → `not-found`、503 / 429 → `network`；`Cannot pull with uncommitted working tree changes: a, b` 解析出文件列表（用手机上出错的两个长路径）；冲突、推送被拒、`untracked file would be overwritten`、未知错误（`other`，可重试）。文案：12 种 `kind` × 中英文，`title` / `explain` / `action` 都非空；只有 `autoRetry` 为真时才承诺自动重试（中文含「15 秒」，否则指向 `Weak network mode`）。
- `autoCommitGlobs.test.ts`（维护版新增）：`includeGlobScope`（`src/autoCommitGlobs`）。取开头的字面文件夹（`00、手机收件箱/**` → `00、手机收件箱`，`notes/daily/*.md` → `notes/daily`，`inbox/` → `inbox`，`README.md` 原样）；转义过的通配符按字面（`a\*b/**` → `a*b`）；`**/*.md`、混有 `*.md`、`[ab]/**`、空列表都返回 `undefined`。

## 4. 本层约束 / 约定 / 禁忌

- 只在 Node 下运行，没有 DOM：`window` 就是 `globalThis`，`localStorage` 是普通对象，`activeDocument` 的伪造版本几乎什么都不做。依赖真实 DOM 的代码要在用例里提供自己的假对象，而不是扩充 `setup.ts`；`setup.ts` 里的东西对所有测试文件生效，改动会影响整个套件。例：`syncSupervisor.test.ts` 自己用 `Object.defineProperty(globalThis, "document", …)` 装带 `visibilityState` getter 的假 `document`，用后删掉；因为 `window` 就是 `globalThis`，源码里的 `window.setTimeout` 也受 `vi.useFakeTimers()` 控制。
- stub 与 helper 都故意保持最小（README 的原则）：只在测试确实需要时才增加符号或成员，不要把 stub 做成"保真的 Obsidian 运行时"。
- 测试文件同样受 `pnpm run lint` 检查（ESLint 范围含 `tests`，见根 `AGENTS.md`），并遵循仓库的双引号 Prettier 风格；不要夹带无关的格式化。
- 导入路径风格并不统一：本层文件用 `../src/...`，子目录文件用 `../../src/...` 或 `src/...` 别名，helper 用相对路径；移动文件时要同步这些路径。
- 真实环境依赖：Git 工作流测试需要本机 `git`（含 `git http-backend`），askpass 测试需要 POSIX `sh`；Node >= 24、pnpm >= 11（`AGENTS.md`）。
- 命名易混：`tests/gitAction.test.ts` 测 `src/gitAction.ts` 的 `runGitAction`；`GitActions` 类（`commit`、`commitAndSync`）的行为测试在 `tests/gitManager/` 里。监督器同理分两处：本层 `syncSupervisor.test.ts` 用假插件和假计时器测 `SyncSupervisor` 本身，它与真实 `GitActions` / `IsomorphicGit` 的联动在 `gitManager/phoneSync.test.ts`。
- 维护版回归开关：`gitManager/isomorphicGitPushAfterMerge.test.ts` 失败往往意味着 `patches/isomorphic-git@1.44.3.patch` 不再适用或 `isomorphic-git` 版本变了，先查补丁，不要放宽对象数断言。`gitManager/pullRecovery.test.ts` 失败则先看 `IsomorphicGit.pull` 的日志与 `clearPullBlockers`；`syncSupervisor.test.ts` 里写死了重试节奏、通知次数与「只在 `managing` 时行动」的开关语义，改这些行为要同步改用例，而不是放宽断言。

## 5. 什么时候需要下钻

- 新增或修改任何 Git 后端行为、`GitActions`、auto commit glob、askpass：读 `gitManager/.frac.md`，需要新 fixture 时再读 `helpers/.frac.md`。
- 改 `src/editor/` 的冲突解析、gutter signs、hunk 补丁：读 `editor/.frac.md`（补丁文本改动还要跑 `signs/` 的 git 往返测试）。
- 改 `src/ui/diff/` 的视图：读 `ui/.frac.md`；要给 `src/ui/` 其他部分补测试，先读 `stubs/.frac.md` 了解空类 stub 的限制。
- 源码新引用 Obsidian API、测试报 `undefined is not a function` 或 `Platform` 相关分支不对：读 `stubs/.frac.md`。
- 改 `src/automaticsManager.ts`、`src/coalesce.ts`、`src/promiseQueue.ts`、`src/gitAction.ts`、`src/syncSupervisor.ts`、`src/syncProblems.ts`、`src/autoCommitGlobs.ts`（`includeGlobScope`）：直接看本层对应的 `*.test.ts`，它们不依赖子目录（除 `syncSupervisor.test.ts` 约 560 行外都很短）。
- 改手机同步里和 Git 后端相关的部分（拉取被打断的修复、弱网请求策略、`scopedStatus`、`commitsAhead`）：读 `gitManager/.frac.md`。
