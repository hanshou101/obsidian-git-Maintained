# .frac.md — patches

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

pnpm 依赖补丁，维护版新增。由根目录 `pnpm-workspace.yaml` 的 `patchedDependencies` 登记，`pnpm-lock.yaml` 记下补丁哈希；pnpm 每次安装时套用，套不上就报错停止，不会悄悄失效。

## 2. 直属文件

- `isomorphic-git@1.44.3.patch`：对文件名里那个版本的 isomorphic-git npm 包的 unified diff，内容是上游 PR #2458 的 backport，代码里带 `Backport of isomorphic-git PR #2458` 注释标记。
  - 改的位置：两个 hunk，分别在 `index.cjs`（Node 与测试用）和 `index.js`（Vite 打包进 `main.js` 用），都是 `listCommitsAndTags` 的函数体。
  - 效果：推送算「远端缺哪些提交」时也从远端已有的提交往回走，等同 `git rev-list <本地> --not <远端>`；修的是手机合并后推送一路走到根提交、重传整个历史。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 补丁只绑文件名里的那个 isomorphic-git 版本；升级 isomorphic-git 必须同时重做或删除补丁，否则 `pnpm install` 失败。
- 两个 hunk 必须保持同一份逻辑：测试跑 `index.cjs`，插件实际用 `index.js`。
- 不直接改 `node_modules`，也不对构建出的 `main.js` 做字符串替换；改补丁走 `pnpm patch` 编辑、`pnpm patch-commit <目录>` 提交（步骤见 `MAINTENANCE.md`）。
- 退出条件：isomorphic-git 的正式版包含 PR #2458 后，升级依赖，删除补丁和 `patchedDependencies` 条目，保留推送测试并确认它仍通过。

## 5. 什么时候需要下钻

- 改补丁或升级 isomorphic-git 前，读根目录 `MAINTENANCE.md` 的「The isomorphic-git patch」一节，以及推送测试 `tests/gitManager/isomorphicGitPushAfterMerge.test.ts`（没有补丁就失败）。
