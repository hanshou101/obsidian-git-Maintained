## 1. 本目录是什么

pnpm 依赖补丁。由根目录 `pnpm-workspace.yaml` 的 `patchedDependencies` 登记，`pnpm-lock.yaml` 记下补丁哈希；pnpm 每次安装时套用，套不上就报错停止，不会悄悄失效。

## 2. 直属文件

- `isomorphic-git@1.44.3.patch`：对 npm 上发布的 isomorphic-git 1.44.3 的 unified diff，两个 hunk，分别改 `index.cjs`（Node 与测试用）和 `index.js`（Vite 打包进 `main.js` 用）里同一个 `listCommitsAndTags` 函数体，内容是上游 isomorphic-git PR #2458：推送算「远端缺哪些提交」时，同时从远端广播的提交往回走、标为 uninteresting，按提交时间从新到旧推进，只剩远端已有的提交时停止，等同 `git rev-list <本地> --not <远端>`。修的是手机合并之后推送一路走到根提交、重传整个历史的问题。代码里有 `Backport of isomorphic-git PR #2458 (obsidian-git-Maintained)` 注释标记。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 补丁只绑 isomorphic-git 1.44.3；升级 isomorphic-git 必须同时重做或删除补丁，否则 `pnpm install` 失败。
- 两个 hunk 必须保持同一份逻辑：测试跑 `index.cjs`，插件实际用 `index.js`。
- 不直接改 `node_modules`，也不对构建出的 `main.js` 做字符串替换；改补丁用 `pnpm patch isomorphic-git@1.44.3` 编辑后 `pnpm patch-commit <目录>`。
- 退出条件：isomorphic-git 正式版包含 PR #2458 后，升级依赖、删除补丁和 `patchedDependencies` 条目，保留推送测试并确认它仍通过。

## 5. 什么时候需要下钻

- 改补丁或升级 isomorphic-git 前，读根目录 `MAINTENANCE.md` 的「The isomorphic-git patch」一节，以及 `tests/gitManager/.frac.md` 里推送测试的说明。
