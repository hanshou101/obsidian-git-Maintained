## 1. 本目录是什么

插件的 Git 能力层：`gitManager.ts` 定义抽象契约 `GitManager`，两个互不相通的后端实现它。
- 桌面：`simpleGit.ts` 的 `SimpleGit`，用 `simple-git` 驱动本机 `git`；认证走 `askpassServer.ts`。
- 移动 / 无本机 git：`isomorphicGit.ts` 的 `IsomorphicGit`，用 `isomorphic-git`，文件系统由 `myAdapter.ts` 的 `MyAdapter` 垫在 Obsidian Vault / DataAdapter 之上，HTTP 走 Obsidian `requestUrl`（维护版：经 `networkPolicy.ts` 的 `sendRequest` 发出，弱网模式关着时它就是直接调 `requestUrl`）。
选哪个后端、何时 new / `unload()` 由 `src/main.ts` 决定（本目录只读 `plugin.settings`、`plugin.localStorage`、`plugin.gitServerPassword`、`plugin.statusBar`、`plugin.setPluginState`；维护版的 `IsomorphicGit` 另外用到可选的 `plugin.syncSupervisor?.`：读 `inBackground`，调 `expectWrites` / `recordPullRecovery`）。调用方是 `src/gitActions.ts`、命令、`src/ui/**`、维护版的 `src/syncSupervisor.ts`（调 `commitsAhead`），以及只能在 `SimpleGit` 上工作的 `src/editor/lineAuthor`、`src/editor/signs`。
路径约定（AGENTS.md）：对外一律用 vault 相对路径；仓库相对路径只在本目录内部流转，`getRelativeRepoPath` / `getRelativeVaultPath` 负责转换，`FileStatusResult` 同时带 `path`（仓库相对）和 `vaultPath`。

  - 同步：`pull` 先拒绝「合并进行中」，再（维护版）`recoverInterruptedPull()`，然后用 `git.merge`（`noUpdateBranch`、`abortOnConflict`，`mergeStrategy !== "none"` 时挂 diff3 的 `mergeDriver`，只支持 ours / theirs）；冲突时先（维护版）`clearPullBlockers`，再 `ensureCleanPullWorktree` / `ensureNoIncomingFileCollisions`、登记 `expectWrites`，然后物化冲突，并 `writeMergeState`（`ORIG_HEAD`、`MERGE_MSG`、`MERGE_MODE`、`MERGE_HEAD`，最后写 `MERGE_HEAD`）；没有冲突时顺序是 `clearPullBlockers`（限定在变更文件）→ `ensureNoIncomingFileCollisions` → `ensureCleanPullWorktree` → `writePullJournal` → `expectWrites` → 只 `checkout` 变更文件 → `writeRef` 移动分支 → `clearPullJournal`。**不读取 `syncMethod` / `rebaseAutoStash`，永远是 merge**。`push` / `getUnpushedCommits`（返回的是变化文件数）基于 `branchInfo()`（由 `branch.<name>.remote|merge` 配置推出 tracking）。
  - 拉取被打断的修复（维护版，AME-1119）。手机上 Obsidian 在 `git.checkout` 写文件的中途被关掉或被系统停住时，工作区里留着一半新文件而索引和分支还是旧的，这些文件之后看起来像本地改动，每次拉取都被 `ensureCleanPullWorktree` 拦下。
    - 拉取日志 `<gitdir>/git-maintained-pull.json`（默认 `.git/git-maintained-pull.json`，路径来自 `getMergeStatePath`，用 `vault.adapter` 直接读写，不经 `MyAdapter`）：`{ version: 1, branch, from, to, paths, startedAt }`。`pull()` 在 `checkout` 之前写，`writeRef` 移动分支之后删；读不出来或字段不对的日志直接丢掉；`paths` 目前只用来校验格式，恢复时重新用 `getFileChangesCount(from, to)` 求文件。
    - `recoverInterruptedPull()`（覆写契约里的默认空实现；除 `pull()` 开头外，`GitActions.performCommit` 开头也调，失败只记日志）：没有日志返回 `undefined`；当前分支不是日志里的 `branch`、HEAD 不是 `from`、或 `to` 提交不存在，就当作已完成或被别的操作超越，只删日志。否则对 `from→to` 的变更文件做 `clearPullBlockers({ restore: false })`（接下来的强制 checkout 本来就会重写它们），仍有 `blocked` 的就抛 `Cannot pull with uncommitted working tree changes: …`；然后 `git.checkout({ ref: to, noUpdateHead: true, force: true, filepaths })`、`writeRef` 把分支推到 `to`、删日志，返回 `{ resumed: true, … }` 并交给 `plugin.syncSupervisor?.recordPullRecovery`。
    - `clearPullBlockers({ from, theirs, target, paths?, incoming?, restore? })`：候选 = `statusMatrix(ref: from)` 里工作区或暂存区和 `from` 不同的文件，加上拉取新增、本地已存在但被忽略（statusMatrix 里没有）的文件。`knownVersions` 对每个候选算出它在 `from`、`target`、`theirs` 以及拉取带来的每个提交（`commitsOnlyIn([theirs], [from], KNOWN_VERSION_COMMITS)`，300 个）里的 blob id（`null` = 不存在）。本地版本（读工作区文件算 `hashBlob`；已删除算 `null`；只有暂存区不同的按 `from` 里的版本算）等于其中任何一个，就不是本地工作，记入 `restored`；否则 `rescueLocalVersion` 抄进救援文件夹，记入 `rescued`；两者都不成记入 `blocked`，留给后面原有的检查报错。`restore`（默认真）时 `restoreToCommit(from, handled, known)` 把这些文件连同索引放回 `from` 的版本（`from` 里没有的删文件并 `git.remove`）。`reportPullBlockers` 把 `restored` / `rescued` 以 `resumed: false` 交给 `recordPullRecovery`。
    - `rescueLocalVersion(path, bytes)`：`settings.rescueFolder` 规范化后为空返回 `undefined`（同上游：拉取照旧被挡住）；本地已删除返回 `""`；否则写到 `<救援文件夹>/<YYYY-MM-DD HH-mm-ss>/<仓库相对路径>`，用 `this.fs.mkdir` 逐级建目录（`MyAdapter.mkdir` 对非隐藏路径调 `vault.createFolder`）再 `writeFile`。
  - `commitsAhead()`（覆写契约默认值）：用 `branchInfo()`；没有当前分支或 tracking、tracking ref 解析不出都返回 `undefined`，本地与远端指向同一提交返回 0，否则 `commitsOnlyIn([local], [remote], 2000)`，没走完（`complete` 为假）返回 `undefined`。这是提交数，和返回「变化文件数」的 `getUnpushedCommits` 不同。私有 `commitsOnlyIn(include, exclude, limit)` 等价 `git rev-list <include> ^<exclude>`：两侧按提交时间新到旧一起走，只剩被排除方的提交后再多走几步（`slop = 5`，和 git 一样防提交时间错乱），超过 `limit` 个提交就停并返回 `complete: false`；`knownVersions` 也用它列出拉取带来的提交。
  - 其余：tree walk 工具（`getFileChangesCount`、`walkDifference`、`getStagedFiles`、`getUnstagedFiles`、私有 `typedWalk`），`getDiffString`（用 `diff` 包的 `createPatch`），`show`（`readBlob`，不支持空 hash），进度通知 `showNotice`（受 `settings.disablePopups` 控制），`checkAuthorInfo`。
- `networkPolicy.ts`（维护版新增）：移动端 HTTP 请求的弱网策略，只 import `obsidian` 的类型，不依赖 `IsomorphicGit`。动机（文件头注释）：Obsidian 的 `requestUrl` 没有超时，Android 上无网或后台被系统断网时请求能挂几分钟（注释里的实测：飞行模式下 149 s 才失败），后面的 `promiseQueue` 全被堵住。
  - 导出：`NetworkEnvironment`（`request` / `weakNetworkMode()` / `isOnline()` / `isHidden()` / `sleep`，方便测试注入）、`NetworkResponse`、`NetworkUnavailableError`（`reason`: `offline` | `timeout` | `hidden-timeout`；消息里的 URL 经 `redactUrl` 去掉凭据与 query）、`REQUEST_TIMEOUT_MS`（发现请求 `GET` / `HEAD` 30 s、fetch / push 的 `POST` 120 s、在后台任何请求 12 s）、`READ_RETRY_DELAYS_MS`（1.5 s、4 s）、`isNetworkFailureMessage(message)`（按 Android / 浏览器 / Node 的网络错误文案做正则匹配，`src/syncProblems.ts` 也用它）、`redactUrl`、`sendRequest(env, param)`。
  - `sendRequest`：`weakNetworkMode()` 为假时就是 `env.request(param)`，和上游一致，不加超时也不重试。为真时：`isOnline()` 为假直接抛 `NetworkUnavailableError("offline")`、不发请求；否则用 `Promise.race` 套超时（在后台用 12 s），超时抛 `timeout` / `hidden-timeout`；只读请求（`GET` / `HEAD`，或 URL 以 `/git-upload-pack` 结尾的 fetch）最多试 3 次，间隔取 `READ_RETRY_DELAYS_MS`，重试条件是 `NetworkUnavailableError`、能被 `isNetworkFailureMessage` 认出的错误或状态码 502 / 503 / 504（次数用完后最后一个 5xx 响应原样交给 isomorphic-git）；推送（`git-receive-pack`）只试 1 次，整个同步交给监督器重试；已在后台或设备离线时不再重试；不是网络错误的异常立刻原样抛出。超时后那次请求在平台里继续跑，迟到的结果被忽略（文件头注释的论证：迟到的 fetch 响应被丢弃；迟到的 push 要么已经移动远端分支、下次 push 发现 up-to-date，要么被当作过期拒绝）。
- `myAdapter.ts`：`MyAdapter`，给 isomorphic-git 的 `fs.promises` 形状（`readFile` / `writeFile` / `readdir` / `mkdir` / `rmdir` / `stat` / `lstat` / `unlink`；`readlink` / `symlink` 直接 reject）。非隐藏路径优先走 Vault API（`vault.read/modify/create/delete`，保持 Obsidian 缓存一致），隐藏路径（任一路径分量以 `.` 开头，或以 `gitDir` 开头）走底层 `adapter`。`.git/index` 被缓存在内存（`index` / `indexctime` / `indexmtime`），读写都不碰磁盘，直到 `saveAndClear()`；`settings.basePath` 变化时丢弃缓存。`stat` 补 `STABLE_STATS`（uid/gid/ino/dev 为 0，否则 index 的 stat 缓存永远不命中），缺文件抛 `code = "ENOENT"` 的 `FileNotFoundError`。
- `askpassServer.ts`：`AskpassServer`（仅桌面，`node:http` / `node:crypto`）。监听 `127.0.0.1` 随机端口，持有 32 字节随机 token；只接受 `POST /askpass`、无 `Origin` 头、请求体 ≤ 16 KiB、`token\nprompt` 格式且 `timingSafeEqual` 校验通过；提示串行排队，弹 `GeneralModal`（提示里含 `Username for` 才明文，其余遮蔽），回 200 + 答案 / 409（取消）/ 403 / 413 / 503；`stop()` 关弹窗并 503 所有未完成请求。只能 `start()` 一次。

## 4. 本层约束 / 约定 / 禁忌

- 新增 Git 操作：先改 `GitManager` 的抽象签名，再同时实现 `SimpleGit` 与 `IsomorphicGit`；会改变插件状态的操作用 `withGitOperation` 包住，失败路径也要走到 `finally`。只有一个后端支持的功能（上面列的 blame / hash / submodule / patch / squash 等）不要塞进契约，调用方要 `instanceof SimpleGit` 守卫（line author、signs 就是这么做的）。
- 桌面 / 移动差异清单：`obsidian-git:head-change` 只有 `SimpleGit` 的 `commitAll` / `commit` / `pull` / `squashAllUnpushedCommits` 会触发；`limitToVault` 与 `*OutsideVault` 只在 `SimpleGit`（移动端恒 0）；`syncMethod` / `rebaseAutoStash` 只在 `SimpleGit`；`IsomorphicGit.branchIsMerged` 永远返回 `true`，`deleteBranch` 无视 `force`，`log` 忽略文件过滤参数，`getConfig` 忽略 `scope`，`checkRequirements` 不会返回 `"missing-git"`；`getUnpushedCommits` 在两端返回的都是「变化的文件数」而非提交数。维护版另有：`recoverInterruptedPull`、`scopedStatus`、弱网请求策略只在 `IsomorphicGit`（`SimpleGit` 用契约里的默认空实现），`commitsAhead` 两个后端都实现、返回提交数。
- 自动提交 glob 的两端匹配器不同：`SimpleGit` 交给 Git pathspec（`:(glob)` / `:(exclude,glob)`），`IsomorphicGit` 用 `autoCommitGlobs` 里的 JS 选择器。改 glob 语义、转义或大小写规则时必须双端验证。`SimpleGit.commitAll` 在 `include` 模式且调用方带了 `unstagedFiles` 时直接信任传入的 `selection`，应传 `selectAutoCommitFiles` 返回的已收窄 selection。
- 维护版新增开关 `manualCommitUsesAutoCommitGlobs`（默认关，设置项见 `src/setting/.frac.md`）在本层不需要新分支：两个后端的 `commitAll` 本来就接受 `selection`、只暂存被选中的文件、然后提交整个 index，所以用户手动暂存的文件照样进入提交。是否把 selection 传给手动提交（Commit all changes、commit-and-sync 等）由 `src/gitActions.ts` 决定。`gitManager.ts` 里 `selection` 字段的注释写的是「applied only to automatic staging」，按代码行为理解是只作用于 `commitAll` 自己执行的那一步暂存，注释本身没有限定调用场景。
- 手机同步（AME-1119）的新行为默认都等于上游：弱网模式关着时 `sendRequest` 就是 `requestUrl`；没有拉取日志时 `recoverInterruptedPull` 什么都不做；`rescueFolder` 为空时 `rescueLocalVersion` 返回 `undefined`。唯一不受设置控制的是 `clearPullBlockers` 把「内容等于历史里某个版本」的本地文件复位：这是 bug 修复（修被打断的拉取留下的半成品），不是可选行为；只有把「不在任何提交里的本地改动」抄进救援文件夹才需要 `rescueFolder`，没设时这些文件仍由原有的 `ensureCleanPullWorktree` / `ensureNoIncomingFileCollisions` 拦下并报错。`knownVersions` 只看拉取带来的前 300 个提交，更早的历史版本不会被认作已知版本（`commitsOnlyIn` 超限时返回的是已找到的部分）。
- 拉取日志的顺序是契约：`writePullJournal` 在所有检查之后、`git.checkout` 之前，`clearPullJournal` 在 `writeRef` 移动分支之后；`recoverInterruptedPull` 只在分支仍停在 `from` 时补做，否则只清日志，剩下的交给下一次拉取的 `clearPullBlockers`。新增会写工作区的步骤，要在写之前调 `plugin.syncSupervisor?.expectWrites(…)`，让监督器把这些写入认作「回声」而不是用户编辑。
- 弱网请求层只作用于 `IsomorphicGit.getRepo().http`。`isHidden()` 来自监督器的 `inBackground`，它跟随 Capacitor 的 `pause` / `resume`，二者先于 `visibilitychange` 到达，所以后台判断比 `document.visibilityState` 早。`REQUEST_TIMEOUT_MS` 的数字（30 s / 2 min / 12 s）也写在设置页 Phone sync 的说明和 `README.md` 里，改常量要一起改。
- `MyAdapter` 的 index 内存缓存与 `wrapFS` 是一对：绕过 `wrapFS` 直接调 `git.*` 会让 index 只改在内存里。`MyAdapter.getIndexPath()` 在运行时通过 `plugin.gitManager.getRelativeVaultPath` 取路径，依赖 `plugin.gitManager` 已指向 `IsomorphicGit`。
- 已知的不对称 / 疑点：`IsomorphicGit.updateBasePath` 写的是 `getRepo()` 返回的临时对象，实际是空操作（`dir` 每次从 `settings.basePath` 读，所以仍然生效）；`IsomorphicGit.log` 的 `date` 用 `new Date(committer.timestamp)`，而 `getLastCommitTime` 对同一个字段乘了 1000，[推测] `log` 把秒当毫秒用了。
- 错误语义：冲突统一抛 `GitConflictError`（带冲突文件列表），断网抛 `NoNetworkError`（`SimpleGit.convertErrors` 靠 stderr 文案匹配）；不要在本层吞掉认证失败、冲突或取消。askpass 路径上取消弹窗以 409 返回，脚本侧如何处理见 `src/constants` 的 `ASK_PASS_SCRIPT`。
- 凭据 / 路径类配置（git 路径、PATH、环境变量、用户名、主机名、服务器密码）读自 `plugin.localStorage` 与 `plugin.gitServerPassword`，与 `plugin.settings` 是不同的对象，存储方式见 `src/setting/.frac.md`。

## 5. 什么时候需要下钻

- 改某个 Git 行为：先读 `gitManager.ts` 的契约，再对照两个实现（桌面看 `simpleGit.ts`，移动看 `isomorphicGit.ts` + `myAdapter.ts`）。
- 改认证 / 凭据弹窗：桌面读 `askpassServer.ts` 与 `simpleGit.ts` 的 `setGitInstance` / `startAskpass`；移动读 `isomorphicGit.ts` 的 `getRepo()`；存储位置读 `src/setting/.frac.md`。
- 改提交范围（auto-commit globs、`manualCommitUsesAutoCommitGlobs`）：本层看两个 `commitAll` / `selectAutoCommitFiles`，规则与入口在 `src/autoCommitGlobs.ts` 和 `src/gitActions.ts`，设置项在 `src/setting/settings.ts`。
- 改 blame / hunk 数据来源：`SimpleGit.blame` / `show` / `hashObject`，消费方见 `src/editor/lineAuthor/.frac.md`、`src/editor/signs/.frac.md`。
- 改结果结构（`Status`、`PullResult`、`PushResult`、`BlameCommit`、`GitConflictError` 等）：它们定义在 `src/types`，同时影响两个后端与 UI。
- 改弱网超时 / 重试 / 离线快速失败：`networkPolicy.ts`（用 `NetworkEnvironment` 注入，测试见 `tests/gitManager/.frac.md` 的 `networkPolicy.test.ts`）；接线在 `isomorphicGit.ts` 的 `network` 与 `getRepo().http`，开关与后台判断来自 `src/syncSupervisor.ts`。
- 改拉取被打断的修复 / 救援文件夹：`isomorphicGit.ts` 的 `pull`、`recoverInterruptedPull`、`clearPullBlockers`、`knownVersions`、`restoreToCommit`、`rescueLocalVersion`；测试在 `tests/gitManager/pullRecovery.test.ts`；报告端是 `src/syncSupervisor.ts` 的 `recordPullRecovery`，用户看到的文案在 `src/syncProblems.ts`。
