## 1. 本目录是什么

插件的 Git 能力层：`gitManager.ts` 定义抽象契约 `GitManager`，两个互不相通的后端实现它。
- 桌面：`simpleGit.ts` 的 `SimpleGit`，用 `simple-git` 驱动本机 `git`；认证走 `askpassServer.ts`。
- 移动 / 无本机 git：`isomorphicGit.ts` 的 `IsomorphicGit`，用 `isomorphic-git`，文件系统由 `myAdapter.ts` 的 `MyAdapter` 垫在 Obsidian Vault / DataAdapter 之上，HTTP 走 Obsidian `requestUrl`。
选哪个后端、何时 new / `unload()` 由 `src/main.ts` 决定（本目录只读 `plugin.settings`、`plugin.localStorage`、`plugin.gitServerPassword`、`plugin.statusBar`、`plugin.setPluginState`）。调用方是 `src/gitActions.ts`、命令、`src/ui/**`，以及只能在 `SimpleGit` 上工作的 `src/editor/lineAuthor`、`src/editor/signs`。
路径约定（AGENTS.md）：对外一律用 vault 相对路径；仓库相对路径只在本目录内部流转，`getRelativeRepoPath` / `getRelativeVaultPath` 负责转换，`FileStatusResult` 同时带 `path`（仓库相对）和 `vaultPath`。

## 2. 直属文件

- `gitManager.ts`：抽象类 `GitManager`（构造参数 `plugin`，字段 `plugin`、`app`）。
  - 契约：`status` / `commitAll` / `commit` / `stage*` / `unstage*` / `discard*` / `getUntrackedPaths` / `pull` / `push` / `getUnpushedCommits` / `canPush` / `checkRequirements` / 分支（`branchInfo`、`checkout`、`createBranch`、`deleteBranch`、`branchIsMerged`）/ `init` / `clone` / 配置 / remote / `fetch` / `log` / `getDiffString` / `show` / `getLastCommitTime` / `updateGitPath` / `updateBasePath`，以及自动提交 glob 相关的 `selectAutoCommitFiles(status, selection)` 与 `commitAll({ message, status?, unstagedFiles?, selection?, amend? })`（类型来自 `../autoCommitGlobs`）。
  - 共享实现：`withGitOperation(op, fn)`（设置 `plugin.setPluginState({ operation })`，`finally` 里清进度条并恢复 `GitOperation.idle`）、`getRelativeVaultPath` / `getRelativeRepoPath`（默认按 `settings.basePath` 字符串拼接，`SimpleGit` 覆写为绝对路径换算）、`getVaultPathspec()`（默认 `undefined`）与 `isPathInsideVault`、`unload()` 钩子、`getTreeStructure(children, root)` + 私有 `simplify`（建 trie、目录在前、单子目录链合并成 `a/b/c`）、`getStagedForMessage()`、`formatCommitMessage(template)`（`{{numFiles}}` `{{hostname}}` `{{files}}` `{{date}}`，`listChangedFilesInMessageBody` 追加文件列表；少于 100 个文件才列出；每个占位符只替换第一处）。
- `simpleGit.ts`：`SimpleGit`（桌面）与导出的 `zeroCommit`（hash `"000000"`，无 author；line author 把它当「未提交」）、私有的 `parseBlame` 等 blame porcelain 解析。
  - `setGitInstance(ignoreError?)`：算 `basePath`（`settings.basePath`）和 `absoluteRepoPath`（`rev-parse --show-cdup`），合并 `localStorage` 里的 PATH / 环境变量 / `settings.gitDir`（`GIT_DIR` + `GIT_WORK_TREE`）/ git 路径（Windows 有默认路径回退），配 `simple-git`（`core.quotepath=off`，`unsafe` 开关全开，进度回调到 `statusBar.displayProgress`），再启动 askpass。`updateGitPath` / `updateBasePath` / `clone` 都会重建实例；`unload()` 置 `unloaded` 并停 askpass。
  - 认证：用户没有自带 `SSH_ASKPASS` 时，把 `ASK_PASS_SCRIPT` 写到插件目录、追加进仓库 `info/exclude`、起 `AskpassServer`，设置 `SSH_ASKPASS` / `GIT_ASKPASS`（已有则不覆盖）/ `SSH_ASKPASS_REQUIRE=force` / `OBSIDIAN_GIT_ASKPASS_PORT` / `OBSIDIAN_GIT_ASKPASS_TOKEN`；总会设 `OBSIDIAN_GIT=1`。
  - 限定 vault：`getVaultPathspec()` 在 `settings.limitToVault` 且 vault 是仓库的严格子目录时返回仓库相对目录，`status` / `stageAll` / `unstageAll` / `discardAll` / `getUntrackedPaths` / `pull` 的文件列表 / `commitAll`（无 selection 时）都据此加 pathspec；`status()` 还会返回 `stagedOutsideVault`、`conflictedOutsideVault`。
  - 提交：`commitAll` 先（`updateSubmodules` 时）提交各子模块，再按 selection 暂存：`include` 模式在调用方没传 `unstagedFiles` 时先 `selectAutoCommitFiles` 收窄（`git add` 不接受零匹配的 pathspec），再 `git add -A -- :(glob)…`；`exclude` 模式 `git add -A -- . :(exclude,glob)…`；无 selection 则 `git add -A [-- vaultPath]`；之后 `git commit`（整个 index，所以用户手动暂存的文件照样被提交）并触发 `workspace.trigger("obsidian-git:head-change")`。`selectAutoCommitFiles` 用 `git status --untracked-files=all` 加 `:(glob)` / `:(exclude,glob)` pathspec 让 Git 自己匹配。
  - 同步：`pull`（可选子模块更新 → `fetch` → 按 `syncMethod` 做 merge / rebase（`mergeStrategy`、`rebaseAutoStash`）/ reset；冲突经 `throwConflictError` 变成 `GitConflictError`；网络错误经 `convertErrors` 变成 `NoNetworkError`；结果 `up-to-date` / `updated` / `skipped`）、`push`（`getPushTarget` 用 `%(push)` 取真实推送目标；结果 `blocked` / `skipped` / `up-to-date` / `pushed`）、`canPush`、`getUnpushedCommits`、仅此后端有的 `squashAllUnpushedCommits()`（对 push target 做 soft reset 再 `commit -C oldHead`，有合并提交 / 暂存区非空 / 不足 2 个提交时不动）。
  - 仅此后端的能力（不在契约里）：`blame`（`git blame --porcelain`，支持 `-w` 与 `-C` 追踪移动）、`isTracked`、`hashObject`、`submoduleAwareHeadRevisonInContainingDirectory`（方法名拼写如此）、`getSubmodulePaths`、`getSubmoduleOfFile`、`applyPatch(patch)`（把补丁写到插件目录再 `git apply --cached --unidiff-zero`，失败时不清理补丁文件）、`rawCommand`、`diff`、`isFileTrackedByLFS`。`show(hash, file)` 用 `git show --textconv hash:path`，hash 为 `""` 时即暂存区版本（signs 依赖这点）。
- `isomorphicGit.ts`：`IsomorphicGit`（移动端）。`getRepo()` 每次返回新对象：`fs: MyAdapter`、`dir: settings.basePath || "/"`、可选 `gitdir`、`onAuth`（`localStorage` 用户名 + `gitServerPassword`）、`onAuthFailure`（用 `GeneralModal` 询问并保存新凭据）、基于 `requestUrl` 的 `http`（整包缓冲、`Accept-Encoding: identity`、遇到 gzip 魔数再手动 inflate）。
  - **所有改动 index 的 isomorphic-git 调用必须经 `wrapFS(promise)`**，它在 `finally` 语义下调用 `MyAdapter.saveAndClear()` 把内存里的 index 落盘。
  - `status` 用 `statusMatrix` + `status_mapping`（HEAD/WORKDIR/STAGE 三元组映射成类 `git status --short` 代码，未知组合会抛错），冲突来自 `GitIndexManager` 的 `unmergedPaths`；`stagedOutsideVault` 恒为 0。
  - 提交：`commitAll` = `checkAuthorInfo()`（`user.name` / `user.email` 必须已设）→ `stageAll` → `commit`；`stageAll` 对 `unstagedFiles ?? status.changed ?? getUnstagedFiles()` 用 `createAutoCommitPathSelector(selection)`（JS 匹配器，不是 Git pathspec）过滤，逐个 `git.add` / `git.remove`；`commit` 若存在 `.git/MERGE_HEAD` 则以 `[HEAD, ...MERGE_HEAD]` 为 parent，提交后 `clearMergeState()`。
  - 同步：`pull` 先拒绝「合并进行中」，用 `git.merge`（`noUpdateBranch`、`abortOnConflict`，`mergeStrategy !== "none"` 时挂 diff3 的 `mergeDriver`，只支持 ours / theirs）；冲突时先 `ensureCleanPullWorktree` / `ensureNoIncomingFileCollisions` 再物化冲突，并 `writeMergeState`（`ORIG_HEAD`、`MERGE_MSG`、`MERGE_MODE`、`MERGE_HEAD`，最后写 `MERGE_HEAD`）；成功后只 `checkout` 变更文件再 `writeRef` 移动分支。**不读取 `syncMethod` / `rebaseAutoStash`，永远是 merge**。`push` / `getUnpushedCommits`（返回的是变化文件数）基于 `branchInfo()`（由 `branch.<name>.remote|merge` 配置推出 tracking）。
  - 其余：tree walk 工具（`getFileChangesCount`、`walkDifference`、`getStagedFiles`、`getUnstagedFiles`、私有 `typedWalk`），`getDiffString`（用 `diff` 包的 `createPatch`），`show`（`readBlob`，不支持空 hash），进度通知 `showNotice`（受 `settings.disablePopups` 控制），`checkAuthorInfo`。
- `myAdapter.ts`：`MyAdapter`，给 isomorphic-git 的 `fs.promises` 形状（`readFile` / `writeFile` / `readdir` / `mkdir` / `rmdir` / `stat` / `lstat` / `unlink`；`readlink` / `symlink` 直接 reject）。非隐藏路径优先走 Vault API（`vault.read/modify/create/delete`，保持 Obsidian 缓存一致），隐藏路径（任一路径分量以 `.` 开头，或以 `gitDir` 开头）走底层 `adapter`。`.git/index` 被缓存在内存（`index` / `indexctime` / `indexmtime`），读写都不碰磁盘，直到 `saveAndClear()`；`settings.basePath` 变化时丢弃缓存。`stat` 补 `STABLE_STATS`（uid/gid/ino/dev 为 0，否则 index 的 stat 缓存永远不命中），缺文件抛 `code = "ENOENT"` 的 `FileNotFoundError`。
- `askpassServer.ts`：`AskpassServer`（仅桌面，`node:http` / `node:crypto`）。监听 `127.0.0.1` 随机端口，持有 32 字节随机 token；只接受 `POST /askpass`、无 `Origin` 头、请求体 ≤ 16 KiB、`token\nprompt` 格式且 `timingSafeEqual` 校验通过；提示串行排队，弹 `GeneralModal`（提示里含 `Username for` 才明文，其余遮蔽），回 200 + 答案 / 409（取消）/ 403 / 413 / 503；`stop()` 关弹窗并 503 所有未完成请求。只能 `start()` 一次。

## 4. 本层约束 / 约定 / 禁忌

- 新增 Git 操作：先改 `GitManager` 的抽象签名，再同时实现 `SimpleGit` 与 `IsomorphicGit`；会改变插件状态的操作用 `withGitOperation` 包住，失败路径也要走到 `finally`。只有一个后端支持的功能（上面列的 blame / hash / submodule / patch / squash 等）不要塞进契约，调用方要 `instanceof SimpleGit` 守卫（line author、signs 就是这么做的）。
- 桌面 / 移动差异清单：`obsidian-git:head-change` 只有 `SimpleGit` 的 `commitAll` / `commit` / `pull` / `squashAllUnpushedCommits` 会触发；`limitToVault` 与 `*OutsideVault` 只在 `SimpleGit`（移动端恒 0）；`syncMethod` / `rebaseAutoStash` 只在 `SimpleGit`；`IsomorphicGit.branchIsMerged` 永远返回 `true`，`deleteBranch` 无视 `force`，`log` 忽略文件过滤参数，`getConfig` 忽略 `scope`，`checkRequirements` 不会返回 `"missing-git"`；`getUnpushedCommits` 在两端返回的都是「变化的文件数」而非提交数。
- 自动提交 glob 的两端匹配器不同：`SimpleGit` 交给 Git pathspec（`:(glob)` / `:(exclude,glob)`），`IsomorphicGit` 用 `autoCommitGlobs` 里的 JS 选择器。改 glob 语义、转义或大小写规则时必须双端验证。`SimpleGit.commitAll` 在 `include` 模式且调用方带了 `unstagedFiles` 时直接信任传入的 `selection`，应传 `selectAutoCommitFiles` 返回的已收窄 selection。
- 维护版新增开关 `manualCommitUsesAutoCommitGlobs`（默认关，设置项见 `src/setting/.frac.md`）在本层不需要新分支：两个后端的 `commitAll` 本来就接受 `selection`、只暂存被选中的文件、然后提交整个 index，所以用户手动暂存的文件照样进入提交。是否把 selection 传给手动提交（Commit all changes、commit-and-sync 等）由 `src/gitActions.ts` 决定。`gitManager.ts` 里 `selection` 字段的注释写的是「applied only to automatic staging」，按代码行为理解是只作用于 `commitAll` 自己执行的那一步暂存，注释本身没有限定调用场景。
- `MyAdapter` 的 index 内存缓存与 `wrapFS` 是一对：绕过 `wrapFS` 直接调 `git.*` 会让 index 只改在内存里。`MyAdapter.getIndexPath()` 在运行时通过 `plugin.gitManager.getRelativeVaultPath` 取路径，依赖 `plugin.gitManager` 已指向 `IsomorphicGit`。
- 已知的不对称 / 疑点：`IsomorphicGit.updateBasePath` 写的是 `getRepo()` 返回的临时对象，实际是空操作（`dir` 每次从 `settings.basePath` 读，所以仍然生效）；`IsomorphicGit.log` 的 `date` 用 `new Date(committer.timestamp)`，而 `getLastCommitTime` 对同一个字段乘了 1000，[推测] `log` 把秒当毫秒用了。
- 错误语义：冲突统一抛 `GitConflictError`（带冲突文件列表），断网抛 `NoNetworkError`（`SimpleGit.convertErrors` 靠 stderr 文案匹配）；不要在本层吞掉认证失败、冲突或取消。askpass 路径上取消弹窗以 409 返回，脚本侧如何处理见 `src/constants` 的 `ASK_PASS_SCRIPT`。
- 凭据 / 路径类配置（git 路径、PATH、环境变量、用户名、主机名、服务器密码）读自 `plugin.localStorage` 与 `plugin.gitServerPassword`，与 `plugin.settings` 是不同的对象，存储方式见 `src/setting/.frac.md`。

## 5. 什么时候需要下钻

- 改某个 Git 行为：先读 `gitManager.ts` 的契约，再对照两个实现（桌面看 `simpleGit.ts`，移动看 `isomorphicGit.ts` + `myAdapter.ts`）。
- 改认证 / 凭据弹窗：桌面读 `askpassServer.ts` 与 `simpleGit.ts` 的 `setGitInstance` / `startAskpass`；移动读 `isomorphicGit.ts` 的 `getRepo()`；存储位置读 `src/setting/.frac.md`。
- 改提交范围（auto-commit globs、`manualCommitUsesAutoCommitGlobs`）：本层看两个 `commitAll` / `selectAutoCommitFiles`，规则与入口在 `src/autoCommitGlobs.ts` 和 `src/gitActions.ts`，设置项在 `src/setting/settings.ts`。
- 改 blame / hunk 数据来源：`SimpleGit.blame` / `show` / `hashObject`，消费方见 `src/editor/lineAuthor/.frac.md`、`src/editor/signs/.frac.md`。
- 改结果结构（`Status`、`PullResult`、`PushResult`、`BlameCommit`、`GitConflictError` 等）：它们定义在 `src/types`，同时影响两个后端与 UI。
