## 1. 本目录是什么

两个 Obsidian `ItemView` 形式的 diff 视图，加一个给 CodeMirror 编辑器用的右键菜单扩展：
- `diffView.ts`：只读的统一 diff（unified），用 `diff2html` 把 `gitManager.getDiffString` 的文本渲染成 HTML。
- `splitDiffView.ts`：左右分栏（a / b）的 `@codemirror/merge` `MergeView`，b 侧在工作区文件存在时可直接编辑并自动写回，桌面端还带 hunk 级 Stage / Unstage / Reset。
- `contextMenu.ts`：把 Obsidian `Menu` 接到 CodeMirror 的 `contextmenu` DOM 事件上，供 `splitDiffView` 使用。
两个视图都用 `DiffViewState`（`src/types`，字段 `aFile` / `aRef` / `bFile` / `bRef`）作为 `setState` / `getState` 的状态，用 `src/constants` 里的 `DIFF_VIEW_CONFIG` / `SPLIT_DIFF_VIEW_CONFIG` 提供 view type、名称、图标。本层不负责「选哪个视图、怎么打开」，也不负责视图注册（`src/main.ts` 的职责）；调用方传来 state，视图自己取内容。

## 2. 直属文件

- `diffView.ts`：`export default class DiffView extends ItemView`，构造 `(leaf, private plugin: ObsidianGit)`。`refresh()`（受 `gettingDiff` 互斥）流程：`plugin.gitManager.getDiffString(bFile, aRef == "HEAD", bRef)`；结果为空时分两路兜底：`gitManager instanceof SimpleGit` 且 `isTracked(bFile)` → 只含 `---` / `+++` 头的空 diff；否则若 vault 里有该文件 → 合成「全部新增」的 diff（`--- /dev/null`，每行加 `+`）；都没有则显示「File not found: …」。最终取 `html(diff)` 解析出的 `.d2h-file-diff` 追加到 `contentEl`（内容区 class `git-diff`）。监听 `obsidian-git:status-changed` 自动刷新。
- `splitDiffView.ts`：`export default class SplitDiffView extends ItemView` 与 `export function getSplitDiffTimeout(configuredTimeout, editable)`（配置值非正整数时回退 `DEFAULT_SETTINGS.diffTimeout`；b 侧不可编辑时超时乘 `READ_ONLY_DIFF_TIMEOUT_FACTOR = 10`）。
  - 左 a 侧永远只读，内容 `gitShow(aRef, aFile)`；右 b 侧：`bRef == undefined` = 工作区（标题后缀「(Working Tree)」），`bRef == ""` = 暂存区（「(Index)」），其余 = 提交（取前 7 位）。只有 `bRef == undefined` 且文件在 vault 里存在（`bShouldBeEditable`）时 b 可编辑，并挂 `autoSavePlugin`：非 `Transaction.remote` 的改动经 `fileSaveDebouncer`（1000ms）`vault.adapter.write` 写回。
  - 刷新：`obsidian-git:status-changed` → 无 mergeView 或 `indexUnmerged` 时 `createMergeView()`（整个重建），否则 `updateRefEditors()`（只更新 a 侧和有 ref 的 b 侧，不碰工作区 b）；`window.setInterval` 每 30s 同样 `updateRefEditors()`，`onClose` 里 `clearInterval`；vault `modify` → `updateModifiableEditor()`（读盘，以 `Transaction.remote` 注解派发，防止回写），`create` / `delete` / `rename` → 重建视图以切换可编辑性。
  - `gitShow(commitHash, file)`：调 `gitManager.show(hash, file, false)`；捕获 simple-git 的 `GitError`：`commitHash === ""` 且报「is in the index, but not at stage 0」→ 置 `indexUnmerged = true` 并退到 stage 2（`":2"`，我方），stage 2 也没有则返回 `""`；报「does not exist」「unknown revision or path」「exists on disk, but not in」「fatal: bad object」→ 返回 `""`（`bad object` 另外 `displayError`，对应嵌套仓库）；其他重新抛出。
  - `renderButtons`：给每个 chunk 画控件（`showButtons = gitManager instanceof SimpleGit && !indexUnmerged && (bRef === undefined || bRef === "")`）：Stage hunk（`bRef == undefined`）/ Unstage hunk（其余），mousedown 时用 `rawHunkFromChunk` + `rawHunksToHunks` + `Hunks.createPatch(bFile, [hunk], "100644", bRef != undefined)` 生成 patch，`(gitManager as SimpleGit).applyPatch`，再 `workspace.trigger("obsidian-git:refresh")`；工作区视图另有 Reset hunk（把 b 侧该 chunk 改回 a 侧内容，`userEvent: "revert"`）。
- `contextMenu.ts`：导出 `getSelectedText(state)`（多选区按 `state.lineBreak` 拼接）和 `diffContextMenu`（`EditorView.domEventHandlers({ contextmenu })`，`preventDefault` 后用 `Menu.forEvent` 弹出：Cut / Copy / Paste / Paste as plain text / Select all）。可编辑性 = `!state.readOnly && facet(EditorView.editable)`；Paste 优先 `navigator.clipboard.read()` 的 `text/html` 并 `htmlToMarkdown`，Plain 版本用 `readText()`。

## 4. 本层约束 / 约定 / 禁忌

- `DiffViewState` 的 ref 约定贯穿两个视图和调用方：`aRef` 为 `"HEAD"` / `""`（暂存区）/ 任意提交引用；`bRef` 为 `undefined`（工作区）/ `""`（暂存区）/ 任意提交引用。`undefined` 与 `""` 含义不同，不要用 `!bRef` 或 `??` 合并。`aFile` / `bFile` 是仓库相对路径，进 vault 前必须经 `gitManager.getRelativeVaultPath()`（仓库根可能不等于 vault 根）。
- `SplitDiffView` 的 `refreshing` 是一个共用的互斥标志（`createMergeView` / `updateRefEditors` / `updateModifiableEditor`）：忙时新请求直接 return，不排队、不合并；`ignoreNextModification` 是一次性标志，自己写盘前置 true，下一次 `modify` 消费掉，写盘失败时它会一直保留，吞掉下一次外部修改。
- 不继承 `FileView`：因为 `.gitignore` 这类点文件没有 `TFile`（源码注释），所以文件内容一律走 `vault.adapter` 读写 vault 相对路径，不要改成依赖 `TFile`。
- 桌面 / 移动差异：`Platform.isMobile` 时 `setState` 手动把标题写进 `leaf.view.titleEl`；hunk 控件只在 `gitManager instanceof SimpleGit`（桌面）出现；`gitShow` 的错误兜底只认 simple-git 的 `GitError` 文案，其他后端的错误会原样抛出；`DiffView` 的「已跟踪但无变化」兜底同样要求 `SimpleGit`。这两个文件都 import `SimpleGit` 做 `instanceof`，所以会把 `src/gitManager/simpleGit` 带进 UI 依赖。
- `DiffView.onClose` 对 `gitViewRefreshRef` 做 `offref`，但该字段只声明、从未赋值；`gitRefreshRef` 是手动 `workspace.on` + `offref`，不是 `registerEvent`。`SplitDiffView` 的事件用 `registerEvent`，但 30s 定时器是 `window.setInterval` 手动清理，改生命周期时要两边对照。
- hunk 控件靠 `contentEl.parentElement?.indexOf(contentEl)` 把按钮位置当作 chunk 序号，依赖 `MergeView` 渲染控件的 DOM 顺序与 `getChunks` 一致；`Hunks.createPatch` 的文件模式写死 `"100644"`。
- hunk 的 Stage / Unstage 在 mousedown 回调里直接 `await (gitManager as SimpleGit).applyPatch(patch)`，既没有经过 `plugin.promiseQueue`（`AGENTS.md` 要求串行化 Git 变更），也没有 `try/catch`；改这里要考虑与队列里其他 Git 操作并发，以及 `applyPatch` 失败时错误的出口。
- 超时：`diffConfig.timeout` 来自 `plugin.settings.diffTimeout`，经 `getSplitDiffTimeout` 处理；`MergeView` 用 `collapseUnchanged: { minSize: 6, margin: 4 }`。
- 菜单与文案（Cut / Copy / Paste / Stage hunk / Reset hunk / 「File not found」等）为硬编码英文。

## 5. 什么时候需要下钻

- 改 diff 的取数（`getDiffString`、`show`、`applyPatch`、`isTracked`、`getRelativeVaultPath`）：不在本层，看 `src/gitManager`（契约 `gitManager.ts` 与两个后端）。
- 改 hunk 的计算 / patch 生成：`src/editor/signs/diff`（`rawHunkFromChunk`、`rawHunksToHunks`）与 `src/editor/signs/hunks`（`Hunks.createPatch`）。
- 改 `DiffViewState` 形状、视图 type / 图标：`src/types`、`src/constants`；视图注册、`obsidian-git:status-changed` 的触发方和 `obsidian-git:refresh` 的响应方都不在本层（刷新编排归 `src/main.ts`，见 `AGENTS.md`）。
- 谁在什么条件下打开哪个视图（unified 还是 split）、如何构造 `DiffViewState`：不在本层，从调用方（上级 `../.frac.md` 与 `plugin.tools` 的实现）往上查。
