# .frac.md — src/ui

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

插件的整个界面层。视图有 History、Source Control、统一 / 分栏 diff、只读文件视图、同步状态视图（维护版新增），另有对话框和状态栏分支名。列表型视图（history、sourceControl）是「TS 外壳 + Svelte 5 根组件 + `components/`」，其余是纯 TS。

界面层不实现 Git：数据和动作都经 `plugin.gitManager`、`plugin.gitActions`、`plugin.promiseQueue`、`plugin.tools` 取得；视图注册、命令 ID、事件的触发方不在这里（`src/main.ts`、`src/commands.ts`）。

## 2. 直属文件

- `readOnlyFileView.ts`：`ReadOnlyFileView`，用 CodeMirror 只读显示某个 ref 下的文件；状态 `ReadOnlyFileViewState`（`src/types`），入口是 `plugin.tools.openFileAtCommit`。不捕获 `show` 的错误；只在还没渲染成功过时才在 `obsidian-git:head-change` 上重试。
- `syncStatusView.ts`（维护版新增）：`SyncStatusView`，同步状态页，纯 TS，每次 `render()` 整块重建。
  - 数据全部来自 `plugin.syncSupervisor`（订阅其 `onChange`）；文案中英双语，问题文案来自 `src/syncProblems.ts`。
  - 由 `SyncSupervisor.openView()` 打开；样式是 `styles.css` 的 `.git-maintained-sync-*`。

## 3. 子目录导航

- `diff/`：见 `diff/.frac.md`；统一 / 分栏 diff 视图和编辑器右键菜单。
- `history/`：见 `history/.frac.md`；History 侧栏，提交列表的加载、分页、刷新；提交行在其 `components/`。
- `modals/`：见 `modals/.frac.md`；各类对话框，多数返回 `Promise`。
- `sourceControl/`：见 `sourceControl/.frac.md`；Source Control 侧栏，文件行与目录树在其 `components/`。
- `statusBar/`：见 `statusBar/.frac.md`；`BranchStatusBar`，状态栏里的分支名。

## 4. 本层约束 / 约定 / 禁忌

- 两个 Svelte 视图（`HistoryView`、`GitView`）外壳同构：`onOpen` → `reload()` → `mount` 根组件并传入 `plugin` 与 `view: this`，重载与关闭先 `unmount`；新增 Svelte 视图沿用。
- 读走 `plugin.gitManager`，变更走 `plugin.promiseQueue.addTask(() => plugin.gitActions.xxx())`。已知例外：`diff/splitDiffView.ts` 的 hunk Stage / Unstage 直接 `applyPatch`，不入队。
- 桌面 / 移动的能力判断主要靠 `gitManager instanceof SimpleGit`，不是 `Platform.isMobile`；界面代码不能假设 `SimpleGit` 一定可用。
- workspace 事件的触发方都在 UI 之外：`obsidian-git:status-changed`（sourceControl、两个 diff 视图监听）、`obsidian-git:head-change`（history、`ReadOnlyFileView` 监听）；UI 反向只触发 `obsidian-git:refresh`（sourceControl、`SplitDiffView`）。要刷新就订阅这些事件，不要自建轮询。
- 清理没有统一写法，改生命周期要逐目录核对（`AGENTS.md` 要求卸载与设置重载两条路径都清理）。history、sourceControl 的刷新错误只 `console.error`；新增代码走 `plugin.displayError`，不要吞 Git 错误。
- 跨目录耦合：`settings.treeStructure` 被 history 与 sourceControl 读写且都不监听变化，另一个视图要 `reload()` 才同步；sourceControl 的 `#merge-status` 经 `plugin.openMergeConflictHelp()` 打开 `MergeConflictModal`，其文案描述冲突区块的操作，改冲突界面时要同步。
- 文案硬编码英文（同步状态视图中英双语除外）。样式分两处：组件自带的 scoped `<style>`，以及根目录 `styles.css`。

## 5. 什么时候需要下钻

- 改 History 或 Source Control 侧栏：读各自的 `.frac.md`；文件行、目录树再读其 `components/.frac.md`。两边各有一份文件行组件，要分别改。
- 改 diff：`diff/.frac.md`；选哪个视图、如何构造 `DiffViewState`：`plugin.tools`。
- 改对话框：先读 `modals/.frac.md` 第 4 节（取消 / 关闭语义），并按类名全仓搜索调用点。
- 改同步状态视图：`syncStatusView.ts`、`src/syncSupervisor.ts`、`src/syncProblems.ts`。
- 新增视图 / 对话框 / 状态栏项：类放本层，视图常量在 `src/constants`，状态类型在 `src/types`，注册在 `src/main.ts`，命令在 `src/commands.ts`。
