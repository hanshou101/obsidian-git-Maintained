## 1. 本目录是什么

插件的整个界面层，由 5 个子目录加 2 个直属视图文件组成：
- Obsidian `ItemView`：History（`history/`）、Source Control（`sourceControl/`）、统一 diff 与分栏 diff（`diff/`）、只读文件视图（本层的 `readOnlyFileView.ts`）、同步状态视图（本层的 `syncStatusView.ts`，维护版新增）。
- 对话框（`modals/`）和状态栏分支名（`statusBar/`）。
列表型视图（history、sourceControl）是「TS 外壳 + Svelte 5 根组件 + `components/`」；diff 与只读文件视图是纯 TS + CodeMirror。
界面层不实现 Git：数据和动作都经 `plugin.gitManager`、`plugin.gitActions`、`plugin.promiseQueue`、`plugin.tools` 取得。视图的注册、命令 ID、事件的触发方都不在这里（`src/main.ts` / `src/commands.ts`，见 `AGENTS.md`）。

## 2. 直属文件

- `readOnlyFileView.ts`：`export default class ReadOnlyFileView extends ItemView`，构造 `(leaf, private readonly plugin)`。在 CodeMirror `EditorView` 里只读显示某个 ref 下的文件内容：`ReadOnlyFileViewState`（`src/types`，字段 `file`、`ref`）经 `setState` 传入，`renderFile()` 调 `plugin.gitManager.show(ref, file, false)`（走抽象契约，不转 `SimpleGit`），销毁旧编辑器后重建 `EditorView`（`lineNumbers`、`drawSelection`、`standardKeymap`、`search`、`lineWrapping`、`EditorState.readOnly`，加一个隐藏光标的 `readOnlyEditorTheme`）。
  - 视图类型 / 名称 / 图标取自 `src/constants` 的 `READ_ONLY_FILE_VIEW_CONFIG`；`navigation = true`；`contentEl` 带 `git-read-only-file-view cm-s-obsidian mod-cm6 markdown-source-view`；标题 `getDisplayText()` = `<文件名> (<ref 前 7 位>)`，`setState` 里无条件写 `leaf.view.titleEl.textContent`。
  - `renderFile()` 在没有 state 或 `!plugin.gitReady` 时直接返回，自身不捕获 `show` 的错误（错误向 `setState` / `onOpen` 的调用方传播）；`setState` 与 `onOpen` 都会调用它（没有 state 的那次空转），每次先 `destroy` 旧编辑器再重建。构造时 `registerEvent` 订阅 `obsidian-git:head-change`，仅在 `!this.editor`（还没渲染成功过，例如打开时 Git 未就绪）时才重试渲染并用 `plugin.displayError` 报错；已有编辑器时不刷新。`onClose` 销毁编辑器。
  - 谁打开它、怎么构造 `ReadOnlyFileViewState`，不在本文件。History 的文件行有「Open file at this commit」按钮，调 `plugin.tools.openFileAtCommit`（见 `history/.frac.md`），[推测] 这就是它的入口，未在本层验证。
- `syncStatusView.ts`（维护版新增，AME-1119）：`export default class SyncStatusView extends ItemView`，构造 `(leaf, private readonly plugin)`。纯 TS、没有 Svelte：每次 `render()` 都 `contentEl.empty()` 后整块重建，根节点类名 `git-maintained-sync-status`，样式是根目录 `styles.css` 末尾的 `.git-maintained-sync-*`（不是组件内 scoped 样式）。
  - 视图类型 / 名称 / 图标取自 `src/constants` 的 `SYNC_STATUS_VIEW_CONFIG`（类型 `git-maintained-sync-status`，图标 `refresh-cw`）；`getDisplayText()` 是「同步状态」/ `Sync status`。注册在 `src/main.ts`；打开方式不在本文件，是 `SyncSupervisor.openView()`（命令 `open-sync-status`、设置页按钮、ribbon 图标、点击通知都走它）。
  - 数据全部来自 `plugin.syncSupervisor`（当非空用）：`onOpen` 订阅 `supervisor.onChange(() => render())` 并用 `registerInterval` 每 15 s 重绘（刷新相对时间和重试倒计时），`onClose` 取消订阅；渲染读 `snapshot()`、`entries`、`language`、`reasonText`、`keepingAwake`；文案经 `supervisor.text(zh, en)` 中英双语（跟 Obsidian 语言），问题的标题 / 解释 / 做法来自 `src/syncProblems.ts` 的 `problemText`。
  - 版面从上到下：头部（按 `phase` 的 syncing / attention / waiting / pending / idle 选图标与标题）；三个按钮——「立即同步」→ `supervisor.requestSync("manual")`（`plugin.gitReady` 为假时只弹通知）、「复制详情」→ `supervisor.details()` 写剪贴板、「清空记录」→ `supervisor.clearLog()`；有问题时的问题框（标题、解释、「怎么办」、起始时间与次数、最多列 20 个文件、可展开的原始错误；`problemText` 的第三个参数传 `state.weakNetworkMode`，决定文案是否承诺自动重试）；事实表（最近成功 / 上传 / 拉取、未上传的提交数、未提交的编辑、网络、后台联网、两个开关，移动端再加一行亮屏；后台被拦时多一条电池设置提示）；历史（新的在前，最多显示 100 条，条目带可展开的详情）。

## 3. 子目录导航

- `diff/`：见 `diff/.frac.md`；`DiffView`（diff2html 统一 diff）、`SplitDiffView`（`@codemirror/merge` 分栏，工作区侧可编辑并自动写回，桌面端带 hunk 级 Stage / Unstage / Reset）和编辑器右键菜单。
- `history/`：见 `history/.frac.md`；History 侧栏视图，负责提交列表的加载、无限滚动、刷新与布局切换；每条提交 / 文件行的渲染在其 `components/`。
- `modals/`：见 `modals/.frac.md`；7 个 Modal，其中 5 个 Promise 型（`BranchModal`、`CustomMessageModal`、`GeneralModal`、`IgnoreModal`、`DiscardModal`），`ChangedFilesModal` 与 `MergeConflictModal` 不返回值。
- `sourceControl/`：见 `sourceControl/.frac.md`；Source Control 侧栏（工具栏、提交框、Conflicts / Staged / Changes / Recently Pulled 区块），文件行与目录树的渲染在其 `components/`。
- `statusBar/`：见 `statusBar/.frac.md`；`BranchStatusBar`，状态栏里的当前分支名，点击切换分支。

## 4. 本层约束 / 约定 / 禁忌

- 两个 Svelte 视图的外壳同构：`HistoryView`（`history/historyView.ts`）与 `GitView`（`sourceControl/sourceControl.ts`）都是 `ItemView` + `HoverParent`，`onOpen` → `reload()` → `mount(Root, { target: contentEl, props: { plugin, view: this } })`，`onClose` / 重载先 `unmount`；子组件靠 props 里的 `plugin` / `view`（`view.app`、`view.leaf`、`view.plugin`）取依赖。新增 Svelte 视图沿用这个模式，不要在组件里另找插件实例。
- 读写 Git 的口径：读走 `plugin.gitManager`（抽象契约），变更走 `plugin.promiseQueue.addTask(() => plugin.gitActions.xxx())`（sourceControl 的按钮与状态栏点击都是如此）。已知例外：`diff/splitDiffView.ts` 的 hunk Stage / Unstage 直接 `applyPatch`，不入队。
- 桌面 / 移动：能力判断主要靠后端类型 `plugin.gitManager instanceof SimpleGit`（history 的分页 50 / 10、diff 的 hunk 控件与 `GitError` 兜底），`Platform.isMobile` 只用在少数视觉处（sourceControl 的推送按钮高亮、diff 视图在移动端手动写标题）。界面代码不能假设 `SimpleGit` 一定可用。
- 事件总线（自定义 workspace 事件，触发方都在 UI 之外）：`obsidian-git:status-changed`（sourceControl、DiffView、SplitDiffView 监听）、`obsidian-git:head-change`（history、ReadOnlyFileView 监听）、`obsidian-git:loading-status` 与 `obsidian-git:repository-state-changed`（sourceControl 监听）；UI 反向只触发 `obsidian-git:refresh`（sourceControl、SplitDiffView）。新增界面需要刷新时订阅这些事件，不要自建轮询；本层目前只有 `SplitDiffView` 有 30s 定时器（维护版的 `SyncStatusView` 另有 15s 重绘，为了刷新相对时间；它不订阅 workspace 事件，而是订阅 `SyncSupervisor.onChange`）。
- 监听与资源的清理没有统一写法，改生命周期要逐目录核对（`AGENTS.md` 要求普通卸载与设置重载两条路径都清理）：history 在 `onMount` 清理函数里 `offref`；sourceControl 用 `view.registerEvent`，跟随视图而不是 Svelte 组件，`reload()` 会叠加监听；DiffView 手动 `workspace.on` + `offref`；SplitDiffView 的事件走 `registerEvent` 但定时器手动清理；`BranchStatusBar` 的点击监听只靠 `remove()`；`SyncStatusView` 在 `onClose` 里调 `supervisor.onChange` 返回的取消函数，重绘定时器走 `registerInterval`。
- 错误出口不一致：history、sourceControl 的刷新只 `.catch(console.error)`，`ReadOnlyFileView` 和 SplitDiffView 的 `bad object` 分支用 `plugin.displayError`；新增代码按 `AGENTS.md` 走 `displayError`，不要吞 Git 错误。
- 共享设置与跨目录耦合：`plugin.settings.treeStructure` 同时被 history 与 sourceControl 的布局切换读写，两边都不实时监听设置变化，另一个视图要 `reload()` 才同步；`commitDateFormat` 被 history 的提交行与 `CustomMessageModal` 共用。sourceControl 的 `#merge-status` 按钮调 `plugin.openMergeConflictHelp()`，而 `modals/MergeConflictModal` 的文案描述的正是 Conflicts 区块的操作流程 [推测：该方法就是打开这个对话框，未在本层验证]；改冲突相关界面时这两处文案要同步。
- 文案全部硬编码英文，没有 i18n（维护版的同步状态视图是例外：中英双语，经 `supervisor.text(zh, en)` 按 Obsidian 语言选）。样式分两处：各 Svelte 组件自带的 scoped `<style lang="scss">`（`sourceControl.svelte` 最大；组件由 `@sveltejs/vite-plugin-svelte` 编译且 CSS 注入，见根目录 `vite.config.mjs`），以及根目录 `styles.css` 里的全局类（例如 `modals/.frac.md` 提示去那里搜 `git-obscure-prompt`、`obsidian-git-textarea`；同步状态视图的 `.git-maintained-sync-*` 在文件末尾）。

## 5. 什么时候需要下钻

- 改 History 侧栏：先读 `history/.frac.md`；改单条提交或文件行再读其 `components/.frac.md`。
- 改 Source Control 侧栏：先读 `sourceControl/.frac.md`；改文件行、目录树、折叠、按钮再读其 `components/.frac.md`。文件行点击如何打开 diff / 文件，history 与 sourceControl 两边各有一份行组件，要分别改。
- 改 diff 渲染、分栏编辑、hunk 操作、右键菜单：`diff/.frac.md`。diff 的取数在 `src/gitManager`；选哪个视图、如何构造 `DiffViewState` 去看 `plugin.tools`（`diff/.frac.md` 的指向，本层未读其实现），触发点是 history 与 sourceControl 文件行的点击（`openDiff`），都不在 `diff/` 内。
- 改任何对话框，尤其取消 / 关闭语义（`DiscardModal` 在 Esc 时不 resolve，方法名 `openAndGetReslt` / `openAndGetResult` 不一致）：先读 `modals/.frac.md` 第 4 节，并按类名全仓搜索调用点。
- 改状态栏分支名：`statusBar/.frac.md`；改只读文件视图：本文件第 2 节与 `readOnlyFileView.ts`；改同步状态视图：本文件第 2 节与 `syncStatusView.ts`，数据与文案在 `src/syncSupervisor.ts`、`src/syncProblems.ts`（见 `src/.frac.md`）。
- 新增视图 / 对话框 / 状态栏项时，类放在本层，视图常量在 `src/constants`、状态类型在 `src/types`、注册在 `src/main.ts`、命令在 `src/commands.ts`。
