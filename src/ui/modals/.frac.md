# .frac.md — src/ui/modals

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

插件里用 Obsidian `Modal` / `SuggestModal` / `FuzzySuggestModal` 做的对话框，每个文件一个导出类，纯 TypeScript，没有 Svelte。分两类：
- 「问一个值」型：`openAndGetResult()` 返回 `Promise`，调用方 `await`。
- 「展示 / 触发动作」型：没有返回值。
本层不含业务逻辑，不碰 Git，也没有平台分支；只持有 `plugin`（取 `app`、`settings`、`cachedStatus`）或 `app`。谁在哪个流程弹出它们，不在本层。

## 2. 直属文件

**问一个值**
- `generalModal.ts`：`GeneralModal` 与 `OptionalGeneralModalConfig`。万能单行输入框，可限定只能选候选项、允许空输入、给初始值；密码模式隐藏输入并带显隐按钮，建议项不回显明文。
- `branchModal.ts`：`BranchModal`，模糊选一个分支名。
- `customMessageModal.ts`：`CustomMessageModal`，提交信息输入；候选项是原文，以及加上 `commitDateFormat` 日期前缀或后缀的两种。
- `ignoreModal.ts`：`IgnoreModal`，多行编辑 `.gitignore`，Save 返回文本。
- `discardModal.ts`：`DiscardModal` 与 `DiscardResult`（`false | "delete" | "discard"`）。按未跟踪 / 已跟踪文件数拼文案和按钮：`"delete"` 删未跟踪文件并一并丢弃已跟踪改动，`"discard"` 只丢弃已跟踪改动，Cancel 为 `false`。

**展示 / 触发动作**
- `changedFilesModal.ts`：`ChangedFilesModal`，模糊选一个变更文件并打开（打不开的类型交给系统默认应用）。
- `mergeConflictModal.ts`：`MergeConflictModal`，合并进行中的帮助：按 `plugin.cachedStatus` 有无冲突给出不同说明，加固定的「完成合并」一段；打开时只取一次快照，不随状态刷新。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 关闭顺序：Obsidian 先调 `onClose` 再调 `onChooseItem` / `onChooseSuggestion`，所以 `BranchModal`、`CustomMessageModal`、`GeneralModal` 的 `onClose` 用短 `setTimeout` 延迟 `resolve(undefined)`，让选中项先 resolve（Promise 只能 resolve 一次）。新增同类 modal 要保留这个顺序，不要改成同步 resolve。
- 取消语义不统一：`BranchModal`、`CustomMessageModal`、`GeneralModal`、`IgnoreModal` 取消得到 `undefined`；`DiscardModal` 只有点 Cancel 才 resolve `false`，Esc 或点遮罩关闭时 Promise 保持 pending，调用方要自行兜底，改它要连调用方一起看。
- 方法名拼写不一致：`openAndGetReslt`（`BranchModal`、`IgnoreModal`）与 `openAndGetResult`（其余三个）。调用方按原名调用，改名要全仓同步。
- `GeneralModal` 用 `" "` 和 `"..."` 两个哨兵字符串区分「空输入」与「取消」，`options` 里含这两个值会被误映射。`CustomMessageModal` 空查询时把 `"..."` 原样 resolve，不转成 `undefined`。
- `MergeConflictModal` 的文案描述的是别处的界面行为（`src/editor/conflicts` 里的 Keep ours / theirs / both 按钮，Source Control 的 Conflicts 区块与加号）；那边改了，这里要同步。所有文案是硬编码英文，无 i18n。
- 依赖面很小：`obsidian`、`src/main`（仅类型）、`src/types`、`src/utils`；保持这个边界，不要在 modal 里直接调 `gitManager`。

## 5. 什么时候需要下钻

- 改某个流程里「弹什么、传什么参数、怎么处理返回值（含 `undefined` / `false` / `"..."`）」：不在本层，按类名全仓搜索调用点。
- 改 `commitDateFormat`：`src/setting/`；`plugin.cachedStatus` 的来源与刷新：`src/main.ts` 及 `src/gitManager`。
- 改密码输入框、`.gitignore` 文本框的外观：样式在根目录 `styles.css`，搜 `git-obscure-prompt`、`obsidian-git-textarea`。
