## 1. 本目录是什么

插件里所有用 Obsidian `Modal` / `SuggestModal` / `FuzzySuggestModal` 做的对话框，每个文件一个导出类，纯 TypeScript，没有 Svelte。
分两类：
- 「问一个值」型，`openAndGetResult()` 返回 `Promise`，调用方 `await`：`BranchModal`、`CustomMessageModal`、`GeneralModal`、`IgnoreModal`、`DiscardModal`。
- 「展示 / 触发动作」型，没有返回值：`ChangedFilesModal`（选中即打开文件）、`MergeConflictModal`（静态帮助）。
本层不含业务逻辑，也不碰 Git：只持有 `plugin`（取 `plugin.app` / `plugin.settings` / `plugin.cachedStatus`）或 `app`。谁、在哪个流程弹出这些对话框，不在本层。本层没有 `Platform` / desktop-mobile 分支判断。

## 2. 直属文件

- `generalModal.ts`：导出 `GeneralModal extends SuggestModal<string>` 和 `OptionalGeneralModalConfig`（`options` / `placeholder` / `allowEmpty` / `onlySelection` / `initialValue` / `obscure`，缺省值在 `generalModalConfigDefaults`）。万能单行输入框：
  - `getSuggestions`：`onlySelection` → 只给 `options`；`allowEmpty` → `[query || " ", ...options]`；否则 `[query || "...", ...options]`。`onChooseSuggestion` 映射：`allowEmpty && " "` → `""`，`"..."` → `undefined`，其余原值。
  - `obscure: true`（密码模式）：`inputEl.type = "password"`，给 `.prompt-input-container` 加 `git-obscure-prompt` / `git-is-obscured`，追加 `#git-show-password` 显隐切换按钮，`renderSuggestion` 把建议项 `hide()` 以免回显明文。
  - `initialValue` 在 `open()` 之后写入 `inputEl` 并派发 `input` 事件。
- `branchModal.ts`：`BranchModal extends FuzzySuggestModal<string>`，构造 `(plugin, branches: string[])`，占位文案「Select branch to checkout」，选中即 `resolve(item)`。方法名是 `openAndGetReslt()`（拼写如此）。
- `customMessageModal.ts`：`CustomMessageModal extends SuggestModal<string>`，提交信息输入。`getSuggestions(query)` 返回三项：`query`、`${date}: ${query}`、`${query}: ${date}`，`date = moment().format(plugin.settings.commitDateFormat)`；空查询时 `query` 被换成字面量 `"..."`，且 `onChooseSuggestion` 不会像 `GeneralModal` 那样把它转成 `undefined`，会原样 `resolve("...")`。方法名是 `openAndGetResult()`。
- `discardModal.ts`：导出 `type DiscardResult = false | "delete" | "discard"` 和 `DiscardModal extends Modal`，构造参数是对象 `{ app, path, filesToDeleteCount, filesToDiscardCount }`。`onOpen` 按两个计数动态拼标题 / 说明 / 按钮：有未跟踪文件才出现 Delete 按钮（`resolve("delete")`，已跟踪的一并丢弃），有已跟踪文件才出现 Discard 按钮（`resolve("discard")`，未跟踪不删），Cancel → `false`；文案用 `src/utils` 的 `plural`。按钮同时绑了 `click` 和 `keypress`（任意键）。`onClose` 只清空 `contentEl`，不 `resolve`。
- `ignoreModal.ts`：`IgnoreModal extends Modal`，构造 `(app, content)`，标题「Edit .gitignore」，一个 `obsidian-git-textarea`（rows 10、cols 30、`wrap: "off"`）加「Save」按钮，Save → `resolve(text.value)` 再 `close()`；`onClose` 清空并 `resolve(undefined)`。方法名是 `openAndGetReslt()`（拼写如此）。
- `changedFilesModal.ts`：`ChangedFilesModal extends FuzzySuggestModal<FileStatusResult>`，构造 `(plugin, changedFiles)`。`getItemText`：`index` 与 `workingDir` 都是 `"U"` → `Untracked | <vaultPath>`，否则拼 `Working Dir: X` / `Index: Y`（非空格才拼）再加 `| <vaultPath>`。`onChooseItem`：`metadataCache.getFirstLinkpathDest(vaultPath, "")` 为 null → `app.openWithDefaultApp(vaultPath)`，否则 `workspace.openLinkText(vaultPath, "/")`。
- `mergeConflictModal.ts`：`MergeConflictModal extends Modal`，构造 `(plugin)`。`onOpen` 读 `plugin.cachedStatus?.conflicted ?? []`：有冲突 → 三步说明（Keep ours / Keep theirs / Keep both 或手动改；冲突数归零后点文件旁的加号标记已解决；对 Conflicts 区块每个文件重复）；无冲突 → 「All conflicts have been marked as resolved」并提示合并仍未结束；最后固定一段「Finish the merge」（输入提交信息并提交暂存区）和「Got it」按钮。只读取一次快照，打开期间不随状态刷新。

## 4. 本层约束 / 约定 / 禁忌

- Promise 型 modal 的关闭约定：Obsidian 先调 `onClose` 再调 `onChooseItem` / `onChooseSuggestion`，所以 `BranchModal`、`CustomMessageModal`、`GeneralModal` 的 `onClose` 用 `setTimeout(10ms)` 延迟 `resolve(undefined)`，让选中项先 resolve；Promise 只能 resolve 一次，后到的 `undefined` 被忽略。新增同类 modal 要保留这个顺序，不要改成同步 resolve。
- 取消语义不统一：`BranchModal` / `CustomMessageModal` / `GeneralModal` / `IgnoreModal` 取消得到 `undefined`；`DiscardModal` 取消得到 `false`，但只有 Cancel 按钮会 resolve，Esc 或点遮罩关闭时 `onClose` 不 resolve，`openAndGetResult()` 的 Promise 保持 pending。调用方需自行兜底，改它要连调用方一起看。
- 两个方法名拼写不一致：`openAndGetReslt`（`BranchModal`、`IgnoreModal`）与 `openAndGetResult`（其余三个）。调用方按原名调用，改名要全仓同步。
- `GeneralModal` 用 `" "` 和 `"..."` 两个哨兵字符串区分「空输入」与「取消」，`options` 里若本来就含这两个值会被误映射；`obscure` 模式只隐藏建议项文字，选中仍走 `onChooseSuggestion`。
- `MergeConflictModal` 的文案描述的是其他界面的行为（Conflicts 区块、加号图标、Keep ours / theirs / both 按钮、「冲突数归零」），对应界面改动后这里要同步；全部为硬编码英文，其他 modal 同样没有 i18n。
- 依赖面很小：`obsidian`、`src/main`（仅类型，取 `plugin`）、`src/types`（`FileStatusResult`）、`src/utils`（`plural`）。保持这个边界，不要在 modal 里直接调 `gitManager`。

## 5. 什么时候需要下钻

- 改某个流程里「弹什么、传什么参数、怎么处理返回值（含 `undefined` / `false` / `"..."`）」：不在本层，按类名全仓搜索调用点（`new GeneralModal(`、`new DiscardModal(` 等）。
- 改 `plugin.settings.commitDateFormat` 的取值或默认值：`src/setting/`；`plugin.cachedStatus` 的来源与刷新：`src/main.ts` 及 `src/gitManager`。
- 改密码输入框的外观：样式不在本层，去根目录 `styles.css` 搜 `git-obscure-prompt`、`git-show-password`、`obsidian-git-textarea`。
