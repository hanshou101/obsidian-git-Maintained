## 1. 本目录是什么

Source Control 侧边视图里「文件列表怎么画」的 Svelte 5 组件：一个递归目录树 `treeComponent.svelte`，加上四种叶子行（已暂存 / 未暂存 / 已拉取 / 冲突）和一个「超出 500 个」提示行。
全部使用 runes（`$props` / `$state` / `$derived` / `$effect` / `$bindable`），根元素统一是 `<main>`；视图实例类型 `GitView` 引自 `../sourceControl`，`plugin` 一律经 `view.plugin` 或 props 取得。
本层只负责渲染与「点击 → 入队 Git 动作 / 打开文件 / 打开 diff」的转发，不持有文件状态；状态数据（`StatusRootTreeItem`、`FileStatusResult`、`conflictCounts`、`closed`）都由调用方传入。
入口是 `treeComponent.svelte`（本层唯一引用其余组件的文件，由上级使用）；没有 `.ts` 文件，没有对外函数。类型和 `FileType` 枚举来自 `src/types`，工具来自 `src/utils`。

## 2. 直属文件

- `treeComponent.svelte`：递归树。Props：`hierarchy: StatusRootTreeItem`、`plugin`、`view: GitView`、`fileType: FileType`、`topLevel?`（默认 false，只加到 `<main class:topLevel>`）、`closed`（`$bindable()`，键是 `TreeItem.path`，缺省 = 展开）、`conflictCounts?: Record<string, number>`（默认 `{}`）。
  - 遍历 `arrayProxyWithNewLength(hierarchy.children, 500)`，每层最多渲染 500 个直接子节点，末尾再放 `<TooManyFilesComponent files={hierarchy.children} />`。
  - 叶子（`entity.data` 有值）按 `fileType` 分派：`FileType.staged` → `StagedFileComponent`，`changed` → `FileComponent`，`pulled` → `PulledFileComponent`，`conflicted` → `ConflictFileComponent`（传 `path={entity.data.path}`、`count={conflictCounts[path]}`、`manager={plugin.gitManager}`，不传 `change`）。
  - 目录行：点击标题 `fold()` 翻转 `closed[item.path]`；整个目录 div 的 `onauxclick`（不检查 `event.button`）直接调 `mayTriggerFileMenu(..., entity.vaultPath, ..., "git-source-control")`；展开时递归渲染自身（`entity as StatusRootTreeItem`，文件首行 `tslint:disable ts(2345)`）并 `bind:closed`，带 `transition:slide|local` 150ms。目录级按钮只有 staged（Unstage → `gitActions.unstageAll(entity.path)`）和 changed（Discard → `gitActions.discardAll(item.vaultPath)`、Stage → `gitActions.stageAll(entity.path)`）；pulled / conflicted 没有目录按钮。图标是内联 SVG，不走 `setIcon`。
  - `onMount`：直接子目录的 `children.length > 100` 时设 `closed[entity.path] = true`（自动折叠大目录）。
- `fileComponent.svelte`：未暂存（changed）文件行。Props：`change: FileStatusResult`、`view`。主点击 `mainClick`：`fileIsBinary(change.path)` → `open`，否则 `plugin.tools.openDiff({ aFile: change.path, aRef: "", event })`。按钮：`go-to-file`（`fileOpenableInObsidian` 为真才显示）、`undo`（`gitActions.discardFile(change)`）、`plus`（`gitActions.stage(change.path, false)`）。状态字母显示 `change.workingDir`。
- `stagedFileComponent.svelte`：已暂存文件行，结构同上。diff 为 `openDiff({ aFile: change.from ?? change.path, bFile: change.path, aRef: "HEAD", bRef: "", event })`（重命名取 `change.from`）。按钮：`go-to-file`（只绑 `onclick`，没有 `onauxclick`）、`minus`（`gitActions.unstage(change.path, false)`）。状态字母显示 `change.index`。
- `pulledFileComponent.svelte`：拉取下来的远端变更行，只读。点击 / 中键 → `open`，右键 → 文件菜单，悬停 → 预览；从不开 diff，没有按钮，不调用 `setIcon`。状态字母显示 `change.workingDir`。
- `conflictFileComponent.svelte`：冲突文件行。Props：`path: string`、`count: number | undefined`、`view`、`manager: GitManager`（不是 `FileStatusResult`）。`vaultPath = manager.getRelativeVaultPath(path)`。点击行 → `open`；唯一按钮 `resolve` → `plugin.promiseQueue.addTask(() => gitActions.stage(path, false))`，`aria-label` 固定为「Mark resolved」，图标 `count === 0 ? "plus" : "check"`。`count` 三态：`undefined` 不显示任何标记，`0` 显示勾图标（`.type.resolved`，颜色 `--git-insert`，「No conflicts left」），`>0` 显示数字（`.type.conflict`，颜色 `--git-change`）。没有 `onauxclick` / 悬停预览 / 右键菜单，所以辅助键点击会冒泡到外层目录 div 的 `onauxclick`。本层唯一带实质 scoped 样式的文件（`.git-tools` 两列 grid，用 `--git-change`、`--git-insert`、`--icon-m`、`--size-2-1`）。
- `tooManyFilesComponent.svelte`：Props `files: unknown[]`；`files.length > 500` 时渲染一行「And N more files」（N = 长度 − 500），否则渲染空 `<main>`。

## 4. 本层约束 / 约定 / 禁忌

- 会改仓库状态的点击一律 `plugin.promiseQueue.addTask(() => plugin.gitActions.xxx(...))`（stage / unstage / discardFile / stageAll / unstageAll / discardAll），不要在组件里直接调 gitManager 的变更方法，也不要绕开队列。
- 路径口径要分清：`change.path` / `entity.path` 是 Git 侧路径（交给 `gitActions.stage` / `unstage` / `stageAll` / `unstageAll`、`fileIsBinary`），`change.vaultPath` / `entity.vaultPath` 是 vault 路径（用于 `getAbstractFileByPath`、`getDisplayPath`、`aria-label`、`data-path`、`mayTriggerFileMenu`）；冲突行只拿到 `path`，靠 `manager.getRelativeVaultPath(path)` 换算。例外要留意：目录 Discard 传 `vaultPath`（`discardAll`），文件 Discard 传整个 `change`（`discardFile`），目录 Stage / Unstage 传 `path`。
- 「500」在两处各自写死（`treeComponent` 的 `arrayProxyWithNewLength(..., 500)` 与 `tooManyFilesComponent` 的 `> 500`、`- 500`），改上限必须同步；限制是对每一层的直接子节点，不是整棵树总数。「100」自动折叠阈值只在 `treeComponent` 的 `onMount`。
- `onMount` 只在该层 `TreeComponent` 挂载时跑；父目录折叠后再展开会重新挂载并再次把大目录置为折叠，覆盖用户之前手动展开的状态。
- 折叠约定与 history 相反：这里 `closed[path]` 缺省为展开；`closed` 自最外层经 `bind:closed` 逐层下传，不要在子层另建副本。
- 叶子行的图标由 `$effect` 里 `setIcon(b, b.getAttr("data-icon")!)` 填充，元素来自 `bind:this={buttons[i]}`；新增按钮要同时加 `data-icon` 和 `buttons[n]`。`{#if}` 掉的按钮槽位为空，`if (b)` 已防御。目录行的按钮则是手写内联 SVG，改图标要改 SVG。
- diff 入口口径：未暂存 `aRef: ""` 且无 `bFile` / `bRef`；已暂存 `aRef: "HEAD"`、`bRef: ""`；空串的含义由 `plugin.tools.openDiff` 解释，不在本层。
- 悬停预览：`fileComponent` / `pulledFileComponent` 用 `getAbstractFileByPath` 判断存在，`stagedFileComponent` 用 `getFileByPath`；只在文件存在于 vault 时才 `hoverPreview`（注释：不预览配置文件或隐藏文件）。
- 本层不判断平台，没有 desktop/mobile 分支。文案（「Open File」「Discard」「Stage」「Unstage」「Mark resolved」「And N more files」等）全部是硬编码英文，无 i18n。
- 键盘无障碍未实现，a11y 告警以 `svelte-ignore a11y_*` 注释压制；`fileComponent` 顶部还留有一条 TODO（左侧栏或路径过长时的 aria-label）。

## 5. 什么时候需要下钻

- 加/改某类文件行的按钮或点击行为：对应 `*FileComponent.svelte`，并追到 `plugin.gitActions`（动作）、`plugin.tools.openDiff`（diff）、`src/utils`（`mayTriggerFileMenu`、`getNewLeaf`、`hoverPreview`）。
- 改文件分组、排序、目录树的构造或 `FileType` 的取值：不在本层，看上级 `../.frac.md`（`src/ui/sourceControl`）以及 `src/types`、`GitManager` 的树构造方法。
- 新增一种文件状态区块（除 staged / changed / pulled / conflicted 之外）：要同时改 `treeComponent.svelte` 的 `fileType` 分派和目录按钮分支，并新增叶子组件。
- 冲突计数 `conflictCounts` 的来源与刷新时机：不在本层，看上级。
