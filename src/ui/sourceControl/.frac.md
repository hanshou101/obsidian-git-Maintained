## 1. 本目录是什么

Source Control 侧边视图（暂存 / 修改 / 冲突 / 最近拉取的文件，提交信息框，工具栏）。`sourceControl.ts` 是 Obsidian `ItemView` 外壳（类名 `GitView`），`sourceControl.svelte` 是挂在其 `contentEl` 里的 Svelte 5 根组件，拥有本视图全部数据与状态；文件行与目录树的渲染交给子目录 `components/`。
数据权威在插件：`plugin.cachedStatus`、`plugin.lastPulledFiles`、`plugin.state.mergeInProgress`、`plugin.repositoryMissing`；本层只在 `refresh()` 里拷成本地 `$state` 并建树。所有改仓库的动作都是 `plugin.promiseQueue.addTask(() => plugin.gitActions.xxx(...))`，多数在 `.finally(triggerRefresh)` 里用 `workspace.trigger("obsidian-git:refresh")` 请插件刷新；本组件自己的 `refresh()` 则由 `obsidian-git:status-changed` 等事件驱动。
视图类型、名称、图标来自 `src/constants` 的 `SOURCE_CONTROL_VIEW_CONFIG`；视图注册归 `src/main.ts`，不在本层。

## 2. 直属文件

- `sourceControl.ts`：`export default class GitView extends ItemView implements HoverParent`，构造 `(leaf, plugin)`，字段 `plugin`、`hoverPopover`、私有 `_view`。`onOpen()` → `reload()`；`reload()` 先 `unmount` 再 `mount(SourceControlViewComponent, { target: contentEl, props: { plugin, view: this } })`（Svelte 5 API），`onClose()` 只 `unmount`。`components/` 里的 `view` prop 类型就是这个 `GitView`，它们通过 `view.app` / `view.leaf` / `view.plugin` 取依赖；`GitView` 还实现了 `HoverParent`（`hoverPopover` 字段）以支持悬停预览。
- `sourceControl.svelte`：根组件，Props `plugin`、`view: GitView`。约 1100 行，其中约 150 行是 `<style lang="scss">`。
  - 本地状态：`status: Status | undefined`、`lastPulledFiles`、四棵树 `changeHierarchy` / `stagedHierarchy` / `conflictHierarchy` / `lastPulledFilesHierarchy`（`StatusRootTreeItem`）、四个折叠开关 `changesOpen` / `stagedOpen` / `lastPulledFilesOpen` / `conflictsOpen`（默认全开）、四个目录折叠字典 `stagedClosed` / `unstagedClosed` / `conflictsClosed` / `pulledClosed`（`bind:closed` 传给 `TreeComponent`）、`conflictCounts`、`unPushedCommits`、`loading`、`repositoryMissing`、`setupInProgress`、`mergeInProgress`。`commitMessage` 与 `showTree` 声明为 `$derived(plugin.settings.…)` 但会被重新赋值（textarea 绑定 / 切换按钮 / 提交后重置），实际当可写初值用。
  - `refresh()`：`!plugin.gitReady` → 清空 `status` 返回；否则 `unPushedCommits = await plugin.getUnpushedCommits()`、拷贝 `cachedStatus`，`plugin.lastPulledFiles` 引用变化时重建 pulled 树，对 `status.changed` / `status.staged` 原地排序，用 `plugin.gitManager.getTreeStructure(files, plugin.settings.limitToVault ? "vault" : "repository")` 建 changed / staged / pulled 树；冲突树用 `status.conflicted` 映射成 `{ path, vaultPath, index: "U", workingDir: "U" }`，不传第二个参数；最后 `await updateConflictCounts()`。
  - 冲突计数：`updateConflictCounts(path?)` 用 `conflictCountUpdate` 这条 Promise 链串行化（注释：避免并发保存覆盖较新的计数），`performConflictCountUpdate` 经 `vault.adapter.read(getRelativeVaultPath(path))` 读文件，`countConflictSections` = 匹配 `/^<{7}/gm` 的行数，读失败（某一侧已删除）计 0。完整刷新重算全部冲突文件；vault `modify` 事件只重算被改的那个。`sortedConflicts`：计数为 0（已解决）的排前面，再按 `localeCompare`。
  - 提交：`getCommitActionDescription` / `canCommit(mode)` / `canCommitAndSync(mode)` 决定两个按钮的禁用和 `aria-label`（有冲突一律禁止；`"staged"` 要有暂存、`"all"` 要有任意改动、`"smart"` = `mergeInProgress || 有暂存 || (settings.autoStageOnEmptyIndex && 有修改)`；`CommitMode` 类型在 `src/types`）。`commit()`、`amendStaged()`（`mode: "staged", amend: true`）、`commitAndSync()` 调 `plugin.gitActions.commit` / `commitAndSync`，成功后 `commitMessage = plugin.settings.commitMessage`，`.finally(triggerRefresh)`；`showCommitMenu` 用 `Menu.forEvent` 弹出「Commit staged / Stage all and commit / Amend staged / Commit staged and sync」。其余动作：`stageAll` / `unstageAll` / `push` / `pull` / `discard`（`gitActions.discardAll()`）、`runSetupAction`（`createNewRepo` / `cloneNewRepo`，`setupInProgress` 防重入）。
  - `onMount`：`view.registerEvent` 订阅 `obsidian-git:loading-status`（置 `loading`）、`obsidian-git:status-changed`（`refresh()`）、`obsidian-git:repository-state-changed`（更新 `repositoryMissing` 并 `refresh()`）；`vault.on("modify")` 对已冲突文件做增量计数，返回的清理函数里 `vault.offref`；`cachedStatus` 为空时调 `view.plugin.refresh()`，否则本地 `refresh()`；`view.scope = new Scope(plugin.app.scope)` 并注册 `Ctrl+Enter` → `commitAndSync()`。
  - 模板：`repositoryMissing` 时显示「No Git repository found.」+ Initialize / Clone 按钮，并用样式隐藏工具栏、提交框和文件区；工具栏 `#backup-btn`（提交并同步）、`#commit-btn`、`#commit-menu`、`#stage-all`、`#unstage-all`、`#push`、`#pull`、`#layoutChange`、`#refresh`，`mergeInProgress` 时多一个 `#merge-status`（点击 `plugin.openMergeConflictHelp()`）；提交框（行数随换行数增长，非空时带清除按钮）；文件区依次是 Conflicts（有冲突才出现）、Staged Changes、「Staged outside vault」/「Conflicts outside vault」两个只显示计数的行、Changes、Recently Pulled Files（`lastPulledFiles` 非空才出现）。每个区块 `showTree` 为真用 `TreeComponent`（`fileType` 分别为 `FileType.conflicted` / `staged` / `changed` / `pulled`，只有冲突区传 `conflictCounts`），否则平铺对应的 `*FileComponent`。

## 3. 子目录导航

- `components/`：见 `components/.frac.md`；递归目录树 `treeComponent` 加 staged / changed / pulled / conflict 四种文件行和「超过 500 个」提示行，入口是 `treeComponent.svelte`。本层在平铺模式下也直接使用其中的叶子组件和 `TooManyFilesComponent`。未暂存 / 已暂存文件行的主点击经 `plugin.tools.openDiff` 打开 diff（二进制文件则直接打开 vault 文件），右键走文件菜单。

## 4. 本层约束 / 约定 / 禁忌

- `buttons[]` 的下标是写死的：0 `#backup-btn`、1 `#commit-btn`、2 `#stage-all`、3 `#unstage-all`、4 `#push`、5 `#pull`、6 `#layoutChange`、7 `#refresh`、8 Staged 区的 Unstage、9 Changes 区的 Stage、10 `#commit-menu`、11 `#merge-status`（条件渲染）。图标由 `$effect` 里 `setIcon(btn, btn.getAttr("data-icon")!)` 填充，`#layoutChange` 点击时还会手动 `setIcon`；新增按钮要同时加 `data-icon` 与下标，并让别的下标不冲突。
- 推送按钮高亮（`unPushedCommits > 0`）在 `$effect` 里按平台分叉：移动端给按钮加 `button-border`，桌面端给其首个子元素（`setIcon` 生成的图标）设 `color` 属性为 `var(--text-accent)`；该 effect 的注释说明「设置变更触发视图 reload 时按钮首次为 null」，所以必须判空。这是本层唯一的 `Platform.isMobile` 分支。`Ctrl+Enter` 用的是字面 `"Ctrl"`，不是 `"Mod"`。
- 按 Obsidian `Component.registerEvent` 语义，`view.registerEvent(...)` 注册的三个 workspace 监听属于 `GitView`（视图卸载才解除），而不是 Svelte 组件；`reload()` 只 `unmount` 组件，不会解除上一轮挂载留下的监听，重复 `reload()` 会叠加，旧监听的闭包还指向已卸载组件的状态。新增监听若要跟随组件生命周期，照 `vault.on("modify")` 的写法：在 `onMount` 返回的清理函数里手动 `offref`。
- 「500」上限在本层平铺模式又写死两次（`arrayProxyWithNewLength(status.staged / status.changed, 500)`），与 `components/` 里的上限必须同步改。平铺的 Recently Pulled 列表和平铺的冲突列表没有套 `arrayProxyWithNewLength`：Pulled 平铺时全量渲染，之后 `TooManyFilesComponent` 在超过 500 个时仍会再显示「And N more files」，文案与实际渲染不符。
- 多数动作开头置 `loading = true`（`discard` 不置），复位只发生在 `refresh()` 里（含 `!gitReady` 分支）；`refresh()` 没有 `try/finally`，`getUnpushedCommits` 或建树抛错会让转圈一直保留，调用处只 `.catch(console.error)`，不走 `displayError`。
- 计数口径：`stagedCount = status.staged.length + status.stagedOutsideVault`，`hasConflicts` 把 `conflictedOutsideVault` 计入，因此 vault 外的暂存 / 冲突文件会影响提交按钮是否可用，但界面上只显示一行计数，没有文件列表。
- 排序比较器左侧取 `vaultPath` 最后一段，右侧取 `getDisplayPath(b.vaultPath)`，两侧口径不同；`status.changed` / `status.staged` 是被原地排序的。
- `showTree` 来自 `plugin.settings.treeStructure`，切换按钮写回设置并 `plugin.saveSettings()`；本层不监听设置变化，设置变更靠 `GitView.reload()` 整体重挂载来同步（见上面 `$effect` 的注释），所以别处改了这个设置，已打开的视图在 `reload()` 前不会跟着变。
- 冲突计数只数行首 `<<<<<<<`，读不到文件（含一侧删除）按 0 处理，会显示成「已解决」；这是传给 `components/` 的 `conflictCounts` 的唯一来源。
- 样式在本文件 `<style>` 里（scoped）：`.conflicts` 用 `--text-warning` 整体染色，并用 `:global(.topLevel …)` 穿透到子组件 `TreeComponent` 的 `.topLevel` 根节点，改 `treeComponent` 的 `topLevel` 类名要同步；提交框清除按钮用 `mask-image` 内联 SVG。文案全部硬编码英文，无 i18n。

## 5. 什么时候需要下钻

- 改某类文件行 / 目录树的外观、按钮、点击、折叠：先读 `components/.frac.md`，再进对应 `.svelte`。
- 改提交 / 推送 / 拉取 / 暂存 / 丢弃的实际行为：不在本层，在 `plugin.gitActions`（及其背后的 `GitManager` 两个后端）；本层只决定按钮状态与入队。
- 改状态数据怎么来（`cachedStatus`、`lastPulledFiles`、`getUnpushedCommits`、各 `obsidian-git:*` 事件何时触发）：不在本层，看 `src/main.ts`（刷新编排，见 `AGENTS.md`）与 `GitManager`；改 `Status` / `CommitMode` / `FileType` 类型：`src/types`。
- 改合并冲突的帮助文案或入口：本层只有 `#merge-status` 按钮调 `plugin.openMergeConflictHelp()`，弹窗内容不在本层。
- 改树结构的构造（`getTreeStructure` 的 `"vault"` / `"repository"` 模式）：`GitManager` 的实现，不在本层。
