# .frac.md — src/ui/sourceControl

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

Source Control 侧边视图：Conflicts / Staged / Changes / Recently Pulled 四个文件区块、提交信息框、工具栏。`sourceControl.ts` 是 `ItemView` 外壳，`sourceControl.svelte` 是挂在其 `contentEl` 里的 Svelte 5 根组件，拥有本视图全部状态；文件行与目录树交给 `components/`。

数据权威在插件（`cachedStatus`、`lastPulledFiles` 等），本层只在 `refresh()` 里拷成本地 `$state` 并建树。

## 2. 直属文件

- `sourceControl.ts`：`GitView`（`ItemView` + `HoverParent`）。`onOpen` → `reload()`：先 `unmount` 再 `mount` 根组件，传入 `plugin` 与 `view: this`；`onClose` 只 `unmount`。子组件的 `view` 就是它。
- `sourceControl.svelte`：根组件，带自己的 scoped 样式。`refresh()` 拷贝插件状态、排序、经 `gitManager.getTreeStructure` 建四棵树，由 `obsidian-git:status-changed` 等事件驱动；`conflictCounts` 由它读文件、数冲突标记得出。
  - 所有改仓库的动作都走 `plugin.promiseQueue.addTask(() => plugin.gitActions.xxx())`；提交按钮能否点由 `canCommit` / `canCommitAndSync` 决定。
  - 没有仓库时只显示 Initialize / Clone；每个区块 `showTree` 为真用 `TreeComponent`，否则直接平铺 `components/` 里的 `*FileComponent`。

## 3. 子目录导航

- `components/`：见 `components/.frac.md`；递归目录树与四种文件行、「超出上限」提示行。

## 4. 本层约束 / 约定 / 禁忌

- 工具栏图标靠 `buttons[]` 的写死下标；新增按钮要同时加 `data-icon` 和不冲突的下标。
- `view.registerEvent` 的监听属于 `GitView`，卸载视图才解除；`reload()` 只 `unmount` 组件，重复 `reload()` 会叠加监听。跟随组件生命周期的监听，照 `vault.on("modify")` 在 `onMount` 清理函数里 `offref`。
- 动作置 `loading = true`，只有 `refresh()` 复位且没有 `try/finally`：建树抛错会让转圈一直保留。
- 渲染条目上限在平铺模式又写死两次，要与 `components/` 同步；平铺的 Pulled 与冲突列表没套上限，提示会与实际渲染不符。
- `conflictCounts` 只数行首 `<<<<<<<`，读不到文件（含一侧删除）按 0，显示成「已解决」。
- `showTree` 来自 `settings.treeStructure`；本层不监听设置变化，已打开的视图要 `reload()` 才同步。
- `.conflicts` 样式用 `:global(.topLevel …)` 穿透到 `TreeComponent` 根节点，改 `topLevel` 类名要同步。

## 5. 什么时候需要下钻

- 改文件行 / 目录树的外观、按钮、点击、折叠：先读 `components/.frac.md`。
- 改提交 / 推送 / 暂存 / 丢弃的实际行为：`plugin.gitActions` 与 `GitManager`，不在本层。
- 改状态数据来源、事件触发时机、视图注册：`src/main.ts`；类型在 `src/types`。
