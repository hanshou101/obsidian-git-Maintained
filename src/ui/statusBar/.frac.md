## 1. 本目录是什么

状态栏里「当前分支名」这一小块的包装类，只有一个文件、一个类。它不创建状态栏元素：`HTMLElement` 和 `ObsidianGit` 实例都由调用方传入（创建、刷新、销毁的时机不在本层；插件生命周期与清理归 `src/main.ts`，见 `AGENTS.md`）；也不订阅任何事件，何时刷新由调用方决定。
本目录没有 Svelte、没有子目录，也不含 Git 逻辑：取分支走 `plugin.gitManager.branchInfo()`，切换分支走 `plugin.gitActions.switchBranch()`。

## 2. 直属文件

- `branchStatusBar.ts`：`export class BranchStatusBar`，构造 `(private statusBarEl: HTMLElement, private readonly plugin: ObsidianGit)`。
  - 构造时给元素加 `mod-clickable` class，并用 `statusBarEl.onClickEvent` 绑定点击：`plugin.promiseQueue.addTask(() => plugin.gitActions.switchBranch())`，即点击分支名发起切换分支，经 `PromiseQueue` 串行化。
  - `display()`（async）：`plugin.gitReady` 为真时取 `await plugin.gitManager.branchInfo()`，`current` 有值就 `setText(current)`，否则 `empty()`；`gitReady` 为假也 `empty()`。只显示分支名文本，不显示 ahead / behind、图标或错误。
  - `remove()`：`statusBarEl.remove()`，移除整个元素。

## 4. 本层约束 / 约定 / 禁忌

- 刷新是被动的：类里没有事件订阅、定时器或 `registerEvent`，分支变化后必须由调用方再调 `display()`，否则文字不会更新。
- 点击监听用的是 `onClickEvent`，没有经过 `registerDomEvent` / `Component`，也没有单独的解绑；清理只有 `remove()` 一个入口，要靠调用方在卸载路径里调用。新增订阅或定时器时，要自己提供清理入口，并让调用方在普通卸载和设置重载（`unloadPlugin` 再 `init`）两条路径里都调用（`AGENTS.md` 的要求）。
- `display()` 没有 `try/catch`：`branchInfo()` 抛错会直接向调用方传播，由调用方负责 `displayError` / 兜底；不要在这里吞掉 Git 错误。
- 点击切换分支必须保持走 `promiseQueue.addTask`，不要直接调 `gitManager`，以免和其他 Git 操作并发。
- 类本身没有平台判断（无 `Platform` 分支）；是否在移动端创建这个状态栏项、创建几次，是调用方的事。
- 文本直接来自 `branchInfo().current`，没有 i18n，也没有长度截断。

## 5. 什么时候需要下钻

- 改状态栏显示内容 / 格式：只改 `branchStatusBar.ts` 的 `display()`。
- 改点击后的行为（如何选分支、checkout 流程）：不在本层，看 `plugin.gitActions.switchBranch` 的实现。
- 改何时创建 / 刷新 / 销毁这个状态栏项：不在本层；按类名搜索 `BranchStatusBar` 找调用点，生命周期与清理总体归 `src/main.ts`（见 `AGENTS.md`）。
