# .frac.md — src/ui/statusBar

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

状态栏里「当前分支名」这一小块的包装类，只有一个文件、一个类。它不创建状态栏元素：`HTMLElement` 和 `ObsidianGit` 实例都由调用方（`src/main.ts`）传入，创建、刷新、销毁的时机不在本层，也不订阅任何事件。

没有 Svelte、没有子目录，也不含 Git 逻辑：取分支走 `plugin.gitManager.branchInfo()`，切换分支走 `plugin.gitActions.switchBranch()`。

## 2. 直属文件

- `branchStatusBar.ts`：`BranchStatusBar`。构造时给元素加 `mod-clickable` 并绑定点击，点击经 `plugin.promiseQueue` 发起 `switchBranch()`。`display()` 在 `gitReady` 时显示当前分支名，否则清空，不显示 ahead / behind 或错误。`remove()` 移除整个元素。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 刷新是被动的：类里没有事件订阅、定时器或 `registerEvent`，分支变化后必须由调用方再调 `display()`，否则文字不会更新。
- 点击监听用 `onClickEvent`，没有经过 `registerDomEvent` / `Component`，清理只有 `remove()` 一个入口，要靠调用方在卸载路径里调用。新增订阅或定时器时，要自己提供清理入口，并让调用方在普通卸载和设置重载两条路径都调用（见 `AGENTS.md`）。
- `display()` 没有 `try/catch`：`branchInfo()` 抛错会向调用方传播，由调用方负责 `displayError`；不要在这里吞掉 Git 错误。
- 点击切换分支必须保持走 `promiseQueue.addTask`，不要直接调 `gitManager`，以免和其他 Git 操作并发。
- 类本身没有平台判断；是否在移动端创建、创建几次，是调用方的事。文本没有 i18n，也没有长度截断。

## 5. 什么时候需要下钻

- 改状态栏显示内容 / 格式：只改 `branchStatusBar.ts` 的 `display()`。
- 改点击后的行为（选分支、checkout 流程）：看 `plugin.gitActions.switchBranch`。
- 改何时创建 / 刷新 / 销毁这个状态栏项：按类名搜索 `BranchStatusBar` 找调用点，生命周期与清理归 `src/main.ts`。
