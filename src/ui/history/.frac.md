# .frac.md — src/ui/history

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

Git History 侧边视图：`historyView.ts` 是 `ItemView` 外壳，`historyView.svelte` 是挂在其 `contentEl` 里的 Svelte 5 根组件，负责提交列表的加载、分页、刷新和布局切换；每条提交怎么画交给 `components/`。

本层拥有全部数据与状态，子组件只收一条 `log`，不自行取数。提交经 `plugin.gitManager.log(...)` 取得，不区分后端。

## 2. 直属文件

- `historyView.ts`：`HistoryView`（`ItemView` + `HoverParent`）。`onOpen` → `reload()`：先 `unmount` 再 `mount` 根组件，传入 `plugin` 与 `view: this`；重载会丢掉全部组件状态并重新取数。`onClose` 只 `unmount`。
- `historyView.svelte`：根组件，状态 `logs` / `loading` / `showTree`。`refresh()` 整体重取并保持已加载条数；`appendLogs()` 是无限滚动，`IntersectionObserver` 观察 `#sentinel`。头部按钮：`#layoutChange` 翻转 `showTree` 并写回 `settings.treeStructure`，`#refresh` 手动刷新。

## 3. 子目录导航

- `components/`：见 `components/.frac.md`；提交行、目录树、文件行三个组件，入口是 `logComponent.svelte`。

## 4. 本层约束 / 约定 / 禁忌

- 分页大小按后端区分：`instanceof SimpleGit`（桌面原生 Git）与 isomorphic-git（移动端）取值不同，判断依据是后端类型而非 `Platform.isMobile`；改它要按两种后端分别考虑。
- 下一页以最后一项的 `hash` 为起点并丢弃返回的第一项（它就是当前最后一项）；不要改成 `hash^`，首个提交会失败。
- `refresh()` 与 `appendLogs()` 没有互斥，交错执行时追加结果会接到新数组后面；两者都没有 `try/finally`，`gitManager.log` 抛错会让 `loading` 一直为 true，错误只 `console.error`。
- `showTree` 只在组件创建时读一次设置；别处改了设置，已打开的 History 视图要 `reload()` 才同步。
- 哨兵靠全局 `activeDocument.querySelector("#sentinel")` 在 `onMount` 里取，不是 `bind:this`；popout 窗口或同 id 元素可能让无限滚动静默失效。
- 取数触发只有四个：初始化、`obsidian-git:head-change`、刷新按钮、滚动到哨兵。新增事件、observer、定时器都要放进 `onMount` 返回的清理函数，否则 `reload()` 会累积。

## 5. 什么时候需要下钻

- 改单条提交或文件行的外观、点击、tooltip、作者 / 日期显示：读 `components/.frac.md`。
- 改提交取数（`log` 的参数含义、起点、两个后端的差异）：看 `src/gitManager`。
- 改 `treeStructure` 等设置本身：`src/setting/`；改视图注册、`obsidian-git:head-change` 的触发时机：`src/main.ts`。
