## 1. 本目录是什么

Git History 侧边视图：`historyView.ts` 是 Obsidian `ItemView` 外壳，`historyView.svelte` 是挂在它 `contentEl` 里的 Svelte 5 根组件，负责提交列表的加载、分页、刷新和布局切换；每一条提交怎么画交给子目录 `components/`。
本层拥有全部「数据与状态」：`logs`（`LogEntry[]`）、`loading`、`showTree`；子组件只接收一条 `log` 加 `view` / `plugin` / `showTree`，不自行取数。
视图类型、名称、图标来自 `src/constants` 的 `HISTORY_VIEW_CONFIG`；视图注册归 `src/main.ts`（见 `AGENTS.md`），不在本层。
提交数据经 `plugin.gitManager.log(...)` 取得（通过 `GitManager` 抽象调用，不区分后端）；本层唯一的后端判断是 `plugin.gitManager instanceof SimpleGit`，用来决定分页大小。

## 2. 直属文件

- `historyView.ts`：`export default class HistoryView extends ItemView implements HoverParent`。构造 `(leaf, plugin)`，字段 `plugin`、`hoverPopover: HoverPopover | null`（`HoverParent` 要求）、私有 `_view`（已挂载的 Svelte 实例）。`onOpen()` → `reload()`；`reload()` 先 `unmount(_view)` 再 `mount(HistoryViewComponent, { target: this.contentEl, props: { plugin, view: this } })`，因此重载会丢掉全部组件状态（`logs`、折叠状态）并重新取数；`onClose()` 只做 `unmount`。使用 Svelte 5 的 `mount` / `unmount` API。`view: this` 让子组件能取 `view.app` / `view.leaf` / `view.plugin`。
- `historyView.svelte`：根组件。Props：`plugin`（声明为 `$bindable()`，但 `mount` 以普通 prop 传入）、`view: HistoryView`。
  - 状态：`logs`（`undefined` = 未加载或 git 未就绪）、`loading`、`showTree = $state(plugin.settings.treeStructure)`（仅初始化时读取一次）。
  - 头部两个按钮：`#layoutChange`（图标 `list` / `folder`，点击翻转 `showTree`，手动 `setIcon`，写回 `plugin.settings.treeStructure` 并 `void plugin.saveSettings()`）和 `#refresh`（`refresh-cw`，`class:loading`，调 `triggerRefresh`）。图标由 `$effect` 里 `setIcon(btn, btn.getAttr("data-icon")!)` 填充 `buttons[]`。
  - `refresh()`：`!plugin.gitReady` → `logs = undefined` 直接返回；否则 `gitManager.log(undefined, false, limit)`，首次 `limit` 为 `SimpleGit` 50 / 其余 10，之后 `limit = logs.length`（刷新后保持已加载条数）。组件初始化时立即调用一次，并监听 `workspace` 事件 `obsidian-git:head-change`（`onMount` 里注册，返回函数里 `offref`）。
  - `appendLogs()`：无限滚动。`gitManager.log(undefined, false, limit, logs.last()?.hash)`，`limit` 同样 `SimpleGit` 50 / 其余 10，然后 `logs.push(...newLogs.slice(1))`——丢弃第一项，因为它就是当前最后一项（源码注释：不能用 `hash^`，首个提交会失败）。触发方是 `IntersectionObserver`，观察 `#sentinel`，条件 `isIntersecting && !loading`。
  - 渲染：`{#if logs}` → `<div class="tree-item nav-folder mod-root">` 内 `{#each logs as log}`（无 key）渲染 `<LogComponent {view} {showTree} {log} {plugin} />`；之后是 `#sentinel` 和一个 40px 的底部占位（让哨兵不被浮在上面的状态栏遮住，也标示列表结束）。`<style>` 块为空。

## 3. 子目录导航

- `components/`：见 `components/.frac.md`；一条提交的折叠行 `logComponent`、目录树 `logTreeComponent`、变更文件行 `logFileComponent`，入口是 `logComponent.svelte`，props 为 `log` / `view` / `showTree` / `plugin`。文件行的主点击经 `plugin.tools.openDiff` 打开该提交的 diff（二进制文件则直接打开 vault 文件），行内「Open file at this commit」按钮调 `plugin.tools.openFileAtCommit`，右键走文件菜单。

## 4. 本层约束 / 约定 / 禁忌

- 分页大小按后端区分：`instanceof SimpleGit`（桌面原生 Git）为 50，否则（isomorphic-git，移动端）为 10；判断依据是后端类型而不是 `Platform.isMobile`。改这个数字或判断要按两种后端分别考虑。
- `refresh()` 与 `appendLogs()` 没有互斥：只有 observer 回调检查 `!loading`，两者可交错执行——`appendLogs` 的 `await` 期间若 `refresh` 替换了 `logs`，追加结果会接到新数组后面。两者都不用 `try/finally`，`gitManager.log` 抛错时 `loading` 会一直为 true，错误只 `console.error`，不走 `displayError`。
- `showTree` 只在组件创建时读一次 `plugin.settings.treeStructure`，之后靠本层按钮写回；别处改了该设置，已打开的 History 视图要 `reload()` 才会同步。
- 哨兵通过全局 `activeDocument.querySelector("#sentinel")` 在 `onMount` 里取得，不是 `bind:this`；多窗口（popout）或页面里有同 id 元素时可能取不到 / 取错，导致无限滚动静默失效。
- 死代码：`layoutBtn` 声明了且有一个 `$effect` 去 `empty()` 它，但没有任何 `bind:this` 给它赋值。
- 本层的取数触发只有四个：组件初始化、`obsidian-git:head-change`、刷新按钮、滚动到哨兵；这里没有订阅 `obsidian-git:status-changed`。分页以最后一项的 `hash` 为起点并丢弃返回的第一项，源码注释明确不能改用 `hash^`（首个提交会失败）。
- 视图生命周期：`onClose` / `reload` 必须 `unmount`，Svelte 组件内注册的 `workspace` 事件靠 `onMount` 的清理函数释放；新增的事件、observer、定时器都要放进 `onMount` 返回的清理函数里，否则 `reload()` 会累积。
- 文案（`Change Layout`、`Refresh`）硬编码英文。

## 5. 什么时候需要下钻

- 改单条提交或文件行的外观、点击行为、tooltip、作者 / 日期显示：读 `components/.frac.md`，再进对应 `.svelte`。
- 改提交取数（`log` 的参数含义、`limit`、起点 `hash`、桌面与移动实现差异）：不在本层，看 `src/gitManager`（契约与两个后端）。
- 改 `treeStructure` / `authorInHistoryView` / `dateInHistoryView` / `commitDateFormat` 这些设置本身：`src/setting/`。
- 改视图注册、`obsidian-git:head-change` 的触发时机：`src/main.ts`。
