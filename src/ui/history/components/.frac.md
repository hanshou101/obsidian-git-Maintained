# .frac.md — src/ui/history/components

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

History 侧边视图里「一条提交怎么画」的三个 Svelte 5 组件：提交行（可折叠）→ 变更文件树或扁平文件列表 → 单个变更文件行。

本层不拥有提交列表、分页、加载状态，只接收一条 `LogEntry`，经 `view`（`HistoryView`）和 `plugin` 回调插件。入口是 `logComponent.svelte`；没有 `.ts` 文件。

## 2. 直属文件

- `logComponent.svelte`：一条提交的折叠行，默认折叠。标题行显示 refs、作者、日期、message，作者与日期受 `authorInHistoryView` / `dateInHistoryView` / `commitDateFormat` 控制。展开后 `showTree` 为真渲染 `LogTreeComponent`，否则平铺 `LogFileComponent`。
- `logTreeComponent.svelte`：递归目录树。叶子（`entity.data` 有值）渲染 `LogFileComponent`；目录点击翻转 `closed[item.path]`，未折叠时递归渲染自身。
- `logFileComponent.svelte`：单个变更文件行。主点击：二进制文件打开 vault 文件，其余经 `plugin.tools.openDiff` 开 diff；右键走文件菜单。图标按钮：`go-to-file` 打开文件，`file-clock` 经 `plugin.tools.openFileAtCommit` 看该提交处的文件。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 折叠默认值相反：提交行默认折叠，目录 `closed[path]` 缺省为展开。`closed` 由 `logComponent` 持有（折叠提交再展开，目录折叠状态保留），经 `bind:closed` 逐层下传，不要在子层另建副本；键是 `TreeItem.path`，不是 `vaultPath`。
- 图标由 `$effect` 里 `setIcon` 按 `data-icon` 填充，元素来自 `bind:this={buttons[i]}`；给 `logFileComponent` 新增图标按钮，`data-icon` 与 `buttons[n]` 缺一不可。
- 「打开 / diff」的分流依据是 `fileIsBinary(diff.path)`（按路径），`file-clock` 另查 `DiffFile.binary` 并排除已删除文件；两处口径不同，改其一要看另一处。
- diff 的 A 侧恒为 `hash^`（重命名取旧路径），本层不处理「根提交没有父提交」。
- 不判断平台，没有 desktop / mobile 分支；异步失败走 `plugin.displayError`。
- 外观基本不在本层：`git-ref`、`git-author`、`git-tools` 等类名的样式在根目录 `styles.css`。类名沿用 `tree-item` / `nav-folder` / `nav-file` 以继承主题，不要随意改名。

## 5. 什么时候需要下钻

- 改提交行显示：`logComponent.svelte`；设置项在 `src/setting/`。
- 改文件行点击、右键菜单、按钮：`logFileComponent.svelte`，并追到 `src/utils` 和 `plugin.tools`。
- 改目录树的构造：`plugin.gitManager.getTreeStructure`，不在本层。提交列表怎么取、何时重绘、`showTree` 由谁决定：看 `../.frac.md`。
