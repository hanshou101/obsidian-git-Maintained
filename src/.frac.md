## 1. 本目录是什么

插件源码总入口，由 Vite（根目录 `vite.config.mjs`）从 `main.ts` 打成根目录的 `main.js`。直属文件负责插件生命周期、命令、Git 动作编排、自动化定时、设置类型与默认值；Git 后端、编辑器集成、设置页和界面各在一个子目录。
- 后端二选一：`main.ts` 的 `useSimpleGit` 就是 `Platform.isDesktopApp`，桌面用 `SimpleGit`（本机 git），移动用 `IsomorphicGit`（isomorphic-git，经 Obsidian adapter 与 `requestUrl`），见 `gitManager/.frac.md`。
- 维护版在本层改的是 `gitActions.ts` 的 `performCommit`、`types.ts`、`constants.ts`（设置 `manualCommitUsesAutoCommitGlobs`），以及 `main.ts` 的 `onload` / `onunload` / `loadSettings` 和 `types.ts` 的 `App.plugins`（插件 id 改成 `git-maintained` 后，处理同一 vault 里的官方插件）；手机推送重传历史的修复不在源码里，在根目录 `patches/`。

## 2. 直属文件

- `main.ts`：默认导出 `ObsidianGit`（Plugin），也是 `main.js` 唯一的导出（Vite 配置 `exports: "default"`，多加具名导出会让构建失败）。持有 `gitActions`、`gitManager`、`automaticsManager`、`tools`、`localStorage`、`gitServerPassword`、`stockPlugin`、`promiseQueue`、`editorIntegration`、状态栏与 `state`（operation / offlineMode / mergeInProgress）。`onload` → `init()` 建后端并检查仓库，`gitReady` 为真后才启动自动化。维护版：`onload` 一开始若 `stockPlugin.isEnabled()`（官方插件 `obsidian-git` 也启用着），弹常驻通知、记 `stoppedForStockPlugin` 并直接返回，什么都不注册，`onunload` 据此跳过 `unloadPlugin()`；`loadSettings` 在自己没有 `data.json` 时用 `stockPlugin.importSettings()` 接手官方设置，接手后立刻 `saveData` 并弹通知。`unloadPlugin()` + `init({ fromReload: true })` 是设置重载路径。`updateCachedStatus()` 每次都全量 `gitManager.status()`（移动端大仓库要几秒）。`displayMessage` / `displayError` / `handleConflict` / `handleNoNetworkError` 是统一的出错与通知出口。
- `gitActions.ts`：`GitActions`，所有面向用户的 Git 动作（clone、commit、commit-and-sync、pull、push、设上游、编辑 remote 等）。公开方法都包在 `runReadyGitAction`（未就绪不跑）与 `gitAction.ts` 的结果类型里，真正逻辑在 `perform*`。commit-and-sync 顺序：(`syncMethod` 为 reset 时先拉) → 提交 → 拉（移动端只会合并）→ 推。`performCommit` 里自动提交用 auto commit globs 挑文件；维护版加了 `useGlobs = fromAuto || settings.manualCommitUsesAutoCommitGlobs`，让手动提交走同一份选择（只有 `mode` 是 staged 时不挑；用户自己暂存的文件照样提交）。
- `gitAction.ts`：`GitActionResult<T>`（success / failed / cancelled）、`GitActionHost` 和 `runGitAction`：捕获错误后按类型分派给 host（冲突、无网络、isomorphic-git 的 `UserCanceledError` 记为 cancelled），并刷新缓存状态。
- `automaticsManager.ts`：自动 commit-and-sync / pull / push 的定时器；上次执行时间存在 localStorage，重启后按剩余时间续上；「停笔后再提交」用 `plugin.autoCommitDebouncer`。自动 commit-and-sync 调 `gitActions.commitAndSync({ fromAutoBackup: true, mode: "all" })`，经 `promiseQueue` 排队。
- `autoCommitGlobs.ts`：解析 auto commit globs 设置（一行一个，去掉首尾空白与空行；圆括号按 git 的字面含义转义），并产生匹配器与路径选择器（Include / Exclude）；移动端靠它在暂存前自己筛文件，桌面端直接把 pathspec 交给 git。
- `promiseQueue.ts`：`PromiseQueue`，Git 动作一个接一个跑；`addTask(task, onFinished)` 不回传 promise，要等结果就传 `onFinished`。
- `coalesce.ts`：把并发调用合并成「当前这次 + 至多一次后续」，用于刷新类任务。
- `commands.ts`：`addCommmands`（原拼写）注册约 40 个命令；命令 id 发布后不能改（例如 `push` 是 Commit-and-sync）。Obsidian 会在前面加插件 id，所以维护版的完整命令 id 是 `git-maintained:push` 这样（官方版是 `obsidian-git:push`），命令面板显示「Git (Maintained): …」。
- `types.ts`：`ObsidianGitSettings`（含维护版的 `manualCommitUsesAutoCommitGlobs`）、`declare module "obsidian"` 里补的私有 API 类型（维护版加了 `App.plugins?.enabledPlugins?`）、`CommitMode`、`Status` / `FileStatusResult` 等跨后端数据类型、错误类（`GitConflictError`、`NoNetworkError`）与 `mergeSettingsByPriority`。
- `constants.ts`：`DEFAULT_SETTINGS`（`manualCommitUsesAutoCommitGlobs: false`，即上游行为）、各视图的 type/name/icon 配置、日期格式、Windows git 默认路径与 askpass 脚本名。
- `statusBar.ts`：`StatusBar`，显示当前操作、进度、离线与合并中状态，以及距上次提交的时间。
- `tools.ts`：`Tools`，大文件检查（`performCommit` 暂存前调用）、打开 diff、在某个提交打开文件、执行原始 git 命令。
- `openInGitHub.ts`：按 remote URL 在 GitHub 打开当前行或文件历史。
- `utils.ts`：零散工具（复数、文件菜单触发、颜色转换、时间与数组工具、`impossibleBranch` 穷尽检查）。
- `pluginGlobalRef.ts`：全局 `pluginRef`，给行作者 gutter 的右键菜单拿到插件实例。
- `externalLibTypes.d.ts`：`css-color-converter` 的不完整类型声明。

- `ui/`：见 `ui/.frac.md`；History / Source Control / diff / 只读文件视图、对话框和分支状态栏，Svelte 5 + TS 外壳。

## 4. 本层约束 / 约定 / 禁忌

- 改 Git 语义要同时顾两个后端：先改 `gitManager/` 的契约，再改两边实现；只在本机 git 上成立的改动不能直接用到移动端（`AGENTS.md`）。
- 会动工作区、索引或仓库状态的动作一律经 `promiseQueue`，不要另起并发。
- 对外路径一律 vault 相对，仓库相对路径只在 `gitManager/` 里流转。
- 视图类型、workspace 事件名（`obsidian-git:*`）、CSS 类名保持上游原样：已打开的面板在换成维护版后照样能用，也方便合并上游。
- 命令 id 和设置字段名一旦发布就不改；新设置要在 `types.ts`、`constants.ts`、`setting/settings.ts` 三处同时加，默认值保持上游行为。
- 改了会影响打包的东西，要 `pnpm run build` 并把 `main.js` 一起提交（维护版跟踪 `main.js`，见根目录 `MAINTENANCE.md`）。
