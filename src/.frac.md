## 1. 本目录是什么

插件源码总入口，由 Vite（根目录 `vite.config.mjs`）从 `main.ts` 打成根目录的 `main.js`。直属文件负责插件生命周期、命令、Git 动作编排、自动化定时、设置类型与默认值；Git 后端、编辑器集成、设置页和界面各在一个子目录。
- 后端二选一：`main.ts` 的 `useSimpleGit` 就是 `Platform.isDesktopApp`，桌面用 `SimpleGit`（本机 git），移动用 `IsomorphicGit`（isomorphic-git，经 Obsidian adapter 与 `requestUrl`），见 `gitManager/.frac.md`。
- 维护版在本层改的是 `gitActions.ts` 的 `performCommit`、`types.ts`、`constants.ts`（设置 `manualCommitUsesAutoCommitGlobs`），以及 `main.ts` 的 `onload` / `onunload` / `loadSettings` 和 `types.ts` 的 `App.plugins`（插件 id 改成 `git-maintained` 后，处理同一 vault 里的官方插件）；手机推送重传历史的修复不在源码里，在根目录 `patches/`。
- 手机同步（AME-1119）：本层新增 `syncSupervisor.ts`（监督器）与 `syncProblems.ts`（错误分类与中英文案），并小改 `gitAction.ts`、`gitActions.ts`、`main.ts`、`automaticsManager.ts`、`autoCommitGlobs.ts`、`commands.ts`、`types.ts`、`constants.ts`；弱网请求策略与拉取中断修复在 `gitManager/`，设置页在 `setting/`，同步状态视图在 `ui/`。所有新设置默认等于上游行为；只有 `weakNetworkMode` 或 `syncOnLeave` 开着时监督器才「动手」，见第 4 节。

## 2. 直属文件

- `main.ts`：默认导出 `ObsidianGit`（Plugin），也是 `main.js` 唯一的导出（Vite 配置 `exports: "default"`，多加具名导出会让构建失败）。持有 `gitActions`、`gitManager`、`automaticsManager`、`tools`、`localStorage`、`gitServerPassword`、`stockPlugin`、`syncSupervisor`（维护版）、`promiseQueue`、`editorIntegration`、状态栏与 `state`（operation / offlineMode / mergeInProgress）。`onload` → `init()` 建后端并检查仓库，`gitReady` 为真后才启动自动化。维护版：`onload` 一开始若 `stockPlugin.isEnabled()`（官方插件 `obsidian-git` 也启用着），弹常驻通知、记 `stoppedForStockPlugin` 并直接返回，什么都不注册，`onunload` 据此跳过 `unloadPlugin()`；`loadSettings` 在自己没有 `data.json` 时用 `stockPlugin.importSettings()` 接手官方设置，接手后立刻 `saveData` 并弹通知。手机同步（维护版）：`onload` 里 vault 的 modify / delete / create / rename 四个事件统一走 `onVaultChange(file, oldPath?)`——总是 `debRefresh()`，但只有 `syncSupervisor.noteVaultChange(…)` 返回真（自动提交能挑中的编辑，且不是拉取自己写的文件），或监督器没在管事（`!managing`）时，才触发 `autoCommitDebouncer`；另外 `registerView(SYNC_STATUS_VIEW_CONFIG.type, …)` 并调一次 `syncSupervisor.register()`。`init()` 在 Git 就绪、`automaticsManager.init()` 之后调 `syncSupervisor.start()`（自动化暂停时也调），`unloadPlugin()` 里调 `syncSupervisor.stop()`。`unloadPlugin()` + `init({ fromReload: true })` 是设置重载路径。`updateCachedStatus()` 每次都全量 `gitManager.status()`（移动端大仓库要几秒）。`displayMessage` / `displayError` / `handleConflict` / `handleNoNetworkError` 是统一的出错与通知出口。
- `gitActions.ts`：`GitActions`，所有面向用户的 Git 动作（clone、commit、commit-and-sync、pull、push、设上游、编辑 remote 等）。公开方法都包在 `runReadyGitAction`（未就绪不跑）与 `gitAction.ts` 的结果类型里，真正逻辑在 `perform*`。commit-and-sync 顺序：(`syncMethod` 为 reset 时先拉) → 提交 → 拉（移动端只会合并）→ 推。`performCommit` 里自动提交用 auto commit globs 挑文件；维护版加了 `useGlobs = fromAuto || settings.manualCommitUsesAutoCommitGlobs`，让手动提交走同一份选择（只有 `mode` 是 staged 时不挑；用户自己暂存的文件照样提交）。手机同步（维护版）：`commitAndSync` 外面包 `supervisor?.syncStarted(fromAutoBackup, reason)` / `await supervisor?.syncFinished(result)`（`CommitAndSyncOptions` 多了可选的 `reason: SyncReason`）；`runReadyGitAction(action, sync = false)` 在 `sync` 为真时（commit、commit-and-sync、push、pull 四个动作）把 `supervisor.observeError` 作为 `runGitAction` 的第三个参数；`recordCommit`（独立的 `commit()` 与 `performCommitAndSync` 里）、`recordPull`（`performPull`）、`recordPush`（`performPush`）记录结果。`performCommit` 开头先 `gitManager.recoverInterruptedPull()`（失败只 `plugin.log`，提交照常）和 `syncSupervisor?.beforeCommit()`，起始状态改由私有 `commitStatus(useGlobs, autoGlobs)` 取：只有 `useGlobs`、`autoCommitGlobMode === "include"`、后端是 `IsomorphicGit`、`syncSupervisor.managing` 同时成立，且 `includeGlobScope(globs)` 不是 `undefined` 时，才调 `IsomorphicGit.scopedStatus(scope)`（只扫 include glob 所在的目录），并手动 `setPluginState({ mergeInProgress })`、不更新 `plugin.cachedStatus`；否则照旧 `updateCachedStatus()` 全量扫描。
- `gitAction.ts`：`GitActionResult<T>`（success / failed / cancelled）、`GitActionHost` 和 `runGitAction`：捕获错误后按类型分派给 host（冲突、无网络、isomorphic-git 的 `UserCanceledError` 记为 cancelled），并刷新缓存状态。维护版给 `runGitAction` 加了可选的第三参数 `observeError(error): boolean`：先让它看到错误，返回真就跳过上面的上报（监督器自己展示）；观察者自己抛错只 `console.error`、按未处理继续上报；返回的 failed / cancelled 不受影响。
- `automaticsManager.ts`：自动 commit-and-sync / pull / push 的定时器；上次执行时间存在 localStorage，重启后按剩余时间续上；「停笔后再提交」用 `plugin.autoCommitDebouncer`。自动 commit-and-sync 调 `gitActions.commitAndSync({ fromAutoBackup: true, mode: "all" })`，经 `promiseQueue` 排队。维护版加了私有 getter `editDelay`——`autoSyncDelaySeconds > 0` 时是秒数 × 1000，否则是 `autoSaveInterval` 分钟——作为该 debouncer 的等待时间；debouncer 复用已有的，所以改了延迟要经 `reload("commit")` 重建才生效（设置页的 `AUTOMATIC_RELOADS` 就是这么接的），而且仍要求 `autoSaveInterval > 0` 且开着 `autoBackupAfterFileChange`。
- `autoCommitGlobs.ts`：解析 auto commit globs 设置（一行一个，去掉首尾空白与空行；圆括号按 git 的字面含义转义），并产生匹配器与路径选择器（Include / Exclude）；移动端靠它在暂存前自己筛文件，桌面端直接把 pathspec 交给 git。维护版加了 `includeGlobScope(globs)`：返回 include globs 能选中的全部文件所在的仓库相对路径（每个 glob 取开头的字面段并去掉转义，如 `notes/daily/*.md` → `notes/daily`），列表为空或某个 glob 的第一段含通配符（`*` `?` `[`）时返回 `undefined`（要遍历整棵树）；`gitActions.ts` 的 `commitStatus` 用它让自动提交只看这些文件夹。
- `syncSupervisor.ts`（维护版新增）：`SyncSupervisor`（`plugin.syncSupervisor`）。**始终记录**每次同步的历史（`SyncLogEntry`，最多 300 条）以及当前问题、最近成功 / 上传 / 拉取时间、后台联网判断，序列化成 JSON 存进 `localStorage.getSyncLog()` / `setSyncLog()`（本设备 local storage，不在 vault，所以不会被提交，重启后还在）；**只有 `managing`（`weakNetworkMode || syncOnLeave`）为真时才行动**。
  - 生命周期：`register()` 在 `onload` 里只调一次（`visibilitychange`、`online` / `offline`，以及存在时的 Capacitor `App` 插件的 `pause` / `resume`；Capacitor 一律从 `window.Capacitor.Plugins` 取，没有就静默跳过）；`start()` 每次 Git 就绪时调（读历史；`managing` 时建 ribbon 图标，只建一次、之后不移除；往 `promiseQueue` 排一个任务刷新 `commitsAhead`，`managing` 时若这是本次运行里第一次 `start()` 且有未上传提交就 `requestSync("startup")`，否则有可重试的旧问题就排重试）；`stop()` 在 `unloadPlugin()` 里调（清定时器、放开亮屏、存盘）。
  - 给视图用的状态：`snapshot()`（`phase`：syncing / attention / waiting / pending / idle；另有 `running`、`problem`、`nextRetryAt`、`pendingEdits`、`ahead`、`online`、`visible`、`background`（`unknown` / `allowed` / `blocked`，Android 是否在后台放行网络）、各时间戳、两个开关）、`entries`、`details()`（「复制详情」的纯文本）、`onChange` 订阅、`openView()`（复用已有叶子，没有就 `getLeaf(true)` 新开）、`text(zh, en)` / `language` / `reasonText`、`clearLog()`。`inBackground`（= 没在前台）跟随 Capacitor 的 `pause` / `resume`，二者先于 `visibilitychange`，所以比 `document.visibilityState` 早；`IsomorphicGit.network.isHidden()` 读它。
  - 触发：`noteVaultChange(vaultPath, oldPath?)` 返回这次 vault 事件是不是「自动提交能挑中的编辑」（`isCommitCandidate` 套 `autoCommitGlobMode` / `autoCommitGlobs`；`expectWrites` 登记的拉取回声不算，登记后 30 s 内同一路径的第一次事件被消耗掉）并更新 `pendingEdits`；`onLeave()`（`syncOnLeave` 且有未提交编辑 / 未上传提交 / 可重试问题 → 取消 `autoCommitDebouncer`，`requestSync("leave")`）；`onReturn()`（`managing` 时：有可重试问题，或 `syncOnLeave` 且有待传内容 / 上次拉取已过 2 分钟 → `requestSync("resume")`；`syncOnLeave` 且后台联网被拦过时，每 7 天最多弹一次电池设置提示）；`online` 事件（只看 `weakNetworkMode`，有可重试问题就 `requestSync("online")`）；`requestSync(reason)` 同一时刻最多排一个，自动化暂停（`getPausedAutomatics`）时除 `manual` 外不排，任务里调 `gitActions.commitAndSync({ fromAutoBackup: true, mode: "all", reason })`。`SyncReason`：`auto` / `manual` / `leave` / `resume` / `online` / `retry` / `startup`。
  - 记录钩子（`GitActions` 与 `IsomorphicGit` 调）：`syncStarted` / `syncFinished`、`beforeCommit` / `recordCommit`（提交期间又有新编辑时不清 `pendingEdits`）、`recordPull`、`recordPush`、`recordPullRecovery`（拉取修复写进历史并弹通知）、`expectWrites`。
  - `observeError(error): boolean`：`UserCanceledError` 不看；其余经 `classifySyncError` 分类，同类问题累计 `attempts`，`other` 满 `MAX_OTHER_ATTEMPTS`（5）次转为需要用户处理；`weakNetworkMode` 开着就按退避排重试（`RETRY_DELAYS_MS` = 15 s / 30 s / 1 min / 2 min / 5 min，最后一档重复；离线用 `OFFLINE_FALLBACK_MS`（5 min）兜底；在后台被拦时不排，回到前台再试）；需要用户处理的问题弹一条不自动消失的通知（点击打开状态页，同一个问题只弹一次，冲突不弹），有东西没上传且问题持续 10 分钟（`LONG_PROBLEM_MS`）时弹一次长时间提示；问题解决后，只在宣布过或持续超过 1 分钟的情况下弹一次「同步恢复正常」。返回值决定上游弹窗是否被吞，规则见第 4 节。
  - 亮屏：`updateKeepAwake()` 在 `keepAwakeWhileSyncing`、移动端 App、前台、有未提交编辑或未上传提交、问题不需要用户处理、距最后一次编辑不足 `KEEP_AWAKE_MAX_MS`（2 min）时，经 Capacitor 的 `KeepAwake` 插件亮屏；屏幕已被别处常亮则不碰。它是唯一不看 `managing` 的动作。
- `syncProblems.ts`（维护版新增）：把一次同步的错误归成监督器能处理、手机上读得懂的类别。`classifySyncError(error, { online, hidden })` → `SyncProblem { kind, retryable, needsUser, files, httpStatus?, raw }`（`raw` 已去掉 URL 里的凭据与 query）。`kind`：`offline` / `background-blocked` / `network` / `auth`（HTTP 401、403）/ `not-found`（404）/ `push-rejected` / `local-changes`（从文案 `Cannot pull with uncommitted working tree changes: …` 里解析出文件）/ `untracked-collision` / `conflict` / `merge-in-progress` / `config` / `other`；`offline`、`background-blocked`、`network`、`push-rejected`、`other` 可重试，其余 `needsUser`。网络类按上下文再分：设备离线 → `offline`；在后台 → `background-blocked`；否则 `network`；`NetworkUnavailableError` 的 `hidden-timeout` 直接是 `background-blocked`；HTTP 408 / 429 / ≥ 500 当网络问题；其余靠 `gitManager/networkPolicy.ts` 的 `isNetworkFailureMessage` 认文案。`problemText(problem, language, autoRetry = true)` 返回 `{ title, explain, action }` 的中英两套文案（`autoRetry` 为假时不承诺自动重试，改为指向 Weak network mode）；`syncLanguage()` 取 Obsidian 的 `getLanguage()`（以 `zh` 开头为中文，其余或抛错为英文）；`isNetworkProblem(kind)` 判断前三类网络问题；`BATTERY_HINT` 是 Android 电池用量设置的指引。文案里写了设置页路径（`Git (Maintained)` 设置 → Phone sync、Identity），改设置页名称或位置要同步这里；匹配 `Cannot pull with uncommitted…`、`untracked file would be overwritten` 等英文报错的正则依赖 `gitManager/isomorphicGit.ts` 的错误文案，改文案会让分类落到 `other`。
- `promiseQueue.ts`：`PromiseQueue`，Git 动作一个接一个跑；`addTask(task, onFinished)` 不回传 promise，要等结果就传 `onFinished`。
- `coalesce.ts`：把并发调用合并成「当前这次 + 至多一次后续」，用于刷新类任务。
- `commands.ts`：`addCommmands`（原拼写）注册约 40 个命令；命令 id 发布后不能改（例如 `push` 是 Commit-and-sync）。Obsidian 会在前面加插件 id，所以维护版的完整命令 id 是 `git-maintained:push` 这样（官方版是 `obsidian-git:push`），命令面板显示「Git (Maintained): …」。维护版加了 `open-sync-status`（「Open sync status」，调 `plugin.syncSupervisor.openView()`），完整 id 是 `git-maintained:open-sync-status`；它无条件注册，不看设置。
- `types.ts`：`ObsidianGitSettings`（含维护版的 `manualCommitUsesAutoCommitGlobs`，以及手机同步的 `weakNetworkMode`、`syncOnLeave`、`autoSyncDelaySeconds`、`keepAwakeWhileSyncing`、`rescueFolder`）、`declare module "obsidian"` 里补的私有 API 类型（维护版加了 `App.plugins?.enabledPlugins?`）、`CommitMode`、`Status` / `FileStatusResult` 等跨后端数据类型、错误类（`GitConflictError`、`NoNetworkError`）与 `mergeSettingsByPriority`。
- `constants.ts`：`DEFAULT_SETTINGS`（`manualCommitUsesAutoCommitGlobs: false`、`weakNetworkMode: false`、`syncOnLeave: false`、`autoSyncDelaySeconds: 0`、`keepAwakeWhileSyncing: false`、`rescueFolder: ""`，即上游行为）、各视图的 type/name/icon 配置（含维护版的 `SYNC_STATUS_VIEW_CONFIG`：类型 `git-maintained-sync-status`，图标 `refresh-cw`）、日期格式、Windows git 默认路径与 askpass 脚本名。
- `statusBar.ts`：`StatusBar`，显示当前操作、进度、离线与合并中状态，以及距上次提交的时间。
- `tools.ts`：`Tools`，大文件检查（`performCommit` 暂存前调用）、打开 diff、在某个提交打开文件、执行原始 git 命令。
- `openInGitHub.ts`：按 remote URL 在 GitHub 打开当前行或文件历史。
- `utils.ts`：零散工具（复数、文件菜单触发、颜色转换、时间与数组工具、`impossibleBranch` 穷尽检查）。
- `pluginGlobalRef.ts`：全局 `pluginRef`，给行作者 gutter 的右键菜单拿到插件实例。

## 4. 本层约束 / 约定 / 禁忌

- 改 Git 语义要同时顾两个后端：先改 `gitManager/` 的契约，再改两边实现；只在本机 git 上成立的改动不能直接用到移动端（`AGENTS.md`）。
- 会动工作区、索引或仓库状态的动作一律经 `promiseQueue`，不要另起并发。
- 对外路径一律 vault 相对，仓库相对路径只在 `gitManager/` 里流转。
- 视图类型、workspace 事件名（`obsidian-git:*`）、CSS 类名保持上游原样：已打开的面板在换成维护版后照样能用，也方便合并上游；维护版自己新增的东西用 `git-maintained-` 前缀（视图类型 `git-maintained-sync-status`、CSS 类 `.git-maintained-sync-*`、`.git/git-maintained-pull.json`）。
- 命令 id 和设置字段名一旦发布就不改；新设置要在 `types.ts`、`constants.ts`、`setting/settings.ts` 三处同时加，默认值保持上游行为。
- 改了会影响打包的东西，要 `pnpm run build` 并把 `main.js` 一起提交（维护版跟踪 `main.js`，见根目录 `MAINTENANCE.md`）。
- 手机同步的开关语义：所有新设置默认等于上游行为（`false` / `0` / 空串）。`SyncSupervisor` 始终记录历史，但只有 `managing`（`weakNetworkMode || syncOnLeave`）为真才「动手」——失败重试、离开 / 回来时同步、吞掉上游弹窗、`main.ts` 的 vault 事件过滤、`gitActions.commitStatus` 的 scoped status。细分：`observeError` 里的重试排程与 `online` 事件重试只看 `weakNetworkMode`；离开时同步、回来时补拉与电池提示只看 `syncOnLeave`；回来时若有可重试的问题，任一开关开着都会同步一次；保持亮屏只看 `keepAwakeWhileSyncing`（且仅移动端 App）。`weakNetworkMode` 的请求层（超时、离线快速失败、读重试）只作用于移动端后端，监督器层（重试、`online`、吞网络弹窗）对两个后端都有效。
- `observeError` 的返回值决定 `runGitAction` 是否跳过上游弹窗（`managing` 为假时一律返回假，只记录）：`background-blocked` 总是吞；`offline` / `network` / `push-rejected` 只在 `weakNetworkMode` 下吞；`conflict` 永远交回上游处理；`auth`、`not-found`、`local-changes`、`untracked-collision`、`merge-in-progress`、`config`、`other` 只有 `needsUser` 为真才吞（改由监督器自己的常驻通知提示，`other` 要连续失败 5 次才算）。只有 commit、commit-and-sync、push、pull 四个动作会把错误交给监督器。
- 回声过滤：`expectWrites(repoPaths)` 登记拉取自己要写的 vault 路径 30 s，期间这些路径的第一次 vault 事件不当作用户编辑。新增会写工作区的 Git 流程要在写之前登记，否则这些写入会被当成编辑、重新触发自动提交（该过滤只在 `managing` 时生效，见 `main.ts` 的 `onVaultChange`）。
- 监督器与状态页的文案是中英双语（`syncLanguage()`：Obsidian 语言以 `zh` 开头用中文，其余用英文），不同于其它界面的硬编码英文；新增文案两种语言都要写。同步历史只存本设备 local storage，不要改成写 vault 文件。
