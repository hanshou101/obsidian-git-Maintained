# .frac.md — src

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

插件源码总入口，由 Vite（根目录 `vite.config.mjs`）从 `main.ts` 打成根目录的 `main.js`。直属文件管插件生命周期、命令、Git 动作编排、自动化定时、手机同步监督、设置类型与默认值；Git 后端、编辑器集成、设置页和界面各在一个子目录。
- 后端二选一：`main.ts` 的 `useSimpleGit`（即 `Platform.isDesktopApp`）选桌面的 `SimpleGit` 或移动的 `IsomorphicGit`，见 `gitManager/.frac.md`。
- 维护版与上游的分歧：插件 id 是 `git-maintained`；设置 `manualCommitUsesAutoCommitGlobs`；手机同步（新文件 `syncSupervisor.ts`、`syncProblems.ts`，其余直属文件只在接线处小改）。手机推送重传历史的修复在根目录 `patches/`。

## 2. 直属文件

**入口与 Git 动作编排**
- `main.ts`：默认导出 `ObsidianGit`（Plugin），也是 `main.js` 唯一的导出（Vite 配置 `exports: "default"`，多加具名导出会让构建失败）。`onload` → `init()` 建后端并检查仓库，Git 就绪后才启动自动化；`unloadPlugin()` + `init({ fromReload: true })` 是设置重载路径；`displayError` / `handleConflict` 是统一的出错出口。
  - 维护版：官方插件也启用时，`onload` 弹常驻通知后直接返回；`loadSettings` 在自己没有 `data.json` 时接手官方设置；vault 的四个事件统一走 `onVaultChange`，由它决定是否触发 `autoCommitDebouncer`；`init()` / `unloadPlugin()` 里启停 `syncSupervisor`。
- `gitActions.ts`：`GitActions`，所有面向用户的 Git 动作（clone、commit、commit-and-sync、pull、push 等）。公开方法包在 `runReadyGitAction`（未就绪不跑）与 `gitAction.ts` 的结果类型里，逻辑在 `perform*`。commit-and-sync：提交 → 拉（移动端只会合并）→ 推。
  - 自动提交用 auto commit globs 挑文件；维护版让手动提交在 `manualCommitUsesAutoCommitGlobs` 开着时走同一份选择（用户自己暂存的文件照样提交）。
  - 维护版的同步接线：`commitAndSync` 外包监督器的 `syncStarted` / `syncFinished`；commit / commit-and-sync / push / pull 把 `observeError` 交给 `runGitAction`；`performCommit` 开头先 `recoverInterruptedPull()` 和 `beforeCommit()`；私有 `commitStatus` 在条件满足时只用 `IsomorphicGit.scopedStatus` 扫 include glob 所在目录。
- `gitAction.ts`：`GitActionResult<T>`（success / failed / cancelled）、`GitActionHost`、`runGitAction`：按错误类型分派给 host（冲突、无网络、用户取消记 cancelled）。维护版加可选第三参数 `observeError(error): boolean`，返回真就跳过上游弹窗。
- `automaticsManager.ts`：自动 commit-and-sync / pull / push 的定时器；「停笔后再提交」用 `plugin.autoCommitDebouncer`，经 `promiseQueue` 排队。维护版：`autoSyncDelaySeconds > 0` 时代替 `autoSaveInterval` 作等待时间；改延迟要 `reload("commit")` 重建 debouncer。
- `autoCommitGlobs.ts`：解析 auto commit globs 设置，产生匹配器与路径选择器（Include / Exclude）；移动端靠它在暂存前自己筛文件，桌面端把 pathspec 交给 git。维护版加 `includeGlobScope(globs)`：取 include glob 的字面开头文件夹，收窄不了返回 `undefined`，供 `commitStatus` 用。
- `promiseQueue.ts`：`PromiseQueue`，Git 动作一个接一个跑；`addTask(task, onFinished)` 不回传 promise。`coalesce.ts`：把并发调用合并成「当前这次 + 至多一次后续」，用于刷新类任务。

**手机同步（维护版新增）**
- `syncSupervisor.ts`：`SyncSupervisor`（`plugin.syncSupervisor`）。始终记录同步历史、当前问题和联网判断，存本设备 local storage（不在 vault，不会被提交）；只有 `managing`（`weakNetworkMode || syncOnLeave`）为真才行动。
  - 生命周期 `register()` / `start()` / `stop()`；给视图用 `snapshot()`、`onChange`、`openView()`；触发 `noteVaultChange`、`onLeave` / `onReturn`、`requestSync(reason)`、`observeError`；`GitActions` 与 `IsomorphicGit` 调其 `syncStarted` / `record*` / `expectWrites` 钩子。
  - `inBackground` 跟随 Capacitor 的 `pause` / `resume`，`IsomorphicGit.network.isHidden()` 读它；`updateKeepAwake()` 保持亮屏，唯一不看 `managing`。
- `syncProblems.ts`：把一次同步的错误归类（`classifySyncError` → `SyncProblem`：可否重试、要不要用户处理、被挡的文件），并给中英文案（`problemText`）。匹配英文报错的正则依赖 `gitManager/isomorphicGit.ts` 的错误文案，改文案会让分类落到 `other`；文案里写了设置页路径，改设置页名称要同步。

**命令、类型、常量**
- `commands.ts`：`addCommmands`（原拼写）注册全部命令；命令 id 发布后不能改，完整 id 带插件 id 前缀（`git-maintained:push`，官方版是 `obsidian-git:push`）。维护版加了无条件注册的 `open-sync-status`。
- `types.ts`：`ObsidianGitSettings`、`declare module "obsidian"` 补的私有 API 类型、跨后端数据类型（`Status` / `FileStatusResult` 等）与错误类（`GitConflictError`、`NoNetworkError`）。
- `constants.ts`：`DEFAULT_SETTINGS`（新增设置的默认值都等于上游行为）、各视图的 type / name / icon（含 `SYNC_STATUS_VIEW_CONFIG`）、Windows git 默认路径、askpass 脚本名。

**其他**
- `statusBar.ts`（`StatusBar`：当前操作、进度、离线与合并中状态）、`tools.ts`（`Tools`：大文件检查、打开 diff、在某个提交打开文件、原始 git 命令）、`openInGitHub.ts`（在 GitHub 打开当前行或历史）。
- `utils.ts`：零散工具。`pluginGlobalRef.ts`：全局 `pluginRef`，给 gutter 右键菜单拿插件实例。`externalLibTypes.d.ts`：类型声明。

## 3. 子目录导航

- `editor/`：见 `editor/.frac.md`；编辑器里的冲突块按钮（桌面 + 移动）、逐行 blame 与 gitsigns 风格标记（仅桌面、仅 `SimpleGit`）。
- `gitManager/`：见 `gitManager/.frac.md`；抽象契约 `GitManager`、`SimpleGit` / `IsomorphicGit` 两个后端、`MyAdapter`、askpass；维护版加了弱网请求策略、移动端拉取中断修复与 `commitsAhead`。
- `setting/`：见 `setting/.frac.md`；声明式设置页（维护版加了手动提交 globs 开关、「停笔后等几秒」和 Phone sync 页）、本设备 localStorage、Git 服务器密码、维护版的 `stockPlugin.ts`（接手官方设置）。
- `ui/`：见 `ui/.frac.md`；History / Source Control / diff / 只读文件视图、对话框、分支状态栏；维护版另有同步状态视图。

## 4. 本层约束 / 约定 / 禁忌

- 改 Git 语义要同时顾两个后端：先改 `gitManager/` 的契约，再改两边实现；只在本机 git 上成立的改动不能直接用到移动端。
- 动工作区、索引或仓库状态的动作一律经 `promiseQueue`，不要另起并发。对外路径一律 vault 相对，仓库相对路径只在 `gitManager/` 里流转。
- 视图类型、workspace 事件名（`obsidian-git:*`）、CSS 类名保持上游原样（已打开的面板照样能用，也方便合并上游）；维护版新增的用 `git-maintained-` 前缀。命令 id 和设置字段名发布后不改。
- 新设置要在 `types.ts`、`constants.ts`、`setting/settings.ts` 三处同时加，默认值保持上游行为。改了会影响打包的东西，要 `pnpm run build` 并把 `main.js` 一起提交。
- 手机同步的开关：重试排程与 `online` 事件重试只看 `weakNetworkMode`；离开时同步、回来时补拉、电池提示只看 `syncOnLeave`；保持亮屏只看 `keepAwakeWhileSyncing`（仅移动端 App）；`managing` 为假时监督器只记录。`weakNetworkMode` 的请求层只作用于移动端后端，监督器层对两个后端都有效。
- `observeError` 的返回值决定是否吞掉上游弹窗：`background-blocked` 总是吞；`offline` / `network` / `push-rejected` 只在 `weakNetworkMode` 下吞；`conflict` 永远交回上游；其余只有 `needsUser` 为真才吞，改由监督器的常驻通知提示。
- 回声过滤：`expectWrites(repoPaths)` 登记拉取自己要写的路径，这些路径短时间内的第一次 vault 事件不算用户编辑。新增写工作区的 Git 流程要在写之前登记，否则会重新触发自动提交（只在 `managing` 时生效）。
- 监督器与状态页的文案中英双语（Obsidian 语言以 `zh` 开头用中文），其它界面硬编码英文；新增文案两种语言都要写。同步历史只存本设备 local storage，不要写进 vault。
