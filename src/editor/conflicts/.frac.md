# .frac.md — src/editor/conflicts

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

编辑器内的合并冲突解决 UI：识别 `<<<<<<<` / `=======` / `>>>>>>>`（可带 `|||||||` diff3 base）冲突块，给标记行染色，每块一组 Keep ours / theirs / both / base 按钮，另有「整文件一键处理」入口。
三层：`model.ts` 纯文本解析（无 CodeMirror / Obsidian 依赖）→ `actions.ts` 用 `dispatch` 改文档 → `view.ts` 的 CodeMirror 扩展，入口 `conflictExtensions` 由 `../editorIntegration.ts` 永远挂载。不调用 Git；桌面 / 移动共用，仅摘要 UI 按 `Platform.isMobile` 分叉。

## 2. 直属文件

- `model.ts`：类型 `ConflictChoice`、`ConflictBlock`（整块与各区范围、三份文本）；函数 `parseConflictBlocks`、`resolveBlockText`。
  - 标记行行首锚定、恰好 7 个标记字符；按 `\n` 切行、不处理 `\r`，CRLF 文本匹配不上（编辑器内文本已是 `\n`）。
  - 缺分隔行或结束行的块静默跳过；块的 `to` 在非文件末尾时多含一个换行；两路块选 `base` 会抛错。
- `actions.ts`：`resolveConflict` 一次 `dispatch` 替换整块；`resolveAllConflicts` 重新解析全文，所有块放进同一个 transaction（一次撤销即可还原）。含两路块时以 `base` 批量解决会抛错，UI 靠「全部块都有 base 才显示 Keep all base」避开。
- `view.ts`：导出 `conflictBlocksField`、`conflictMarkersField`、`conflictExtensions`，仅 `docChanged` / `reconfigured` 时重算。
  - 装饰：标记行、头标记行末尾的 `ConflictButtonsWidget`（有 base 才有 Keep base）、内容区按行的 `git-conflict-*-line`；按钮是 Obsidian `ButtonComponent`。
  - 摘要（`renderConflictSummary`）：桌面用 `showPanel` 顶部面板 `ConflictPanel`，移动端改在位置 0 插 block widget `ConflictSummaryWidget`。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- `parseConflictBlocks` 是单一事实来源（`view.ts` 与 `actions.ts` 都调它）：改标记语法或块边界会同时影响装饰位置、按钮替换范围和批量替换。
- 冲突 UI 只在 Live Preview 且文本含 `<<<<<<<` 时出现，门禁是 `computeBlocks`；要支持 Source 模式必须改这里。
- 解决冲突只 `dispatch` 文档改动，不写磁盘、不 stage；class 名 `git-conflict-*` 要与根目录 `styles.css` 一致。
- `ConflictButtonsWidget.eq` 只比 `from/to/ours/theirs/base`，恰是 `resolveConflict` 用到的字段；动作改为依赖 `markers` 或各 Range 时必须同步扩展 `eq`，否则会复用持有旧 block 的 widget。

## 5. 什么时候需要下钻

- 改冲突识别规则（diff3、嵌套、CRLF）：只读 `model.ts`。
- 改按钮 / 面板 / 装饰或平台差异：读 `view.ts`。
- 改解决动作（撤销粒度、聚焦、解决后 stage）：读 `actions.ts`。
