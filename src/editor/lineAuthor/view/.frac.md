## 1. 本目录是什么

Line Author（逐行 blame）功能的「视图」层：把上级 `lineAuthor/model` 里的状态（StateField `lineAuthorState` + `LineAuthorSettings`）渲染成 CodeMirror 的行 gutter。包含三块：gutter 的 CodeMirror 扩展与区间装配（`view.ts`）、视图级缓存（`cache.ts`）、gutter 右键菜单（`contextMenu.ts`）。单个 marker 的文字/配色/占位细节下沉在 `gutter/`。
本层不取 blame、不管功能开关；开关与装配在上级 `lineAuthorIntegration.ts`（`cache.ts` 的注释要求在它的 disabler 路径里调用 `clearViewCache()`）。本层没有桌面/移动分支判断，功能能否启用见上级 `../.frac.md`。

## 2. 直属文件

- `view.ts`：导出 `lineAuthorGutter`（CodeMirror `gutter({ class: "line-author-gutter-container", renderEmptyElements: true, ... })` 扩展）。
  - `markers(view)` 读 `view.state.field(lineAuthorState, false)`（字段可能不存在 / 值为 `undefined` = blame 尚未返回），生成 `RangeSet<GutterMarker>`；`lineMarkerChange` 用 `laStateDigest` 比较新旧状态，只在 blame 状态变化时重算。
  - `lineAuthoringGutterMarkersRangeSet`：缓存键 = LA 状态 digest + 每个文档行的 `[from, to]`（`to` 取自 `view.lineBlockAt(from).to`；一个 line block 可含多个文档行，块内只显示最新提交）+ `JSON.stringify(latestSettings.get())`。文档文本刻意不进 digest（改动只有保存后才体现在 LA，而保存会改变 LA 的 `key`）。结果存入 `gutterMarkersRangeSet`，除非本次用了 `initialLineAuthoringGutter`（`allowCache=false`，颜色需每次重算）。
  - `computeLineAuthoringGutterMarkersRangeSet` 分支顺序：空文档 / 最后一个空行 → `UNDISPLAYED`（`TextGutter("")`）；`optLA === undefined` → 初始等待 gutter；`la === "untracked"` → `newUntrackedFileGutter`；行号映射落在 `[1, lastAuthorLine]` 内 → 正常 `lineAuthoringGutterMarker`；`lastAuthorLine < 1`（原文件为空）→ 初始等待 gutter；其余（有未保存改动）→ 夹到合法范围并用 `key + "computing"`、`"waiting-for-result"` 渲染。最后 `RangeSet.of(ranges, true)`。
  - `computeLineMappingForUnsavedChanges`：用 `optLA.lineOffsetsFromUnsavedChanges` 的累计行偏移把「文档行号」映射回「blame 行号」；有未保存改动的那一行映射为 `undefined`（显示为 computing）。代码里标注 `todo. explain`。
  - `initialSpacer` / `updateSpacer` 返回占位宽度 marker（`initialSpacingGutter()` 或 `getLongestRenderedGutter()?.gutter`），同时调用 `temporaryWorkaroundGutterSpacingForRenderedLineAuthoring`：对 `.cm-gutters` 把空的 `margin-left` 设为 `unset`（Obsidian v1.0 的重叠 bug 临时规避，注释写明待官方修复后移除）。
- `cache.ts`：模块级可变缓存，全部由 `clearViewCache()` 一次清空。导出：`gutterInstances`（`LineAuthoringGutter` 实例缓存）、`gutterMarkersRangeSet`（RangeSet 缓存）、`attachedGutterElements`（已挂到 DOM 的 gutter 元素集合，供右键命中）、`getLongestRenderedGutter()` / `conditionallyUpdateLongestRenderedGutter(gutter, text)`（记录最长已渲染文字；长度不同于持久化值时调用 `localStorage.setGutterSpacingFallbackLength`）、`recordRenderedAgeInDays(age)` / `computeAdaptiveInitialColoringAgeInDays()`（环形缓冲取 `median`，给等待态 gutter 选初始颜色）。注意：环形缓冲实际容量常量是 `15`，而注释写的是 `50`。
- `contextMenu.ts`：`handleContextMenu(menu, editor, mdv)`（Obsidian `editor-menu` 回调）与 `enrichCommitInfoForContextMenu(commit, isWaitingGutter, elt)`（`gutter/gutter.ts` 调用，把 `{hash, isZeroCommit, isWaitingGutter}` JSON 写到元素的 `data-commit` 属性）。
  - 编辑器有焦点（`editor.hasFocus()`）时直接不处理；否则用 `findGutterElementUnderMouse()` 找到被点的 gutter，读 `data-commit`，非 zero commit 且非等待态才加「Copy commit hash」（section `obs-git-line-author-copy`）。
  - 另外加 3 个可勾选的快捷设置项（section `obs-git-line-author-configure`）：`showCommitHash`、`authorDisplay`、`dateTimeFormatOptions`。隐藏后重新显示时取 `lastShownAuthorDisplay` / `lastShownDateTimeFormatOptions`（缺省取 `DEFAULT_SETTINGS.lineAuthor`）。点击调用 `pluginRef.plugin?.settingsTab?.lineAuthorSettingHandler(key, value)`，即由设置页对象（`src/setting/` 层）负责落地，菜单本身不写设置。

## 3. 子目录导航

- `gutter/`：见 `gutter/.frac.md`；单个 gutter marker 的文字格式化、按提交年龄配色、占位/未提交/未跟踪 marker、以及右键时按鼠标位置反查 gutter 元素。

## 4. 本层约束 / 约定 / 禁忌

- 缓存的唯一失效入口是 `clearViewCache()`：`cache.ts` 注释写明当前设计是设置变化时整个 line author 功能重载，所以只在上级的 disabler 路径里清（实际调用点见 `../.frac.md`）；新增缓存必须登记到该函数，否则重载后会读到旧设置下的 marker。
- 缓存键由设置的 `JSON.stringify` 参与；`LineAuthoringGutter.eq` 不比较 settings，因此「同 key 不同内容」不会触发 CodeMirror 重绘，内容变化必须体现在 `key`（保存/重算会换 key，未保存时用 `key + "computing"`）。
- 行号约定：`lineAuthoring.hashPerLine` 为 1-based（下标 0 占位），`lastAuthorLine = hashPerLine.length - 1`；文档行与 blame 行不等价，必须过 `computeLineMappingForUnsavedChanges`。
- `la.hashPerLine` 越界分支：`laEndLine > lastAuthorLine` 时先加一个 `UNDISPLAYED`，但该分支没有 `continue`，会继续落到后面的分支再为同一范围追加 marker。
- `contextMenu.ts` 的 `showCommitHash` 分支把 `actionNewValue = currentValue`（未取反）传给 `lineAuthorSettingHandler`，改这里前先核对 handler 对布尔值的处理（该 handler 的契约见 `src/setting/.frac.md`）。
- `pluginRef.plugin!`（`src/pluginGlobalRef`）被 `cache.ts`（`localStorage`）与 `contextMenu.ts`（`settings.lineAuthor`）直接解引用，调用时插件实例必须已设置。
- `view.ts` 的 `markers()` 每次按键 / 光标移动会被调用数次（源码注释），所以重计算只放在缓存未命中的分支。

## 5. 什么时候需要下钻

- 改某个 gutter 单元的显示内容、宽度稳定策略、颜色算法：读 `gutter/.frac.md`，再进 `gutter/gutter.ts` / `coloring.ts`。
- 改右键菜单命中不准：`contextMenu.ts` + `gutter/gutterElementSearch.ts`（鼠标位置 hack）。
- 改未保存修改时 gutter 的行为（computing / 行偏移）：先读 `view.ts` 的 `computeLineMappingForUnsavedChanges`；`LineAuthoringWithChanges.lineOffsetsFromUnsavedChanges` 的类型定义在上级 `lineAuthor/model.ts`，本层只消费它。
- 改缓存失效时机：读 `cache.ts`，再按上级 `../.frac.md` 找到触发 `clearViewCache()` 的调用点。
