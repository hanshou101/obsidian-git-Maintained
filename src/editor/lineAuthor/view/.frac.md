# .frac.md — src/editor/lineAuthor/view

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

Line Author（逐行 blame）的视图层：把 `../model.ts` 的 `lineAuthorState` 与 `LineAuthorSettings` 渲染成 CodeMirror 行 gutter；单个 marker 的细节在 `gutter/`。不取 blame、不管功能开关（在上级 `lineAuthorIntegration.ts`）。

## 2. 直属文件

- `view.ts`：导出 `lineAuthorGutter`（CodeMirror `gutter` 扩展）。
  - `markers` 读 `lineAuthorState`（`undefined` 表示 blame 还没回来），产出 `RangeSet`；`lineMarkerChange` 比 `laStateDigest`，blame 状态变了才重算。
  - 区间集缓存键 = blame digest + 各文档行的 line block 范围 + 当前设置；文档文本刻意不进 digest（改动要保存后才体现在 blame，保存会换 `key`）。
  - 无 blame 用初始等待 gutter，`"untracked"` 用未跟踪 gutter；其余行经 `computeLineMappingForUnsavedChanges` 映射回 blame 行号，映射不上（有未保存改动）的用 `key + "computing"` 与 `"waiting-for-result"` 渲染。
  - `initialSpacer` / `updateSpacer` 给占位宽度，并临时规避 Obsidian 的 gutter 重叠 bug。
- `cache.ts`：模块级缓存，全由 `clearViewCache()` 清空：marker 实例、区间集、已挂 DOM 的 gutter 元素（供右键命中）、最长已渲染 gutter（写回间距长度）、已渲染年龄环形缓冲（给等待态选初始色）。
- `contextMenu.ts`：右键菜单。
  - `handleContextMenu`（`editor-menu` 回调）：编辑器有焦点时不处理，否则找到被点的 gutter（`findGutterElementUnderMouse()`），给「Copy commit hash」和三个快捷设置项，点击交给 `lineAuthorSettingHandler`。
  - `enrichCommitInfoForContextMenu` 由 `gutter/gutter.ts` 调用，把提交信息写进元素的 `data-commit`。

## 3. 子目录导航

- `gutter/`：见 `gutter/.frac.md`；单个 marker 的文字、配色、占位，以及右键时反查 gutter 元素。

## 4. 本层约束 / 约定 / 禁忌

- 缓存的唯一失效入口是 `clearViewCache()`（停用路径调用，设置变化时整个功能重载）；新增缓存必须登记进去，否则读到旧设置下的 marker。
- `LineAuthoringGutter.eq` 不比 settings：内容变化必须体现在 `key`（未保存用 `key + "computing"`），否则 CodeMirror 不重绘。
- 行号 1-based（`hashPerLine` 下标 0 占位）；文档行号不等于 blame 行号，必须先映射。
- 行号越界分支先加一个不显示的 marker 却没有 `continue`，会为同一范围再追加 marker。
- `showCommitHash` 菜单项把当前值原样（未取反）交给 handler，而 handler 直接写入它，改前先核对。
- `cache.ts`、`contextMenu.ts` 直接解引用 `pluginRef.plugin!`；`markers()` 每次按键调用数次，重计算只放在缓存未命中的分支。

## 5. 什么时候需要下钻

- 改单个 gutter 的内容、宽度、配色：读 `gutter/.frac.md`；右键菜单命中不准：`contextMenu.ts` + `gutter/gutterElementSearch.ts`。
- 改未保存修改时的行为：`view.ts` 的 `computeLineMappingForUnsavedChanges`；偏移类型在 `../model.ts`。
- 改缓存失效时机：读 `cache.ts`，触发点在上级 `lineAuthorProvider.ts` 的 `destroy()`。
