## 1. 本目录是什么

Line Author（逐行 blame 侧栏）的 CodeMirror gutter 渲染层：把一份 blame 结果（`LineAuthoring`）里某个行区间翻译成一个 `GutterMarker`，负责文字格式化、按提交年龄上色、占位（等待结果 / 未提交 / 未跟踪）以及从 DOM 反查被右键的 gutter。
它不取 blame、不决定何时刷新：数据来自 `src/editor/lineAuthor/model` 的类型与上级 `view/` 的 `cache`、`contextMenu`（本层 import 它们），设置值来自 `LineAuthorSettings`。本层没有任何桌面/移动分支判断，也不关心 blame 数据从哪个后端来；功能能否启用由上级 `lineAuthor` 决定（见 `../../.frac.md`）。

## 2. 直属文件

- `gutter.ts`：核心。导出 `TextGutter`（只显示固定文字的占位 marker，`eq` 按 text）、`LineAuthoringGutter`（真正的 blame marker）和工厂 `lineAuthoringGutterMarker(la, startLine, endLine, key, settings, options?)`。
  - 文本 = `[提交 hash 前 6 位(showCommitHash)] [作者(authorDisplay: hide/initials/first name/last name/full)] [日期(dateTimeFormatOptions: hide/date/datetime/custom/natural language，时区 viewer-local/author-local/utc0000)]`，空段被丢弃，空格连接；作者与 committer 不同时作者名后加 `*`（`isDeepStrictEqual`，来自 `node:util`）。缺作者名用 `-`，缺日期用 `?`。
  - `toDOM()` 只算一次模板，每次返回 `cloneNode(true)` 并登记到 `attachedGutterElements`；真实提交才会 `recordRenderedAgeInDays`（供自适应初始配色）和 `conditionallyUpdateLongestRenderedGutter`；`destroy()` 仅在 DOM 已脱离 `activeDocument.body` 时才从 `attachedGutterElements` 移除。
  - 「假提交」（zero commit 或 `options === "waiting-for-result"`）用 `adaptTextForFakeCommit`：以全局最长已渲染文字为模板，把非空白字符替换成 `+`（zero commit）或 `%`（等待中，优先级更高），再按 `localStorage.getGutterSpacingFallbackLength()` 补齐/截断；zero commit 只保留末尾 3 个 `+`，前面换成空白。目的是避免 gutter 宽度来回抖动。
  - 额外产物：tooltip（`setTooltip` 显示 commit summary）、`data-author` / `data-author-email` 属性、`enrichCommitInfoForContextMenu(...)` 给右键菜单挂提交信息、`elementClass = "obs-git-blame-gutter"`。
  - 工厂用 `gutterInstances` 缓存，缓存键 = sha256(`JSON.stringify(settings)` + `s{start}-e{end}-k{key}-o{options}`)。**必须走工厂，不要直接 `new LineAuthoringGutter`。** `eq()` 只比较 `key/startLine/endLine/options`，不比较 settings 与 lineAuthoring 内容，调用方要靠 `key` 区分内容变化。
- `coloring.ts`：配色。`coloringBasedOnCommitAge(epochSeconds, isZeroCommit, settings)` 返回 `{ color: "rgba(...)", daysSinceCommit }`；`previewColor("oldest" | "newest", settings)` 给设置页做色块预览；`setTextColorCssBasedOnSetting(settings)` 把 `settings.textColorCss` 写入 `activeDocument.body` 的 CSS 变量 `--obs-git-gutter-text`。
  - 年龄比例 `x = clamp(天数 / maxAgeInDaysFromSettings, 0, 1) ^ (1/2.3)`（让较新的提交更醒目），在 `settings.colorNew` 与 `settings.colorOld` 之间逐通道线性插值；暗色模式（`pluginRef.plugin.app.isDarkMode()`）RGB 乘 0.4、alpha 0.75，亮色 alpha 0.25。zero commit 年龄恒为 0。
- `commitChoice.ts`：`chooseNewestCommit(lineAuthoring, startLine, endLine)`，在闭区间内选出「最新」提交作为这个 gutter 的代表。遇到 zero commit 即覆盖当前候选，其余按 `author.epochSeconds`（缺省按 0）比较，所以后面更新的普通提交仍可能取代 zero commit；区间内没有任何 hash 时返回 `undefined`（类型上被 `undefined!` 绕过，`gutter.ts` 的 `computeDom` 会直接访问 `commit.isZeroCommit`）。
- `initial.ts`：blame 尚未返回时的占位。`initialSpacingGutter()` 返回宽度等于持久化的 `gutterSpacingFallbackLength` 的 `-` 串 `TextGutter`；`initialLineAuthoringGutter(settings)` 返回 waiting 状态的 `LineAuthoringGutter`；`adaptiveInitialColoredWaitingLineAuthoring(settings)` 构造一份只有一行、hash 为 `"waiting-for-result"` 的伪 `Blame`，年龄取 `computeAdaptiveInitialColoringAgeInDays()`（此前记录过的渲染年龄），没有记录时取 `maxAge * 0.25`。**`initialLineAuthoringGutter` 的结果不可被调用方缓存**，缓存键里已包含 `ageForInitialRender`，每次调用都要重新取颜色。
- `untrackedFile.ts`：`newUntrackedFileGutter(key, settings)`，未跟踪文件的 gutter：伪 `Blame` 只有一行 `"000000"` → `zeroCommit`（从 `src/gitManager/simpleGit` import，仅为该常量），范围固定 1..1，显示效果与「新改动」的 `+++` 相同。
- `gutterElementSearch.ts`：右键菜单的 workaround。Obsidian 的 `editor-menu` 事件拿不到目标 gutter，所以 `prepareGutterSearchForContextMenuHandling()` 在 `window` 上记录最近一次 `mousedown` 的 `clientX/clientY`，`findGutterElementUnderMouse()` 遍历 `attachedGutterElements` 用 `getBoundingClientRect` 命中。代码里标了 todo（等 Obsidian 修复后移除）。

## 4. 本层约束 / 约定 / 禁忌

- 行号一律 1-based：`hashPerLine` 的下标 0 是占位（`[undefined!, "hash"]`），`startLine/endLine` 为闭区间；`LineAuthoring` 的 `"untracked"` 变体在本层类型上被 `Exclude` 掉，未跟踪文件通过 `newUntrackedFileGutter` 走伪 blame。
- 全局状态都放在上级 `cache.ts`（`gutterInstances`、`attachedGutterElements`、最长已渲染 gutter、已渲染年龄），本层只读写不拥有；动 gutter 渲染时要同时想到这些缓存的失效时机。
- `gutter.ts`（假提交路径）与 `initial.ts` 用 `pluginRef.plugin!.localStorage.getGutterSpacingFallbackLength()`（`src/pluginGlobalRef`），插件实例未设置时会抛错；`coloring.ts` 对 `pluginRef.plugin` 做了可选链，缺失时按亮色模式处理。
- `gutterElementSearch.ts` 的 `mousedown` 监听器没有移除路径（插件卸载 / 设置重载都不会清理）；「已注册」靠 `mouseXY.x === -10` 哨兵判断，第一次真实 `mousedown` 之前重复调用会重复注册。
- 日期的 `author-local` / `utc0000` 只对字符串格式串追加 ` Z` / `[Z]`，`natural language` 走函数格式化，不带时区标记。
