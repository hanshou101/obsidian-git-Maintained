## 1. 本目录是什么

Line Author：在 Markdown 编辑器左侧显示逐行 `git blame` 信息（短 hash / 作者 / 日期，按提交年龄着色）的完整功能，分四块：
- `model.ts`：数据类型、CodeMirror StateField、`LineAuthorSettings` 类型和全局设置访问器。
- `lineAuthorProvider.ts`：对某个文件算 blame、缓存结果、通知编辑器。
- `lineAuthorIntegration.ts`：Obsidian 事件接线与功能的启用 / 停用 / 刷新。
- `view/`：把 `lineAuthorState` 渲染成 gutter（含 `view/gutter/`）。

**仅桌面可用**：`isAvailableOnCurrentPlatform()` 要求 `plg.useSimpleGit && Platform.isDesktopApp`，本目录只通过 `SimpleGit`（原生 git，见 `src/gitManager/simpleGit.ts`）取 blame；移动端（isomorphic-git）不会激活，`activateFeature()` 静默返回。功能实例挂在 `plugin.editorIntegration.lineAuthoringFeature`（`src/editor/editorIntegration.ts` 层），provider 也通过这条路径拿到 `SimpleGit`。

数据流：Obsidian 事件 → `LineAuthoringFeature` → `LineAuthorProvider.trackChanged(file)` → `SimpleGit` 取 HEAD 与文件对象 hash、必要时 `blame` → 以 `LineAuthoringId` 缓存 → `eventsPerFilePathSingleton` 通知订阅该路径的编辑器（`notifyLineAuthoring(key, la)`，实现在本目录之外）→ 按 `model.ts` 注释，由 `newComputationResultAsTransaction` 的调用方把结果变成 transaction → `lineAuthorState` 更新 → `view/` 重新渲染。

## 2. 直属文件

- `lineAuthorIntegration.ts`：导出 `LineAuthoringFeature`。
  - 生命周期：`onLoadPlugin()`（`registerEditorExtension(this.codeMirrorExtensions)` + `provideSettingsAccess(getter/setter)`，setter 会写回 `plg.settings.lineAuthor` 并 `saveSettings()`）、`conditionallyActivateBySettings()`（`settings.lineAuthor.show` 为真才激活）、`activateFeature()`、`deactivateFeature()`、`refreshLineAuthorViews()`（`show` 为真时先 deactivate 再 activate，即整体重载；`obsidian-git:head-change`、`css-change` 事件都调用它，`view/cache.ts` 的注释说设置变化时同样整体重载）。
  - `activateFeature()`：平台不可用直接返回；否则 `setTextColorCssBasedOnSetting`、new `LineAuthorProvider`、注册事件、挂扩展；任何异常 `console.warn` 后调用 `deactivateFeature()` 清理（所以该函数写得很防御）。
  - 编辑器扩展开关：不重新注册，而是修改同一个 `codeMirrorExtensions` 数组（push `enabledLineAuthorInfoExtensions` / `remove`），再调用 `workspace.updateOptions()`；激活时 `iterateAllLeaves(handleWorkspaceLeaf)` 处理已打开的文件。
  - 事件：`editor-menu`→`handleContextMenu`、`file-open`、`active-leaf-change`（只处理有 `file` 的 `MarkdownView`）、vault `modify` / `rename`（仅 `TFile`）→ `trackChanged`；`obsidian-git:head-change`、`css-change`→ 整体刷新。每个事件既 `plg.registerEvent(...)` 又在 `destroyEventHandlers()` 里 `offref`（用了 `!` 非空断言，假定已 create 过）；创建时还会调用 `prepareGutterSearchForContextMenuHandling()`。
- `lineAuthorProvider.ts`：导出 `LineAuthorProvider`、`enabledLineAuthorInfoExtensions = Prec.high([lineAuthorState, lineAuthorGutter])`，并 re-export `previewColor`（来自 `view/gutter/coloring`）。
  - `trackChanged(file)`：包一层 try/catch，`console.warn` 后原样重新抛出；`computeLineAuthorInfo(path)` 依次调用 `submoduleAwareHeadRevisonInContainingDirectory`（方法名拼写即如此，勿「修正」）、`hashObject`，用 `lineAuthoringId(head, objHash, path)` 当 key，key 为 `undefined` 就静默返回；未命中 `lineAuthorings` 缓存才调用 `blame(path, settings.lineAuthor.followMovement, settings.lineAuthor.ignoreWhitespace)`；最后通知订阅者 `sub.notifyLineAuthoring(key, la)`。
  - `destroy()`：清空 `lineAuthorings` 并调用 `view/cache` 的 `clearViewCache()`（这就是 `cache.ts` 注释里「disabler」的实际落点）。
- `model.ts`：
  - 类型：`LineAuthoring = Blame | "untracked"`、`LineAuthoringId`（格式 `head{head}-obj{objHash}-path{path}`，保证 HEAD 变化 / 文件内容变化 / 路径不同都会换 key；子模块文件用所在最底层子模块的 HEAD）、`LineAuthoringWithChanges { la, key, lineOffsetsFromUnsavedChanges: Map<number, number> }`、`LineAuthorSettings` 及其枚举型字段（`followMovement`: inactive / same-commit / all-commits；`authorDisplay`: hide / full / first name / last name / initials；`dateTimeFormatOptions`: hide / date / datetime / natural language / custom；`dateTimeTimezone`: viewer-local / author-local / utc0000；另有 `show`、`showCommitHash`、`last*` 记忆字段、`coloringMaxAge`（字符串，如 `1y`）、`colorOld/colorNew`、`textColorCss`、`ignoreWhitespace`）。
  - `lineAuthorState`：`StateField<LineAuthoringWithChanges | undefined>`，初值 `undefined`（尚无结果）；事务里带 `LineAuthoringContainerType` effect（私有，只能通过 `newComputationResultAsTransaction(key, la, state)` 构造）就整体替换；否则走 `enrichUnsavedChanges`，把本次文档改动累计进 `lineOffsetsFromUnsavedChanges`（未改的行不在 map 里，改了且行数不变为 0，行数变化时最后一行记差值）。`compare` 只比较 `key`。
  - `laStateDigest(state)`：返回尚未 `.hex()` 的 sha256 对象（含 untracked 标记、key 与全部偏移），调用方可继续 `update` 后取 hex，用作视图缓存键。
  - `latestSettings { get, save }` + `provideSettingsAccess(...)`：全局设置访问器，初始是 `undefined!`，必须先经 `LineAuthoringFeature.onLoadPlugin()` 注入。`maxAgeInDaysFromSettings(settings)` 用 `src/setting/settings` 的 `parseColoringMaxAgeDuration` 解析 `coloringMaxAge`，非法时退回 `DEFAULT_SETTINGS.lineAuthor.coloringMaxAge`。

## 3. 子目录导航

- `view/`：见 `view/.frac.md`；把 `lineAuthorState` 渲染成 CodeMirror gutter（区间装配、视图缓存、gutter 右键菜单），其下的 `gutter/` 负责单个 marker 的文字、配色与占位。

## 4. 本层约束 / 约定 / 禁忌

- 只有一个 blame 来源：`SimpleGit`。给 `GitManager` 接口加 blame 不会让移动端自动支持本功能，激活条件在 `isAvailableOnCurrentPlatform()`。
- 重载式刷新：HEAD 变化（`obsidian-git:head-change`）、主题变化（`css-change`）以及设置变化后的刷新都是 `deactivateFeature()` + `activateFeature()`，`lineAuthorings` 与视图缓存因此全部丢弃；不要假设 `LineAuthorProvider` 的缓存能跨刷新存活。`show` 为 false 时 `refreshLineAuthorViews()` 什么都不做。
- `lineAuthorings` 缓存没有淘汰策略，key 只会随 HEAD / 内容 / 路径增多，直到 `destroy()` 才清空。
- `lineAuthorState.update` 在无 effect 时会原地修改 `prev.lineOffsetsFromUnsavedChanges` 并返回同一个对象；因为 `compare` 只看 `key`，凡是依赖「未保存改动」的缓存都必须用 `laStateDigest`，不能用对象引用或 `key`。
- 没有时间戳：旧的 blame 结果如果晚于新的到达，会覆盖新的（`model.ts` 注释承认）。
- 错误处理不对称：`file-open` / `active-leaf-change` 的处理器 `.catch(console.error)`；vault `modify` / `rename` 的处理器直接返回 `trackChanged(...)` 的 Promise 而不 catch，而 `trackChanged` 又会重新抛出，失败时会变成未处理的 rejection。
- 扩展开关靠修改 `codeMirrorExtensions` 数组；`deactivateCodeMirrorExtensions` 在 `for...of` 中对同一数组调用 `.remove`，目前数组里只有一个元素所以没问题，再加扩展时要改成先拷贝。
- `latestSettings.get()` 的实现就是读 `plg.settings.lineAuthor`，而 `view/view.ts` 在缓存键计算里每次都会调用它并 `JSON.stringify`，所以 getter 要保持廉价、返回稳定结构。
- 运行时依赖：`model.ts` 非 type-only 地 import `src/setting/settings`（`parseColoringMaxAgeDuration`）；`lineAuthorIntegration.ts` 非 type-only 地 import `SimpleGit`（用于 `instanceof`），对 `src/main` 只有类型引用。

## 5. 什么时候需要下钻

- 改 gutter 的显示、配色、缓存、右键菜单：读 `view/.frac.md`，再按其指引进 `gutter/`。
- 改何时重新计算 blame、何时刷新：读 `lineAuthorIntegration.ts` 的事件部分与 `lineAuthorProvider.ts`；blame 本身的命令行参数与解析在 `src/gitManager/simpleGit.ts` 的 `blame`。
- 改订阅者如何把结果送进编辑器（`notifyLineAuthoring`、`newComputationResultAsTransaction` 的调用方）：看上级 `src/editor/.frac.md` 与 `eventsPerFilepath.ts`。
- 改 `LineAuthorSettings` 字段或默认值：同时改 `model.ts`、`src/constants` 里的 `DEFAULT_SETTINGS.lineAuthor` 和 `src/setting/settings.ts` 的设置页，并考虑 `lineAuthorSettingHandler` 与右键菜单（`view/contextMenu.ts`）里用到的键。
