## 1. 本目录是什么

编辑器内的「行级 diff」功能（gitsigns.nvim 风格）：对当前打开的笔记，用编辑器文本与 git 取回的对比文本做差异，得到 hunk 列表，再驱动三种表现——行 gutter 里的 add / change / delete 标记（signs）、点击标记弹出的 diff 预览浮窗（含 Stage / Reset 按钮）、状态栏的 `+N ~N -N` 计数；同时给命令层提供 hunk 动作（reset / stage / 跳转）。
**仅桌面可用**：`SignsFeature.isAvailableOnCurrentPlatform()` 要求 `plg.useSimpleGit && Platform.isDesktopApp`，对比文本只能从 `SimpleGit` 取。相关设置在 `plugin.settings.hunks`（`showSigns`、`statusBar`: `"disabled"` / `"colored"` / 其它、`hunkCommands`）。

数据流：`SignsFeature`（事件 / 定时器）→ `SignsProvider.trackChanged(file)` → `gitManager.show("", path)` → `eventsPerFilePathSingleton` 通知订阅该路径的编辑器（`notifyGitCompare({ compareText, compareTextHead })`，订阅方在本目录之外，应通过 `newGitCompareResultAsTransaction` 派发）→ `hunksState` 计算 hunks（同步或防抖）→ `signsMarker` / 浮窗 / `ChangesStatusBar` 渲染。

## 2. 直属文件

- 装配与生命周期
  - `signsIntegration.ts`：`SignsFeature`（挂在 `plugin.editorIntegration.signsFeature`，公开字段 `changeStatusBar`）。`conditionallyActivateBySettings()` 在 `showSigns || statusBar != "disabled" || hunkCommands` 时激活；`activateFeature()` 创建 provider、事件、CodeMirror 扩展，`statusBar` 开启时 `addStatusBarItem()` 并 new `ChangesStatusBar`；失败则 `deactivateFeature()`。事件：`active-leaf-change`、vault `rename`（先让旧路径的订阅者 `changeToNewFilepath(file.path)`，再 `trackChanged`）、`obsidian-git:refreshed`（→ `refresh()` 遍历所有 leaf）、每 10 秒对 `activeEditor.file` 刷新一次（捕捉外部对 git index 的改动）。**没有 vault `modify` 监听**：文档编辑靠 CodeMirror 事务实时重算，对比文本只在上述时机重新取。
  - `signsProvider.ts`：`SignsProvider`（`trackChanged` / `destroy()` 空实现）与两组扩展常量：`enabledHunksExtensions = [hunksState, computeHunksDebouncerStateField]`（始终挂）、`enabledSignsExtensions = [diffTooltipField, cursorTooltipBaseTheme, signsGutter, signsMarker, selectedHunksState]`（仅 `showSigns` 为真时追加）。还 re-export 了 `previewColor`（来自 line author 的 coloring，与本目录功能无关）。
- hunk 计算与数据模型
  - `hunkState.ts`：核心。`hunksState: StateField<HunksData | undefined>`、`computeHunksDebouncerStateField`、`HunksStateHelper`（`getHunk` / `getHunkAtPos` / `getCursorHunk` / `hasHunksData`，给选区生成带 `added.lines` / `removed.lines` / `no_nl_at_eof` 的「部分 hunk」）、effect 类型 `GitCompareResultEffectType` / `DebouncedComputeHunksEffectType`、`newGitCompareResultAsTransaction`。
  - `diff.ts`：`computeHunks(textA, textB, chunks, changes)`，基于 `@codemirror/merge` 的 `Chunk.build` / `Chunk.updateB`（`scanLimit: 1000, timeout: 200`，传入旧 chunks + `ChangeDesc` 即增量更新）；`rawHunkFromChunk`、`rawHunksToHunks`、`lineFromPos` 把 chunk 换成 git 风格 hunk（一侧为 0 行时该侧 start 减 1）。文件下半是被注释掉的旧 diff 实现。
  - `hunks.ts`：从 gitsigns.nvim（Lewis Russell，MIT）翻译来的纯函数，文件头有版权声明须保留。类型 `Hunk` / `HunkNode` / `Sign` / `SignType` / `StatusObj`；`abstract class Hunks` 的静态方法 `createHunk`、`createPartialHunk`、`calcSigns`、`createPatch`（生成可交给 `git apply` 的补丁，`invert` 用于取消暂存）、`getSummary`、`findHunk`、`findNearestHunk`、`parseDiffLine`、`getHunkHeader`、`patchLines`。`computeStagedHunks` 与 `filterCommon` 的相关部分被注释 / 未使用。
- 表现层
  - `gutter.ts`：`GitGutterMarker`（class `git-gutter-marker git-<type> staged|unstaged`，`changedelete` 显示 `~`）、`signsMarker`（把 hunks 变成 RangeSet；只有防抖结果到达 / 新对比文本 / 无脏数据时才重算，其余仅 `rangeSet.map(tr.changes)`）、`signsGutter`（class `git-signs-gutter`，点击有 hunk 的行调用 `togglePreviewHunk`）。
  - `tooltip.ts`：`togglePreviewHunk`、`selectedHunksState`（被展开预览的 hunk 起始位置集合，随文档变化 `mapPos`）、`diffTooltipField`（`showTooltip.computeN`）、`cursorTooltipBaseTheme`。浮窗用 `diff2html` 渲染单个 hunk 的补丁，工具栏 Close / Stage / Reset；Stage 走 `plugin.promiseQueue.addTask(() => plugin.hunkActions.stageHunk(pos))`，Reset 直接调 `plugin.hunkActions.resetHunk(pos)`，Esc 通过当前 `MarkdownView.scope` 关闭。
  - `changesStatusBar.ts`：`ChangesStatusBar`，class `git-changes-status-bar`（`statusBar === "colored"` 时再加 `-colored`），`display(hunks, file)` 统计 `+added ~changed -deleted`；缓存当前 `MarkdownView`，侧栏获得焦点时仍显示正确编辑器；`display` 只在 `file` 与缓存视图的文件一致时才更新。
- 动作
  - `hunkActions.ts`：`HunkActions`（`plugin.hunkActions`）。`resetHunk(pos?)` 用 `removed.lines` 覆盖对应区间；`stageHunk(pos?)` 用 `Hunks.createPatch(...)` 生成补丁交给 `plugin.gitActions.applyPatch`（未暂存 hunk 优先，没有则取暂存 hunk 并 `invert`）；`goToHunk("first"|"last"|"next"|"prev")` 移动光标并滚动。内部 getter `editor` 通过 `obEditor.cm`（`@ts-expect-error`）取 CodeMirror 视图，且仅在 `hasHunksData`（有数据且 `!isDirty`）时才返回，所以防抖计算期间这三个动作都是静默 no-op。

## 4. 本层约束 / 约定 / 禁忌

- 行号约定：`Hunk.added.start` / `removed.start` 为 1-based 行号，纯删除（`added.count === 0`）时 `added.start` 是被删位置的上一行（文件顶部为 0），纯新增时 `removed.start` 同理；`vend = added.start + max(count - 1, 0)`。改 `diff.ts` / `hunks.ts` 的行号运算前先对照这个约定，`createPatch` 对 `add` 类型 hunk 会 `start + 1`。
- 防抖与过期丢弃：`scheduleHunkComputation` 在 `|changes.length - changes.newLength| > 1000` 或 `maxDiffTimeMs > 16` 时走 1000ms 防抖（先置 `isDirty = true`），否则同步算。`computeHunksDebouncerStateField.revision` 是对象身份：文档变化或文件路径变化即换新对象，旧的防抖结果因 revision 不匹配被丢弃。`maxDiffTimeMs` 为衰减最大值（`max(0.95 * old, 本次耗时)`）。
- `hunksState.update` 里有副作用：`applyHunkComputation` 与 `compareText` 缺失分支会调用 `pluginRef.plugin?.editorIntegration.signsFeature.changeStatusBar?.display(...)`，状态栏更新是在 StateField 更新过程中触发的。
- 增量 diff 依赖 `ChangeDesc` 可组合：`console.assert` + 回退（丢弃 chunks 做全量 diff）保证即使事务历史不一致也不会阻塞输入。
- 暂存 hunk 目前是未完成状态：`SignsProvider.computeSigns` 把 `compareTextHead` 固定为 `undefined`（取 HEAD 版本的代码被注释），`hunkState` 从不写 `stagedHunks`（恒为 `[]`），`Hunks.computeStagedHunks` 被注释；因此 gutter 的 `staged` 标记与「取消暂存」分支在现有代码下基本不会出现。动这块之前先决定要不要恢复这条链。
- `SignsProvider.computeSigns` 通过 `plugin.editorIntegration.lineAuthoringFeature.isAvailableOnCurrentPlatform()` 取 `SimpleGit`（而非 `signsFeature` 自己的同名方法），两处逻辑目前相同，改平台判断时两边都要看。
- `ChangesStatusBar` 的构造函数里直接 `plugin.app.workspace.on("active-leaf-change", ...)`，没有 `registerEvent` 也没有在 `remove()` 里解除，停用 / 重新激活 signs 会累积监听器。
- `selectedHunksState.update` 会先原地增删传入的旧 `Set`，再返回基于 `mapPos` 的新 `Set`。
- `SignsFeature.deactivateCodeMirrorExtensions` 与 line author 同样在 `for...of` 里对数组 `.remove`，靠 `workspace.updateOptions()` 生效；`destroyEventHandlers` 用 `!` 断言各 `EventRef`。
- 样式类（`git-gutter-marker`、`git-signs-gutter`、`git-diff-tooltip`、`tooltip-toolbar`、`git-changes-status-bar`、`git-add` / `git-change` / `git-delete`）都不在本目录定义。`hunks.ts` 没有任何 import（纯函数）；`diff.ts` 只依赖 CodeMirror，但 `rawHunksToHunks` 用了 Obsidian 注入的 `Array.prototype.last()`，脱离 Obsidian 环境单测时需要 polyfill。

## 5. 什么时候需要下钻

- 改 hunk 的行号 / 补丁生成 / 符号判定：读 `hunks.ts` 与 `diff.ts`，并对照 `hunkState.ts` 里 `HunksStateHelper.getHunk` 对 `added.lines` / `removed.lines` 的填充。
- 改何时重算、卡顿、防抖：读 `hunkState.ts` 的 `hunksState.update` 与 `scheduleHunkComputation`。
- 改对比文本来源（比较 index / HEAD）或刷新节奏：读 `signsProvider.ts` 与 `signsIntegration.ts`；`show` 的实现在 `src/gitManager/simpleGit.ts`。
- 改 stage / reset / 命令入口：读 `hunkActions.ts`、`tooltip.ts`；补丁最终交给 `plugin.gitActions.applyPatch`（`src/gitActions.ts` 一侧）；命令注册在 `src/commands.ts`，`hunkCommands` 设置如何门控它需到那里确认。
- 订阅方如何把 `notifyGitCompare` 变成 transaction，以及 `signsFeature` 在何时被创建 / 激活：看上级 `src/editor/.frac.md` 与 `eventsPerFilepath.ts` / `editorIntegration.ts`。
