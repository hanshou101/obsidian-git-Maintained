# .frac.md — src/editor/signs

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

编辑器内的「行级 diff」（gitsigns.nvim 风格）：编辑器文本与 git 对比文本做差异，得到的 hunk 驱动 gutter 增改删标记、点击弹出的 diff 浮窗（带 Stage / Reset）和状态栏计数，并给命令层提供 hunk 动作（reset / stage / 跳转）。
**仅桌面可用**：`SignsFeature.isAvailableOnCurrentPlatform()` 要求 `useSimpleGit && Platform.isDesktopApp`，对比文本只能从 `SimpleGit` 取。设置在 `plugin.settings.hunks`。
数据流：`SignsProvider.trackChanged` 经 `gitManager.show` 取对比文本 → `eventsPerFilePathSingleton` 通知订阅编辑器（`../control.ts`）→ `hunksState` 算 hunks → gutter、浮窗、状态栏。

## 2. 直属文件

- `signsIntegration.ts`：`SignsFeature`（`plugin.editorIntegration.signsFeature`）；`showSigns`、`statusBar`、`hunkCommands` 任一开启即激活。
  - 事件：`active-leaf-change`、vault `rename`（先让旧路径订阅者改订新路径）、`obsidian-git:refreshed`，另有定时器刷新当前编辑器（捕捉外部对 git index 的改动）。**没有 vault `modify` 监听**，编辑靠事务实时重算。
- `signsProvider.ts`：`SignsProvider.trackChanged` 取对比文本并通知订阅者；两组扩展常量 `enabledHunksExtensions`（始终挂）、`enabledSignsExtensions`（仅 `showSigns` 时追加）；并 re-export `previewColor`。
- `hunkState.ts`：核心。`hunksState`（StateField）、防抖状态 `computeHunksDebouncerStateField`、`HunksStateHelper`（取光标 / 选区 / 指定位置的 hunk）、`newGitCompareResultAsTransaction`。
- `diff.ts`：`computeHunks`，用 `@codemirror/merge` 的 `Chunk` 做增量 diff 再换成 git 风格 hunk；留着被注释掉的旧实现。
- `hunks.ts`：从 gitsigns.nvim（MIT）翻译来的纯函数，无 import，文件头版权声明必须保留；`Hunks` 的静态方法算符号 `calcSigns`、补丁 `createPatch`、最近 hunk。
- `gutter.ts`：`signsMarker`（hunks → gutter 标记；仅防抖结果到达、新对比文本或无脏数据时重算，其余只映射位置）、`signsGutter`（点击有 hunk 的行调 `togglePreviewHunk`）。
- `tooltip.ts`：`togglePreviewHunk`、`selectedHunksState`（被展开预览的 hunk 位置）、`diffTooltipField`；浮窗用 `diff2html` 渲染单个 hunk 的补丁，工具栏 Close / Stage / Reset。
- `changesStatusBar.ts`：`ChangesStatusBar.display(hunks, file)` 统计增改删；缓存当前 `MarkdownView`，侧栏获得焦点时仍显示正确编辑器。
- `hunkActions.ts`：`HunkActions`（`plugin.hunkActions`）：`resetHunk`、`stageHunk`（补丁交给 `plugin.gitActions.applyPatch`；未暂存 hunk 优先，没有则取暂存 hunk 并 `invert`）、`goToHunk`；只在 `hasHunksData` 时动作，防抖计算期间静默 no-op。

## 4. 本层约束 / 约定 / 禁忌

- 行号约定：`Hunk.added.start` / `removed.start` 为 1-based；纯删除时 `added.start` 是被删位置的上一行（文件顶部为 0），纯新增时 `removed.start` 同理；`createPatch` 对 `add` 类型会 `start + 1`。改行号运算前先对照。
- 防抖：大改动或上次 diff 耗时长时走防抖（先置 `isDirty`），否则同步算；`computeHunksDebouncerStateField.revision` 是对象身份，文档或路径变化即换新，旧的防抖结果因不匹配被丢弃。
- `hunksState.update` 有副作用：算完直接调 `signsFeature.changeStatusBar?.display(...)`。
- 暂存 hunk 未完成：`computeSigns` 把 `compareTextHead` 固定为 `undefined`，`stagedHunks` 恒为 `[]`，所以 `staged` 标记与「取消暂存」分支基本不会出现；动之前先决定要不要恢复这条链。
- `SignsProvider.computeSigns` 借 `lineAuthoringFeature.isAvailableOnCurrentPlatform()` 取 `SimpleGit`，不是 `SignsFeature` 自己的同名方法；改平台判断两处都要看。
- `ChangesStatusBar` 构造时直接 `workspace.on("active-leaf-change", …)` 且从不解除，停用再激活会累积监听器。
- 样式在根目录 `styles.css`，浮窗基础主题在 `tooltip.ts`。`rawHunksToHunks` 用了 Obsidian 注入的 `Array.prototype.last()`，脱离 Obsidian 单测要 polyfill。

## 5. 什么时候需要下钻

- 改 hunk 行号 / 补丁 / 符号判定：读 `hunks.ts` 与 `diff.ts`，对照 `HunksStateHelper.getHunk` 对 `added.lines` / `removed.lines` 的填充。
- 改何时重算、防抖：`hunkState.ts` 的 `hunksState.update` 与 `scheduleHunkComputation`；改对比文本来源或刷新节奏：`signsProvider.ts`、`signsIntegration.ts`（`show` 在 `src/gitManager/simpleGit.ts`）。
- 改 stage / reset / 命令入口：读 `hunkActions.ts`、`tooltip.ts`；补丁交给 `src/gitActions.ts` 的 `applyPatch`，命令注册与 `hunkCommands` 门控在 `src/commands.ts`。
