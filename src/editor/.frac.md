# .frac.md — src/editor

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

插件在 Obsidian 编辑器（CodeMirror 6）里的全部集成：三个独立功能加一层「按文件路径（vault 相对路径）发布 / 订阅」的粘合代码。
- 功能：`conflicts/`（桌面 + 移动）、`lineAuthor/` 与 `signs/`（仅桌面：要求 `useSimpleGit && Platform.isDesktopApp`，数据来自 `SimpleGit`，移动端不激活）。
- 粘合：`editorIntegration.ts` 持有两个有开关的功能并给出生命周期入口，`control.ts` 让每个编辑器订阅自己当前文件的事件，`eventsPerFilepath.ts` 是「路径 → 订阅者集合」单例。
- 上级：`src/main.ts` 持有 `plugin.editorIntegration` 并调三个生命周期入口；设置页在设置变化时调重载入口。

## 2. 直属文件

- `editorIntegration.ts`：`EditorIntegration`，字段 `lineAuthoringFeature`、`signsFeature`（子目录经 `plugin.editorIntegration.*` 反向访问它们）。
  - `onLoadPlugin()` 启动 `eventsPerFilePathSingleton`，注册 `subscribeNewEditor` 与 `conflictExtensions`，再调两个功能的 `onLoadPlugin()`；`onReady()` 按设置激活；`onUnloadPlugin()` 停用并清空单例。
  - `activateLineAuthoring()` / `deactiveLineAuthoring()` 与 `refreshSignsSettings()` 是设置变化时的重载入口。
- `control.ts`：`FileSubscriber`（每个编辑器一个）与 StateField `subscribeNewEditor`；`notifyLineAuthoring` / `notifyGitCompare` 把结果变成 transaction 派发；`changeToNewFilepath` 在重命名时改订新路径。
- `eventsPerFilepath.ts`：单例 `eventsPerFilePathSingleton`：`ifFilepathDefinedTransformSubscribers`、`forEachSubscriber`、`init()`（幂等，启动定时清扫过期订阅者）、`clear()`。

## 3. 子目录导航

- `conflicts/`：见 `conflicts/.frac.md`；冲突块解析、解决动作、CodeMirror 装饰与按钮，无设置开关。
- `lineAuthor/`：见 `lineAuthor/.frac.md`；逐行 blame：事件与启停、blame 计算与缓存、StateField 与设置类型，渲染在 `view/`。
- `signs/`：见 `signs/.frac.md`；hunk 计算、gutter 标记、diff 浮窗、状态栏与 `HunkActions`。

## 4. 本层约束 / 约定 / 禁忌

- 事件流向固定：Obsidian 事件 → `*Feature` → `*Provider` → `eventsPerFilePathSingleton` → `FileSubscriber.notifyXxx` → transaction → StateField。新增一种「按文件推送给编辑器」的数据，要同时加 `notifyXxx`、effect + `newXxxAsTransaction`、StateField、Provider。
- 两个功能共用同一种启停手法：`onLoadPlugin()` 里只 `registerEditorExtension(this.codeMirrorExtensions)` 一次，之后对该数组 push / remove 再 `workspace.updateOptions()`；不要替换这个数组对象。
- rename 时只有 signs 的处理器会调 `changeToNewFilepath` 改订新路径，line author 的只 `trackChanged`。
- 订阅者清理有三条通道：`notifyGitCompare` 里的 `removeIfStale()`、定时清扫、`onUnloadPlugin()` 的 `clear()`；`notifyLineAuthoring` 不检查过期。`notifyGitCompare` 的 `state.field(hunksState)` 没传 `false`，未挂载 `hunksState` 的编辑器会抛错。
- `eventsPerFilepath.ts` 在 import 时就 `new` 并 `init()`，定时器是 `window.setInterval`，只有 `clear()` 能停；`onLoadPlugin()` 再调 `init()` 是为了卸载后重新加载能恢复。
- `signs` 借用 `lineAuthoringFeature.isAvailableOnCurrentPlatform()` 取 `SimpleGit`；改平台判断要同时看两个功能。

## 5. 什么时候需要下钻

- 改某个功能：读对应子目录的 `.frac.md`。
- 改推送机制（订阅 / 退订 / 重命名 / 清理）或新增功能的接线：读本层三个文件，并确认 `src/main.ts` 调用各入口的时机。
- 改 Git 取数本身（`blame`、`show`、`hashObject`）：去 `src/gitManager/`。
