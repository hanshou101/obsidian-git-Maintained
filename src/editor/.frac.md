## 1. 本目录是什么

插件在 Obsidian 编辑器（CodeMirror 6）里的全部集成：三个独立功能加一层「按文件路径发布 / 订阅」的粘合代码。
- 功能：`conflicts/`（合并冲突块的高亮与 Keep ours/theirs/both/base 按钮，桌面 + 移动）、`lineAuthor/`（逐行 blame gutter，仅桌面）、`signs/`（gitsigns 风格的行变更标记、hunk 预览浮窗、状态栏计数与 hunk 动作，仅桌面）。
- 粘合：`editorIntegration.ts` 持有两个有开关的功能并提供生命周期入口；`control.ts` 让每个编辑器实例订阅它当前文件的事件；`eventsPerFilepath.ts` 是「路径 → 订阅者集合」的单例注册表。
- 平台边界：`lineAuthor` 与 `signs` 的 `isAvailableOnCurrentPlatform()` 都要求 `useSimpleGit && Platform.isDesktopApp`，数据来自 `SimpleGit`（`src/gitManager/simpleGit.ts`），移动端 isomorphic-git 路径下不会激活；`conflicts` 不依赖 Git 后端，在移动端改为用 block widget 而不是顶部面板。
- 上级关系：`src/main.ts` 持有 `plugin.editorIntegration`（按方法名 `onLoadPlugin` / `onReady` / `onUnloadPlugin` 推断在对应生命周期阶段调用）；设置读自 `plugin.settings.lineAuthor` 与 `plugin.settings.hunks`；`EditorIntegration` 的 `activateLineAuthoring` / `deactiveLineAuthoring` / `refreshSignsSettings` 是设置变化时重载功能的入口（调用方在本目录之外）。

## 2. 直属文件

- `editorIntegration.ts`：导出 `EditorIntegration`，字段 `lineAuthoringFeature: LineAuthoringFeature`、`signsFeature: SignsFeature`（子目录里的 provider 和 `hunkState` 都通过 `plugin.editorIntegration.*` 反向访问它们）。
  - `onLoadPlugin()`：`eventsPerFilePathSingleton.init()`；注册 `subscribeNewEditor` 与 `conflictExtensions`（冲突 UI 无设置开关，永远挂载）；再调用两个功能的 `onLoadPlugin()`。
  - `onReady()`：两个功能各自 `conditionallyActivateBySettings()`。`onUnloadPlugin()`：两个功能 `deactivateFeature()` + `eventsPerFilePathSingleton.clear()`。
  - `activateLineAuthoring()` / `deactiveLineAuthoring()`（方法名里的 `deactive` 是原样拼写）、`refreshSignsSettings()`：`showSigns || statusBar != "disabled" || hunkCommands` 任一为真则重载 signs（先 deactivate 再 activate），否则只 deactivate。
- `control.ts`：导出 `FileSubscriber`、`FileSubscribers = Set<FileSubscriber>` 和 `subscribeNewEditor`（`StateField<FileSubscriber>`，`create` 为每个编辑器 new 一个，`update` 调用 `updateToNewState`，`compare` 是引用相等）。
  - `FileSubscriber` 通过 `editorInfoField` 取当前文件路径，通过 `editorEditorField` 取 `EditorView`；创建时向 `eventsPerFilePathSingleton` 登记。
  - `notifyLineAuthoring(id, la)`：用 `newComputationResultAsTransaction` 构造并 `view.dispatch`（刻意用 `this.view.state` 而不是缓存的 `this.state`，注释称后者会在关闭面板时出问题）。
  - `notifyGitCompare(data)`：先 `removeIfStale()`；仅当 `hunksState` 不存在或 `compareText` / `compareTextHead` 与新数据不同才派发 `newGitCompareResultAsTransaction`。
  - `removeIfStale()`：当 `view.state.field(subscribeNewEditor)` 不再是自己、或 view 已 destroyed 时退订并返回 true（同一个 leaf / EditorView 里打开了新文件会产生这种过期订阅者）。`changeToNewFilepath(path)`：重命名时退订旧路径、订阅新路径。
- `eventsPerFilepath.ts`：导出单例 `eventsPerFilePathSingleton`（类 `EventsPerFilePath` 不导出）。`ifFilepathDefinedTransformSubscribers(filepath, handler)`（路径为空返回 `undefined`，否则按需创建该路径的 `Set` 后交给 handler）、`forEachSubscriber`、`init()`（幂等，启动每 60 秒一次的 `removeIfStale` 清扫）、`clear()`（停定时器并清空 Map）。

## 4. 本层约束 / 约定 / 禁忌

- 事件流向固定为：Obsidian 事件 → 功能的 `*Feature`（`lineAuthorIntegration.ts` / `signsIntegration.ts`）→ 对应 `*Provider` 计算 → `eventsPerFilePathSingleton.ifFilepathDefinedTransformSubscribers(path, subs => subs.forEach(s => s.notifyXxx(...)))` → `FileSubscriber` 把结果变成 CodeMirror transaction → 各 StateField 更新。新增一种「按文件推送给编辑器」的数据，要同时加：`FileSubscriber.notifyXxx`、一个 effect + `newXxxAsTransaction`、一个 StateField、一个 Provider。
- 订阅键是 vault 相对路径（`file.path`）。按 `signs/` 与 `lineAuthor/` 的摘要，路径重命名时 `SignsFeature` 的 rename 处理器会先调用 `FileSubscriber.changeToNewFilepath` 再 `trackChanged`，而 Line Author 的 rename 处理器只重新 `trackChanged`；[推测] 在 signs 停用而 line author 开启时，重命名后的编辑器仍挂在旧路径的订阅集合下。
- 两个功能共用同一种启停手法：`onLoadPlugin()` 里只做一次 `registerEditorExtension(this.codeMirrorExtensions)`，之后靠对该数组 `push` / `remove` + `workspace.updateOptions()` 开关扩展；不要替换这个数组对象。新增功能应沿用并在 `EditorIntegration` 的 `onLoadPlugin` / `onReady` / `onUnloadPlugin` 三处接线。
- 订阅者清理有三条独立通道：`notifyGitCompare` 内联的 `removeIfStale()`、60 秒定时清扫、`EditorIntegration.onUnloadPlugin()` 的 `clear()`。`notifyLineAuthoring` 不检查过期；`notifyGitCompare` 里 `state.field(hunksState)` 没传 `false`，推送到未挂载 `hunksState` 的编辑器会抛错。
- `eventsPerFilepath.ts` 在模块被 import 时就 `new EventsPerFilePath()`，构造函数立即 `init()` 启动 `window.setInterval`（不是 `registerInterval`），因此只有 `clear()` 能停；`EditorIntegration.onLoadPlugin()` 再调一次 `init()` 是为了卸载后重新加载能恢复。Map 里的条目（含空 Set）在 `clear()` 前不会删除。
- 两个桌面功能都靠 `plugin.editorIntegration.lineAuthoringFeature.isAvailableOnCurrentPlatform().gitManager` 取 `SimpleGit`（`signs` 也借用 line author 的这个方法）；改平台判断时需同时检查两个 `isAvailableOnCurrentPlatform`。
- 编辑器里的文件路径可能为空（注释称启动后的第一个编辑器会这样）：`subscribeMe` 此时直接返回，之后 `updateToNewState` 在 `lastSeenPath` 仍为空且路径出现时才补订阅。

## 5. 什么时候需要下钻

- 改 blame gutter 的数据、缓存、刷新：读 `lineAuthor/.frac.md`（视图细节再看其 `view/`）。
- 改行变更标记、hunk 预览、stage / reset 动作、状态栏计数：读 `signs/.frac.md`。
- 改冲突块识别或解决按钮：读 `conflicts/.frac.md`。
- 改推送机制（订阅 / 退订 / 重命名 / 过期清理）或新增功能的接线：读本层的 `control.ts`、`eventsPerFilepath.ts`、`editorIntegration.ts` 三个文件，并确认 `src/main.ts` 调用 `EditorIntegration` 各入口的时机。
- 改 Git 取数本身（`blame`、`show`、`hashObject`、`submoduleAwareHeadRevisonInContainingDirectory`）：去 `src/gitManager/`。
