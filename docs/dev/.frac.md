## 1. 本目录是什么

面向开发者而不是终端用户的文档目录，目前只有 Line Authoring（行作者标注）功能的开发文档一篇，作者是上游贡献者 GollyTicker。用户向的功能说明在上级 `docs/` 的 `Line Authoring.md`（文中也链接到发布站点 `publish.obsidian.md/git-doc/Line+Authoring`）。
本目录不含图片；读它是为了理解 Line Authoring 如何接入 CodeMirror 6，以及改动该功能后该手工回归哪些场景。

## 2. 直属文件

- `LineAuthorFeature.md`：英文，约 160 行，分五块。
  - 架构：先列出需要先读的 CodeMirror 6 概念（EditorState、StateField、Transaction、Annotation、ChangeSet）。然后给出 7 步数据流：每个编辑器面板按文件路径向发布/订阅模型（`eventsPerFilepath.ts`）注册 `LineAuthoringSubcriber`（`control.ts`）；文件变化或打开新文件时，`lineAuthorProvider`（`lineAuthoProvider.ts`）异步计算 `LineAuthoring`（`model.ts`，通过 `simpleGit.ts` 解析 `git blame` 输出）；结果通知订阅者，订阅者用 `newComputationResultAsTransaction` 生成 transaction 并 dispatch 到当前 `EditorView`；`lineAuthorState`（StateField）据此更新；`lineAuthorGutter`（`view/view.ts`）随之重绘。
  - 开发：可用上游的在线 test-vault 仓库配合 watch 模式，vault 里的插件文件是指向仓库根目录编译产物的符号链接；另提到一个 docker-setup 分支。
  - 必测的边界与错误场景清单（手工回归用）：仓库外运行、未跟踪文件、多窗口/多面板/同文件多开、特殊字符与 unicode 文件名、以 `--` 开头的文件名、空文件、末行无换行、多行块内提交不同、移动/复制追踪（follow）、子模块（包括 line authoring id 必须用子模块自己的 HEAD，而非超级项目的 HEAD，否则缓存键不变导致视图不更新）、vault 根与仓库根不同、`git blame` 出错、忽略空白开关、本地/UTC 时区格式、是否显示行号时的渲染。
  - "Unsaved Changes Gutter Update Scenario"：未跟踪文件应始终显示 `+++`；已跟踪文件在保存并重新计算前应显示 `%` 且保留原行颜色，插入/删除要让后续行的作者标注相应移位；还要测多行剪切粘贴、Ctrl+Z，以及已保存与未保存改动交界处的编辑。
  - 未来改进想法列表（悬停显示提交信息、显示被删除行、区分 untracked 与 changed、独立首字母方案等），不是已实现的功能。

## 5. 什么时候需要下钻

- 改动 Line Authoring（git blame 解析、缓存键、gutter 渲染、未保存改动的 `%` / `+++` 标记）前读 `LineAuthorFeature.md`，回归时按"边界与错误场景"和"Unsaved Changes Gutter Update Scenario"逐项走。
- 改用户可见的设置名或界面文案时，同时要更新 `docs/Line Authoring.md` 及 `docs/assets/` 里对应的 `line-author-*` 截图；见 `docs/.frac.md` 与 `docs/assets/.frac.md`。
