## 1. 本目录是什么

面向开发者的文档，只有 Line Authoring（行作者标注）开发文档一篇，沿用上游。用户向说明在上级 `docs/Line Authoring.md`。不含图片，不参与构建、测试或发布。

## 2. 直属文件

- `LineAuthorFeature.md`：英文开发笔记，四块：
  - Architecture：该先读的 CodeMirror 6 概念，和数据流：面板按文件路径订阅 → 异步跑 `git blame` → transaction 发给 `EditorView` → StateField 更新 → gutter 重绘。
  - Development：用上游的 test-vault 配合 watch 模式，插件文件是指向仓库根编译产物的符号链接。
  - Edge cases and error cases：手工回归清单，不是测试代码（仓库外运行、未跟踪文件、多窗口、子模块、时区等），含 “Unsaved Changes Gutter Update Scenario”：未跟踪文件始终显示 `+++`，已跟踪文件保存前显示 `%`。
  - Potential Future Improvements：未实现的想法。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 文中源码路径是上游旧布局（如 `/src/lineAuthor/…`、`/src/simpleGit.ts`），现在实际在 `src/editor/`（含 `lineAuthor/`）和 `src/gitManager/simpleGit.ts`；个别文件名拼写（如 `lineAuthoProvider.ts`）也对不上。以实际文件为准，不照抄路径。
- 子模块里文件的行作者缓存键必须用子模块自己的 HEAD，不能用超级项目的，否则在子模块里提交后视图不更新。

## 5. 什么时候需要下钻

- 改 Line Authoring（`git blame` 解析、缓存键、gutter 渲染、未保存改动标记）前读 `LineAuthorFeature.md`，改完按它的回归清单逐项手动走。
- 改用户可见的设置名或界面文案：同时更新 `docs/Line Authoring.md` 与 `docs/assets/` 里的 `line-author-*` 截图。
