# .frac.md — docs

> 生成规则：本文件只总结当前目录的直属文件，以及直属子目录的 `.frac.md`。
> 输入范围：direct-files + child-fracs only

## 1. 本目录是什么

插件的用户文档，沿用上游（Vinzent03/obsidian-git）的文档集，发布在 `publish.obsidian.md/git-doc`。页面按 Obsidian vault 的方式写：页面之间用 `[[页面]]`、`[[页面#标题]]` 维基链接互相引用，部分页面带 `aliases` 前置元数据。
全是 Markdown 与图片，不参与构建、测试或发布产物；链接或截图出错没有任何自动检查，要靠人工核对。维护版自己的改动与安装方式写在根目录 `README.md` 的 Maintained edition 一节，不在这里。

## 2. 直属文件

按主题分组。

**入口与安装**
- `Start here.md`：入口页与目录（列出下面所有页面）；解释 Git、Sync、Commit-and-sync 等术语；嵌入 `Getting Started.md` 的 `Performance on mobile` 一节。
- `Installation.md`：插件安装（应用内，或手动解压 release；手动方式的链接指向上游的 release 页）和 Windows / Linux / macOS 的安装要求；嵌入 `assets/` 里两张 Windows 安装截图。
- `Getting Started.md`：桌面端（新建或克隆仓库；"Vault inside a larger repository" 对应设置 **Limit file operations to the vault**）与移动端（isomorphic-git 的限制、性能警告、克隆方式）。

**认证、外部工具、排障**
- `Authentication.md`：macOS / Windows / Linux 下 HTTPS 与 SSH 的凭据配置、`SSH_ASKPASS` 方案，以及插件内置的 askpass 输入框（要求 Git 进程的 `PATH` 里有 `curl`）。
- `Integration with other tools.md`：Obsidian 桌面应用拿不到 shell 的 `PATH`，Git LFS 与 GPG 需要额外配置。
- `Common issues.md`：常见报错排查，多数条目转链到 `Installation.md`、`Authentication.md`、`Integration with other tools.md`、`Conflict resolution.md`。

**日常使用**
- `Features.md`：Source Control 视图、提交行为（staged 优先）、History 视图、自动 commit-and-sync 及其 glob 选择、提交信息占位符、子模块支持。维护版只在这里改了两句（见第 4 节）。
- `Conflict resolution.md`：在 Obsidian 内解决合并冲突的流程（Conflicts 分组、**Keep ours / Keep theirs / Keep both**、**Mark resolved**，再 Commit 才结束合并），以及 rebase 与 "Other sync service" 策略的差异。
- `Tips-and-Tricks.md`：`.gitignore` 建议内容；与 Obsidian Sync 并用。
- `Line Authoring.md`：行作者标注的用户指南（仅桌面端，仅 Live Preview 与 Source 模式），用相对路径引用 `assets/` 里全部 `line-author-*` 图；自述这些图没跟上新版 Obsidian。
- `.gitignore`：只忽略 `.obsidian`。

## 4. 本层约束 / 约定 / 禁忌

- 链接是 Obsidian 维基链接，指向页面文件名（含空格）和标题锚点（如 `#commit-and-sync`、`#Performance on mobile`、`#SSH_PASS Tools`）。重命名页面或标题前要全局搜索 `[[` 引用，否则链接静默失效；新增页面要在 `Start here.md` 的目录里登记。
- 图片有两种引用方式：`Installation.md` 用 Obsidian 嵌入 `![[文件名.png]]`（按文件名解析），`Line Authoring.md` 用 Markdown 相对路径 `assets/…`。移动 `assets/` 或改文件名会破坏后者。
- 文档沿用上游。维护版只改了 `Features.md` 里关于设置 **Use these globs for manual commits too**（`manualCommitUsesAutoCommitGlobs`，默认关闭，等于上游行为）的两句：打开后，`Commit-and-sync` 等手动提交也按自动提交的 globs 暂存。
- `Installation.md` 的手动安装链接仍指向上游 release；维护版的安装方式在根目录 `README.md`，那里把 `docs/` 定位为上游的用户文档。
- 有测试覆盖的行为描述，改行为时两边一起改：提交的 staged 优先与 auto commit glob 见 `tests/gitManager/` 的契约测试和 `tests/autoCommitGlobs.test.ts`；冲突标记解析见 `tests/editor/conflicts/`；内置 askpass 见 `tests/gitManager/askpass.test.ts`。
- 文中的设置名与界面文案（如 **Limit file operations to the vault**、`Stage all changes when nothing is staged`、**Keep ours**）是用户看到的字面文本，改源码里的显示文案后要同步这里。

## 5. 什么时候需要下钻

- 改认证 / askpass：`Authentication.md`；改提交、自动提交 glob、子模块：`Features.md`；改冲突处理 UI 或 merge 策略文案：`Conflict resolution.md`；改移动端限制或 vault 范围设置：`Getting Started.md`；改安装与 PATH：`Installation.md`、`Integration with other tools.md`、`Common issues.md`。
- 改 Line Authoring：`Line Authoring.md`；截图见 `assets/.frac.md`，实现原理与回归清单见 `dev/.frac.md`。
