## 1. 本目录是什么

插件的用户文档，沿用上游（Vinzent03/obsidian-git）的文档集，发布在 `publish.obsidian.md/git-doc`（`dev/LineAuthorFeature.md` 里的链接指向该站点）。页面按 Obsidian vault 的方式编写：页面之间用 `[[页面]]`、`[[页面#标题]]` 维基链接互相引用，部分页面带 `aliases` 前置元数据（如 `01 Start here`、`02 Installation`、`04 Authentication`），`docs/.gitignore` 只忽略 `.obsidian`。
全是 Markdown 与图片，不参与构建、测试或发布产物，链接或截图出错不会被任何自动检查发现，要靠人工核对。
子目录：`assets/`（页面嵌入的截图和动图）、`dev/`（面向开发者的 Line Authoring 说明）。

## 2. 直属文件

- `Start here.md`：入口页与目录，列出下面所有页面；解释 Git、"Backup"（已弃用术语）、Sync、Commit-and-sync；嵌入了 `Getting Started` 的 `Performance on mobile` 一节。
- `Installation.md`：插件安装（应用内或手动解压 release，手动方式链接的是上游 `Vinzent03/obsidian-git` 的 release 页）以及各系统装 Git 的要求：Windows 需要 Git 2.29 以上、PATH 选项含第三方软件、启用 Git Credential Manager（用 `![[third-party-windows-git.png]]` 与 `![[credential-manager-windows-git.png]]` 嵌入两张截图）；Linux 只推荐 AppImage，Snap 与 Flatpak 受限；macOS 配 `osxkeychain`。
- `Getting Started.md`：桌面端（新建本地仓库、克隆已有仓库、iCloud 注意事项、"Vault inside a larger repository" 对应设置 **Limit file operations to the vault**，说明哪些操作仍是全仓库范围）与移动端（isomorphic-git 的限制：无 SSH、仓库大小受限、无 rebase、无子模块、无符号链接与文件权限；性能警告；通过插件或 iOS Working Copy 克隆）。
- `Authentication.md`：macOS / Windows / Linux 下 HTTPS 与 SSH 的凭据配置、`credential.helper`、`ksshaskpass` 等 `SSH_ASKPASS` 方案，以及插件内置的 askpass 脚本（没有其他 `SSH_ASKPASS` 时会弹出 Obsidian 内的输入框，脚本要求 Git 进程的 `PATH` 里有 `curl`）。
- `Features.md`：Source Control 视图；提交行为（staged 优先、`Stage all changes when nothing is staged`、`Commit staged`、`Commit all changes`、桌面端 `Amend staged`、`Commit-and-sync` 与 `Commit staged and sync`）；History 视图；自动 commit-and-sync 的三种触发方式；自动提交的 glob 选择（Exclude / Include、Git pathspec glob、空 Include 只提交已暂存内容、匹配含隐藏文件、桌面与移动端的实现差异、与 "Limit file operations to the vault" 的优先关系；维护版新增的 **Use these globs for manual commits too** 打开后，`Commit-and-sync` 等手动提交也按同一份 globs 暂存）；提交信息的 momentjs 占位符；子模块支持与前置条件。
- `Conflict resolution.md`：在 Obsidian 内解决合并冲突的流程（Conflicts 分组、**Keep ours / Keep theirs / Keep both**、**Mark resolved**、再 Commit 才结束合并）；rebase 与 "Other sync service" 策略的差异；vault 外的冲突；push 被拒绝不等于冲突。
- `Common issues.md`：常见报错排查（xcrun、`git ENOENT` / Cannot run Git command 与 "Custom Git binary path"、反复 pull/push 多半是认证问题、`.gitignore` 对已跟踪文件无效、gpg、git-lfs、合并冲突），多数条目转链到 `Installation`、`Authentication`、`Integration with other tools`、`Conflict resolution`。
- `Integration with other tools.md`：Obsidian 桌面应用拿不到 shell 的 PATH，所以 Git LFS（macOS 要补 `/opt/homebrew/bin/`、Linux 用 `which git-lfs`）与 GPG（`gpg.program` 或设置里的附加 PATH）需要额外配置。
- `Tips-and-Tricks.md`：`.gitignore` 建议内容；与 Obsidian Sync 并用（"Disable on this device"、用 "Other sync service" 作为 pull 的 merge strategy 只更新 HEAD）。
- `Line Authoring.md`：行作者标注的用户指南，用 `![](assets/line-author-*.png)` 的相对路径引用 `assets/` 里全部 28 个 `line-author-*` 文件；说明仅桌面端、仅 Live Preview 与 Source 模式可用，文中自述截图尚未随 Obsidian v1.0 更新。
- `.gitignore`：只有 `.obsidian`。

## 4. 本层约束 / 约定 / 禁忌

- 链接是 Obsidian 维基链接，指向页面文件名（含空格）和标题锚点。已被引用的锚点包括 `#commit-and-sync`、`#Gitignore`、`#SSH_PASS Tools`、`#GPG Signing`、`#Git Large File Storage`、`#Linux`、`#For existing remote repository`、`#Create new local repository`、`#Performance on mobile`；重命名页面或标题前要全局搜索 `[[` 引用，否则链接静默失效。
- 图片有两种引用方式：`Installation.md` 用 Obsidian 嵌入 `![[文件名.png]]`（按文件名解析），`Line Authoring.md` 用 Markdown 相对路径 `assets/…`。移动 `assets/` 或改文件名会破坏后者。
- 文档沿用上游，维护版只改了 `Features.md` 里设置 `manualCommitUsesAutoCommitGlobs`（「Use these globs for manual commits too」，默认关闭，等于上游行为）相关的两句。`Installation.md` 的手动安装链接仍指向上游 release；维护版的安装方式写在根目录 `README.md` 的 Maintained edition 一节，不在 docs 里。
- 文档中有测试覆盖的行为描述，改行为时要两边同时改：提交的 staged 优先与 auto commit glob 语义见 `tests/gitManager/` 的契约测试；冲突标记解析见 `tests/editor/conflicts/`；认证中的内置 askpass 见 `tests/gitManager/askpass.test.ts`。
- 文中设置名与界面文案（如 **Limit file operations to the vault**、`Stage all changes when nothing is staged`、**Keep ours**）是用户看到的字面文本，改源码里的显示文案后要同步这里。

## 5. 什么时候需要下钻

- 改认证 / askpass：`Authentication.md`；改提交、自动提交 glob、子模块：`Features.md`；改冲突处理 UI 或 merge 策略文案：`Conflict resolution.md`；改移动端限制或 vault 范围设置：`Getting Started.md`；改安装与 PATH 相关：`Installation.md`、`Integration with other tools.md`、`Common issues.md`。
- 改 Line Authoring：`Line Authoring.md`，截图见 `assets/.frac.md`，实现原理与回归清单见 `dev/.frac.md`。
- 维护版新增或改变任何用户可见的设置、命令、行为：先在这里找到对应页面，再决定是补充段落还是新增页面（新增页面要在 `Start here.md` 的目录里登记）。
